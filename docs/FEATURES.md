# Legion 功能使用介绍

> 本文是 Legion 平台（本仓库产品）的**用户视角功能使用手册**，覆盖当前已合入的全部用户可见功能。
> 定位：**用**（这是什么、入口在哪、怎么操作、期望结果、相关设置与边界），不做内部架构/源码导读。
> 与 `README.md`（产品总览+快速开始+模块导航）互链去重：本文承载细节，README 承载引导与入口。

## 0. 一句话定位

Legion 是一套「**将军（general）+ 编队智能体（soldier/roster）**」的多智能体协作平台：
将军在 Web 军团指挥台（workbench）上为各工作空间发布目标，目标自动拆成阶段任务链分发给该空间专属编队，
智能体执行并把过程与产出沉淀回任务，将军在任务详情里直接验收——全程不离开浏览器。
日常主体是 **workbench 军团指挥台（:5173）**，数据与 API 中枢是 **team-hub v2（:8787）**，
**scrum v1 看板（:4820）** 为历史遗留引擎（除调试/迁移外不再日常使用）。

## 2. 快速开始

### 2.1 启动三件套（免手动可用下面的自动启停）

日常使用推荐让 **DSH Desktop** 自动拉起三个子服务（见 §2.2）。下面的三件套命令仅用于独立调试或未跑 Desktop 的场合：
启动顺序为 **① team-hub v2（:8787）→ ② workbench 指挥台（:5173）→ ③（可选）v1 看板（:4820）**。
核心要点：`team-hub/server.mjs` 是数据中枢必须最先起；`workbench` 改前端源码后必须重新构建产物，
`:5173` 不是热更新端口；v1 看板可选，仅调试/迁移用。

### 2.2 伴随 DSH Desktop 自动启停（推荐）

`services-plugin`（`@dsh-external/dsh-legion-services`，本仓库 `services-plugin/`）把上述三件套托管进 **DSH Desktop 的 web profile**：
Desktop 启动即自动拉起 team-hub v2 / v1 看板 / 指挥台，进程异常退出会自愈重启（闪退退避），Desktop 退出时随插件回收全部子服务；
某端口已被监听则跳过（不重复占用）。状态日志在 `<legion根>/.legion-services.log`。
运行依赖以 `~/.dsh/profiles/web/` 的 `package.json` 依赖 + `cordis.patch.yml` 的 `legion-services` 行登记，
其中 **patch 里必须显式给 `legionDir`（如 `D:/project/DSH/legion`）**——pnpm 对 `file:` 依赖是复制快照，运行时插件文件在 profile 的 node_modules 副本里，
靠 `import.meta.url` 自定位会找错根目录。
日常改码流程：把 `~/.dsh/profiles/web/node_modules/@dsh-external/dsh-legion-services` 建成 **junction → 本仓库 `services-plugin/`**，改代码即时生效；
若曾重跑 `pnpm install`（会把 junction 替换回复制快照），需按 `Remove-Item` + `New-Item -ItemType Junction` 重建。

### 2.3 三分钟体验循环

1. 浏览器打开 **http://127.0.0.1:5173**（旧标签页请 `Ctrl+F5` 强刷，5173 托管构建产物）。
2. 右侧顶部确认「🧭 中枢」已探测到 `:8787`；左侧选一个具体工作空间（如 software 软件流水线）。
3. 底部 **「🎯 发布目标」** 输入目标 → 该空间自动生成阶段任务链（需求澄清 → 方案搜索 → 任务拆解 → 测试用例设计 → 编码实现 → 代码审查 → 测试执行 → 部署与 CI/CD，`blockedBy` 串链），右侧「当前任务集」立即出现。
4. 点任意任务行 → **任务详情**：🤖 AI 执行过程 / ⏱ 进展时间线 / 📋 描述 / 🎯 验收标准。
5. 想自动推进：左侧底部开 **「⚡ 持续执行编排」** → 分析类阶段（需求/方案/拆分）由 AI 自动执行并提交待验收；写码类在任务详情点 **「🤖 派 AI 执行」**。
6. 任务到 🟡 待验收 → 详情里 **✓ 验收通过**（放行 done，解锁下游）或 **↩ 打回重做**（附原因）。

## 3. 模块章节（分模块功能指南）

### 3.1 安装与启动

- **入口**：本地终端按 §2.1 三件套命令启动；或由 DSH Desktop 按 §2.2 自动拉起。
- **功能**：一键拉起 team-hub v2（:8787）、workbench 指挥台（:5173）、v1 看板（:4820）。
- **操作步骤**：先起 team-hub（数据中枢），再构建并托管 workbench（改前端必须重新构建产物），v1 看板可选；端口与健康检查见 §5.1。
- **期望结果**：`:5173` 打开指挥台，`🧭 中枢` 探测到 `:8787` 即为就绪。
- **相关设置与边界**：`:5173` 托管构建产物（非热更），改前端需 `pnpm build` 后刷新；由插件托管时占用已监听端口会跳过。

### 3.2 空间与专属编队

- **入口**：左侧「工作空间」列表 + 「＋ 新建空间」。
- **功能**：左侧「工作空间」= team-hub 真实分区：全部空间 + 各空间（software 8 软件岗 / marketing 5 市场岗 / product 5 产品岗 / ops 4 运营岗 / default 3 通用岗，`node team-hub/scripts/seed-roster.mjs` 幂等播种）。
- **操作步骤**：「＋ 新建空间」两步建空间 + 从全局智能体目录**选人入编**或新建智能体（`POST /api/spaces`、`/api/spaces/{id}/agents`、`/api/agents`）；空间行「⚙」→ 空间设置可**绑定仓库**。
- **仓库绑定**：**「📂 选择文件夹」浏览本机目录**（与 DSH 工作空间选目录一致，不手填路径），选定后自动识别 git 仓库与远程（`origin`/首个 remote 预填「远程仓库 URL」；**留空 = 仅本地 / 不进共享仓库**）。绑定存 `spaces` 表 `local_dir`/`remote_url`，守护派工/隔离按空间以该仓库为工作目录与隔离根。
- **移除空间**：空间行「⚙」→ 设置底部「危险区」→ 展开即拉取**影响预检**（只读：任务/编队/模型/执行请求/技能/目标/编排/会话/消息/日程/成员 11 类计数 + 在办任务清单），需 **type-to-confirm** 输入 `delete-space:<id>` 精确匹配才可确认；删除级联清空该空间全部数据表（`POST /api/spaces/delete`，审计保留 `space:delete` 历史），**software/default 受保护不可删**。磁盘残留（本地文件/绑定目录）需按提示由运维清理，接口不删磁盘。
- **期望结果**：每空间只见自己的专属编队；未入编但认领了该空间任务的执行者以「⚙️ xxx · 执行中」合流展示。

### 3.3 中央视图

- **入口**：指挥台首页（默认视图）。
- **功能**：首页 3D 办公场景——编队绕会议桌，发光头部颜色 = 状态（🟢进行中 / 🟡待验收 / 🔴受阻 / 🔵待命），头顶名牌带任务数 + 目标进度环。
- **操作步骤**：点击智能体（2D 总览卡 / 3D 身体或名牌均可）→ 该智能体**任务清单**：🟢 运行中（进行中/待验收/受阻）/ ⚪ 待办 / ✅ 已完成，头部显示其默认模型徽标；点任务行 → 任务详情。「全部空间」视图按分区展示全部编队。
- **期望结果**：一眼看清各智能体状态与负载，快速进入某个体的任务清单。
- **相关设置与边界**：状态颜色（🟢🟡🔴🔵）对应进行中/待验收/受阻/待命；点击不同载体进入同一任务清单。

### 3.4 当前任务集与任务详情

- **入口**：右侧「当前任务集」（当前空间任务按角色泳道）。
- **功能**：每岗任务列表按状态排序（🟢 进行中 → 🟡 待验收/受阻 → ⚪ 待认领 → ✅ 已完成），默认显示前 3 条 + 「▾ 展开全部 N 个任务（M 未完成）」一键展开为该岗全量任务；折叠/展开状态按岗位记忆。
- **操作步骤 - 任务详情弹窗**：
  - **🤖 AI 执行过程**：执行该任务的 AI 沉淀的过程记录（evidence + 评论时间流）。
  - **❓ 待将军确认（就地答复）**：士兵提问时（最后一条评论以 `❓` 开头），该条评论下方**就地出现答复框**——待确认内容与输入框同屏、支持 `Ctrl+Enter` 发送；答复即写入任务评论，守护下一轮带答复续做、`❓` 自动解除。无需滚到弹窗底部找「评论」按钮，也不再弹二级输入框；底部「💬 评论/记录」同样是就地展开的输入框，有 `❓` 时额外提供「❓ 去答复（待确认）」跳转。
  - **🧾 审计（改动 × 证据，L1/L2）**：任务收尾时展示改动文件清单（A/M/D/R 徽标 + 行数 ±）→ 逐文件展开 diff、逐文件「✓ OK / ✘ 有问题」批注（存 `reviewNotes`）、整体结论一键批注；测试报告、产物、多轮补丁同屏；**打回自动把批注拼进原因评论交付下一轮 worker**。
  - **⚠ 并行改动重叠（L3）**：本任务改到的文件若同时被其他任务改动，审计区顶部黄色警示列出对方任务与状态（🟢进行中=活风险）。
  - **⏱ 进展时间线**：goal:publish / claim / transition / comment / patch / review-note / evidence / reassign 等审计动作（`GET /api/activity?taskId=`）。
  - 📋 描述、🎯 验收标准、🚧 边界（做什么 ✅ / 不做什么 🚫）、🔗 依赖提示、创建/更新时间。
  - **状态操作**（按状态出现）：todo →「▶ 开工 / 🔒 认领」；in_progress →「📮 提交验收 / 归还待办」；in_review →「✓ 验收通过（仅将军）/ ↩ 打回重做（附原因 + 审计批注）」；blocked →「解阻」；另有「💬 评论/记录」「转派」与「🤖 派 AI 执行」。
- **期望结果**：已认领并派工的任务显示「🤖 AI 执行中（已派工）」禁用按钮（防重复派发），不再出现「状态进行中却提示还没有 AI 执行」的观感错位。

### 3.5 发布目标与自动建链

- **入口**：底部「🎯 发布目标」（选中具体空间后可用）。
- **功能**：`POST /api/goal`——**每次发布会新建一个目标记录（G-xxx）**并按编队为其生成独立阶段任务链（`soldier=role`、`priority=high`、`blockedBy=前一任务`）；链任务挂 `goalId`，**不会取消**该空间既有目标/旧链——同一空间可同时推进多个目标，各自任务链由守护并行派工，互不干扰。
- **目标状态与版本**：每个目标带 `status`（🟢 active 进行中 / 🟡 paused 将军暂停 / ✅ done 链任务全部验收完成自动收尾 / ✕ canceled 将军取消）与自增 `version`（乐观锁，状态每次变更 +1）；中央目标卡按目标逐行列出 objective、状态徽标、`vN` 与各自链进度（done/total/percent），行内 ⏸ 暂停 / ▶ 恢复 / ✕ 取消（`POST /api/goal/status`，仅将军；取消会同步取消该目标未开工的链任务，在办/待验收留给将军收尾）。
- **取消目标后的在办任务（留痕 + 挂起）**：取消**不会**处决 `in_progress` / `in_review` 的任务（可能已有真实产出待裁决），但会对每条这类任务**自动追加一条提示评论并置「将军拦截」**（hold）：评论说明所属目标已取消、不会再有下游流转，并给出三条处置路径（产出可用 → 验收通过推进 done／无保留价值 → 取消／仍需交付 → 转派重做），响应体同时返回 `strandedTasks`（被留痕的任务 id 列表）供上层提示。目的：这类任务既没有下游、也不会被守护自动推进，不提示就会静默滞留在「⏳ 待我决定」里直到将军偶然发现。
- **操作步骤**：选中具体空间 → 在「🎯 发布目标」输入目标文本并发布；确认自动建链后，目标卡即出现并显示链进度；进度随任务推进自动更新。
- **验收标准 + 边界必带**：拆出的每个阶段任务都自动生成验收标准与边界（按岗位模板 `team-hub/stage-standards.mjs`），任务详情、执行提示词、调度弹窗同步注入；手动建任务（`POST /api/create`）留空同样自动注入，可传自定义 `acceptance`/`boundary` 覆盖。
- **期望结果**：目标进度（done/total/percent）显示在中央目标卡与场景进度环（未取消目标任务合计）。

### 3.6 任务调度与验收

- **入口**：底部「🗓 任务调度」。
- **功能**：中枢调度弹窗——全部任务按状态分组 + 统计条；待验收任务默认展开（打回/通过引导）；任务行可点进详情。
- **操作步骤**：打开调度弹窗 → 按状态分组查看各任务 → 点待验收任务进入详情 → 做「✓ 验收通过」或「↩ 打回重做」。打回时填写原因，评审批注会自动并入交给下一轮 worker。
- **期望结果**：跨岗位快速总览所有任务状态，并集中处理待验收/打回。
- **相关设置与边界**：区分「待验收（打回/通过）」与「受阻/待办」分组；验收通过口为将军（general）专属，普通执行者不可越权验收。

### 3.7 自动交接与守护流水线

- **入口**：发布目标后由守护（scrum-worker）自动执行，无需人工触发。
- **功能**：任何 agent 环节产生的任务自动交接给对应岗位 agent 实现——守护每 `intervalMs` 扫单，凡「角色在流水线（roles.json 8 岗）、依赖已解除、未被将军拦截、未全局暂停」的 todo/blocked 任务，即自动认领并按该岗位派 AI 执行；上一环验收 done → 下一环自动解锁、下轮自动接管，需求→方案→拆解→用例→编码→审查→测试→部署自动流转。
- **人工闸门**：roles.json 配了 `gate` 的阶段（当前 = **需求澄清 requirement + 方案搜索 researcher**）完成并合入主分支后停在 🟡 in_review，且要求交付的产物文档（`artifact`）必须存在；**将军确认后才流转**：✓ 验收通过 → 守护自动流转到下一阶段；↩ 打回附原因 → 士兵按反馈修订重做。
- **操作步骤/将军干预**：🖐 拦截 / 🚀 放行（`POST /api/hold`）；🔁 转派（soldier 与 role 一并改）；↩ 打回重做；⏸ 全局暂停。任何环节士兵遇「必须将军拍板」的疑问时任务转 blocked 并在界面给出醒目的「❓ 待将军确认」徽标。
- **合入自动调解**：中间阶段 worker 完成并把改动合入主分支失败时，守护或公共调解员自动接管：清脏工作区 → `git merge --no-ff w/<id>` → 无冲突则干净合入并推进 done；真内容冲突则派「合入调解员」subagent 裁决 → 去标记 → 提交 → 推进 done。
- **守护重启孤儿回收**：守护进程重启后，首轮扫单自动把本守护名下未被将军拦截的 in_progress 释放回 todo（`/api/release-stale?ids=`），下轮复用 `w/<id>` worktree 的 WIP 重新认领续做。

### 3.8 模型 × 智能体配置

- **入口**：底部「⚙️ 模型配置」。
- **功能**：每空间每角色可选**默认模型**（`agent_models` 表，`GET/POST /api/models`、`POST /api/models/clear`，均记审计）；未配置 = 平台默认（custom-ds / deepseek-v4-flash-openai）。候选 = 本机 DSH 部署真实模型（`~/.dsh/settings.yaml`），按省 token 档位分组（⚡ 轻量 / 🔶 均衡 / 🟣 旗舰强推理 / 👁 视觉）。
- **操作步骤**：打开「⚙️ 模型配置」→ 选择空间与角色 → 从候选档位中选默认模型 → 保存（记审计）。执行守护按角色配置选模型。
- **典型策略**：分析类（requirement/researcher/breaker）→ 轻量；写码/审查（coder/reviewer）→ 旗舰；测试/运维 → 轻量或均衡。
- **期望结果**：按角色/空间为每个任务选到合适的执行模型，兼顾质量与 token 消耗；智能体任务清单头部显示模型徽标。
- **相关设置与边界**：候选模型来自 `~/.dsh/settings.yaml`；如需调整档位/模型需在 Platform 侧配置模型列表。

### 3.9 对话中心

- **入口**：左侧「💬 对话中心」（`ChatView`）。**「全部空间」视图不再是死路**：显示「选择工作空间开始对话」入口（空间列表来自 `GET /api/spaces`），点选即进入该空间会话态（对应 `setScope` 切换，会话/消息/回复身份随空间隔离）。
- **功能**：随工作空间隔离的会话（team-hub v2 `/api/chat/*`，scope 分区）。选中具体空间后新建会话/发消息（Enter 发送，≤8000 字符），历史经 `GET /api/chat/messages` 恢复（>50 条可用「↑ 加载更早」分页回溯）；跨标签页/跨端实时送达走中枢单一 `/api/events` SSE 按 `chat:*` kind 过滤（不新增事件源）。消息按纯文本渲染（安全：不执行任何 HTML/脚本）。
- **操作步骤**：从「全部空间」视图选一个工作空间（或左侧先切到具体空间）→ 新建会话 → 输入消息（Enter 发送）→ 等待 AI 直答（默认开启）或人工回复；历史超出 50 条用「↑ 加载更早」分页回溯。
- **上下文输入（如何让回复方“有据可答”）**：
  - **关联工作空间**：会话始终归属一个具体空间；守护答问时会附上该空间**绑定仓库的只读上下文摘要**（顶层目录/文件结构 + README/LEGION/AGENTS/docs-FEATURES 等关键文件片段，提示词中标注「工作空间只读上下文（来源/生成时间）」）。仓库未绑定或读取失败 → 明示「无法提供工作空间内容上下文」降级占位，不冒充。
  - **上传文件**：编辑区「📎 附件」选择文本文件（每消息 ≤3 个、单个 ≤10MB、UTF-8 文本类），发送前可移除；发送后消息旁显示「📎 文件名（大小）」标识，文件正文随该消息仅作**当次回复上下文**，不进消息 body（服务端只存引用 + uploads 落盘，staged 孤儿 24h / 已绑定 7 天自动清理）；黑名单扩展名（exe/zip/压缩包/图片/pdf/office 等）或非法 UTF-8 二进制会被拒绝并给出可读原因。
  - **预算护栏**：外部上下文（空间摘要 + 附件）合计 ≤8000 字符（env `CHAT_CTX_BUDGET_CHARS` 可覆写），其中空间摘要另有**独立子预算** `CHAT_CTX_DIGEST_BUDGET_CHARS`（默认 4000，P3-4 起不再复用总预算变量）、单块上限 `CHAT_CTX_FILE_CAP_CHARS`（默认 4000）；超限先裁摘要、后裁最旧附件，截断处带「已截断」标记；内容仅当次提示词有效，不跨消息留存。
- **AI 回复**：发消息后守护（scrum-worker responder）从 `GET /api/chat/replies` 拉 awaiting 消息，用轻量子代理按「会话历史 + 上述上下文」直答，回复以 `author=<scope>-assistant`（或 ⚙ 设置的自定义身份）落为第二条消息（`POST /api/chat/replies/answer`，≤120s 超时自动 failed）；气泡三态：⏳ 等待回复… / ✅ replied（🤖 + 模型徽标）/ ❌ failed 附原因 + **重试**按钮；身份泛化：general = 我（右），其余 author（含 assistant）一律对方侧。
- **失败可行动与运行前提可见**：失败原因按五类分类（模型未配置 / 模型通道错误 / 超时中止 / 守护 foreman 不可用 / 其他）生成**含恢复指引**的可读文案，不再出现笼统「回复子代理未完成（error）」；对话头部有**健康状态点**（绿=守护在线 + 回复开 + 模型已解析；黄=某前提缺失并给修复动作；红=最近一条回复失败文案；灰=端点不可用），诚实标注「已解析不代表 provider 实际可用，以最近一次回复为准」。**P2-6**：判定逻辑抽到 `workbench/src/chatUi.ts` 并单测（灰态端点缺失不误导；黄态三项缺失并列不互相掩盖；红态含「重试」可行动指引）；发送失败文案区分未授权（401/403 → 填 token）与中枢不可达，**均明示「草稿已保留」**。
- **实时与断线恢复（P2-6）**：头部另有**实时通道指示**（绿=已连接 / 黄=重连中·已重连第 N 次 / 红=已断开，断开仍可点击手动刷新），并显示事件水位与「补齐 N 次」计数。恢复靠三层叠加：① 浏览器原生 `EventSource` 重连自带 `Last-Event-ID`，服务端据此**只回放增量**；② 重连成功回调**立即重拉**当前会话与会话列表（不等 15s 轮询）；③ 以**全量事件流的 seq 水位**检出缺口（首帧只建基线不误报）即触发补齐——因为服务端**不带**续传头时只回放**最近 30 条（有界）**，「断线久到超出回放窗口」或「连接在线但中间丢帧」两种情况只有本地水位判据能兜住。三态是**同一条源消息的 meta 更新**（awaiting→replied/failed），列表合并按同 id 覆盖最新版本，气泡能实时流转而不会停在「等待回复」。
- **回复设置入口（每空间）**：对话头部「⚙ 回复设置」打开弹窗——**AI 回复开关**（默认开；关闭后新消息零出站、人-人消息不受影响）+ 可选 模型 / 回复身份 / systemHint，保存即持久化（`GET/POST /api/chat/reply-settings`）。
- **期望结果**：在空间内与 AI 助手多轮对话，回答可引用该空间仓库内容与随消息上传的文件；失败给出“怎么修/怎么重试”的指引；历史可回溯，失败可重试；断线重连后消息与三态自动补齐、无重复条目。
- **相关设置与边界**：每空间可开关 AI 直答（对话头部 ⚙）；回复运行前提 = 守护进程在线 + 已配置可用 assistant 模型；消息按纯文本渲染，不执行 HTML/脚本。**附件内容按 UTF-8 文本注入**，二进制附件不支持；附件未绑定消息前**内容不可读**（staged → 绑定后才可读，跨会话/跨空间一律 403）；附件清理后消息里的引用仍留存（前端可解释「附件已过期」）。标签页被挂起（定时器冻结）时补齐会延后到唤醒。

### 3.10 文件中心

- **入口**：左侧「📁 文件中心」（`FilesView`）。
- **功能**：浏览当前空间**绑定的本地文件夹**（`local_dir`；未绑定 → 面板引导到「⚙ 空间设置」绑定，绑定后自动列出根目录）。列表（目录在前/大小/时间/含 `.git` 仓库标记）→ 点目录逐层进入、点文件预览（大文本截断带行数提示、读取中可见 loading、二进制提示不可预览）、下载字节一致。
- **搜索与批量（P2-7）**：顶部搜索框按**文件名**匹配（可勾「含子目录」递归），命中高亮、结果可「定位」到所在目录或直接预览/下载；结果达上限时显示「已达上限，请缩小关键词或目录范围」而非静默丢结果。勾选多项后出现批量栏：**批量下载**（逐个触发，不打包）、**移动到…**（输入相对目录路径）、**批量删除**（永久删除，需确认）；操作后按项汇总「成功 N 项，失败 M 项」并给出首条失败原因。
- **操作步骤**：进入文件中心 → 点目录逐层进入 → 点文件预览/下载；写操作用上传/新建目录/重命名/删除按钮（需令牌 + 二次确认）。
- **上传冲突策略（P2-7）**：标题栏「冲突」下拉四选一——**每次询问**（默认；同名时弹确认，确定=覆盖，取消=跳过且原文件不变）、**覆盖**、**跳过**、**自动改名**（`-1/-2` 递增，提示显示实际落盘名）。选择**记忆在本地**（下次沿用；浏览器禁用本地存储时自动降级为「每次询问」）。未知策略值由服务端 400 拒绝，不静默降级。
- **大文件分片与断点续传（P2-7）**：超过 8MB 自动走 `init → chunk×N → complete`，显示进度条、百分比与「共 N 片」，可随时取消。中断后重新选择同一文件即**从已传字节继续**（提示「续传中 X%」）；上传会话记在服务端磁盘（`.dsh-uploads/`，该目录受保护不可被文件中心浏览或删除），故刷新页面、重启服务后仍可续传。未收齐时完成会被拒绝（不留半写坏文件，会话保留）。
- **git 状态与差异（P2-7，只读）**：标题栏显示当前分支、领先/落后与改动汇总（暂存/未暂存/未跟踪/冲突），可展开「最近提交」；列表新增 git 标记列（`M` 改动、`A` 新增、`D` 删除、`R` 改名、`??` 未跟踪、`U` 冲突，鼠标悬停显示 git 原始两位状态并区分是否已暂存）；点标记或「差异」打开该文件的 unified diff，可在「工作区 vs 索引」与「已暂存 vs HEAD」间切换，并显示 `+N/−M` 统计；二进制与超长截断如实标注。**不提供暂存/提交/检出**——这些写操作不在此面板内。
- **写操作**：经 serve.mjs `/api/files/*`——**仅回环 + 写需令牌**（`--token`），覆盖需二次确认（`strategy=overwrite`，`overwrite=1` 为兼容别名）、删除需 `confirm=yes` 弹确认、`.git` 与 `.dsh-uploads` 内部受保护、路径越界（`../`/盘符/符号链接出根）一律拒绝。
- **期望结果**：在平台内安全地浏览、预览、下载与写入空间绑定的本地目录。
- **相关设置与边界**：根目录 = 空间绑定的 `local_dir`；越界/`.git`/`.dsh-uploads` 403 属预期保护；写操作仅回环可用且需令牌。批量下载不打包 zip；分片为顺序上传（不做并发与逐片哈希）；搜索只匹配文件名（不检索内容）；「移动到」目标目录须已存在；git 面板只读且领先/落后依赖本地 upstream 引用。

### 3.11 浏览器助手

- **入口**：左侧「🌐 浏览器助手」（`BrowserView`）。
- **功能**：地址栏输入 → serve.mjs `/api/web/fetch` **SSRF 防护代理**抓取：协议白名单（仅 http/https）、私网/回环/混淆 IP/域名解析到内网一律 `ssrf_blocked`（界面文案「已拦截：禁止访问内网地址」）、重定向逐跳再校验、限长（默认 2MiB）与整链总超时（默认 10s，含重定向共享 deadline）可配；正文按结构化文本返回（title/正文/摘要/链接），SPA 空壳给明确提示不伪造正文。无 scheme 自动补 `https://`，最近地址可复用（datalist）。
- **正文提取（P2-8）**：零依赖 Readability-lite——先剔除导航/页脚/侧栏/表单等样板（含 class/id 样板词命中），再对 `article`/`main`/`[role=main]` 与块级 `div`/`section` 候选按「文本长度 ×(1−2×链接密度) + 段落/标题加权」打分选块，最后结构化渲染（标题→`#`、列表→`-`、代码→围栏、引用→`>`、表格→`|` 分隔）。界面用徽标明示抽取质量：**抽取策略**（正文容器/主内容区/密度评分/整页回退）、字数、标题数、列表数、剔除样板块数；`链接密度偏高`、`整页回退`、`正文较短`、`正文已截断` 会单独提示，让你知道「这次抽得是否可信」。
- **抓取历史与缓存（P2-8）**：抓取按**空间**记入 team-hub（面板底部「本空间抓取历史」：点标题即回填重抓、可删单条或整空间清空；标题缺失时显示 URL，失败记录带错误码，同一地址显示「抓过 N 次」）。同空间内 5 分钟内的重复抓取**直接命中缓存**（徽标「缓存命中（N 秒前）」），过期则带 `ETag`/`Last-Modified` 重新验证，确认未变时显示「缓存已确认未变」（省流量且内容不变）。
- **限流与配额（P2-8）**：面板顶部显示本空间额度读数——**本分钟剩余次数 / 进行中并发 / 今日已用流量**，接近上限时染色提醒。超限时界面给出可行动指引并提示等待时间：`抓取过于频繁`（每分钟次数）、`同时进行的抓取太多`（并发）、`今日抓取流量已用完`（每日字节配额）。
- **页面截图（P2-8，默认关闭）**：开启后（`DSH_WEB_SHOT_ENABLE=1`）对当前页 headless 截图并在面板内预览、可新窗口打开。未开启时按钮禁用并说明开启方式；本机没装 Edge/Chrome 时同样禁用并说明。
- **操作步骤**：输入 URL（可省略 scheme）→ 提交 → 查看结构化正文与质量徽标 → 按需点「📷 截图」或从「本空间抓取历史」点回旧地址。
- **期望结果**：安全地抓取外网页面并得到**干净正文**（不含导航/页脚噪声），重复抓取命中缓存，超限时被明确限流而非静默失败，内网/私网目标始终被拦截。
- **相关设置与边界**：抓本地 mock 页需以 `DSH_WEB_FETCH_ALLOW_PRIVATE=1` 启动 serve.mjs（生产默认关闭）；协议仅 http/https，私网/回环目标一律拦截。
  截图需 `DSH_WEB_SHOT_ENABLE=1`（默认关闭，会真实启动浏览器进程；可用 `DSH_WEB_SHOT_BROWSER` 指定浏览器路径，指定后**只认该路径**）；
  配额可用 `DSH_WEB_QUOTA_SPACE_RPM`（默认 30/分钟）、`DSH_WEB_QUOTA_CONCURRENCY`（默认 3）、`DSH_WEB_QUOTA_HOST_RPM`（默认 30/分钟）、`DSH_WEB_QUOTA_DAILY_BYTES`（默认 200MB）调整，缓存 TTL 用 `DSH_WEB_CACHE_TTL_MS`（默认 5 分钟）；
  **缓存与配额计数都在 serve.mjs 进程内存中**（重启清零）；历史与配额是**按空间**的，不标注空间的调用（脚本/运维）不限流；抓取历史依赖 team-hub v2（未运行时面板明确报不可用，而不是显示成「没有记录」）。

- **入口**：左侧「📅 日程日历」/「🔔 通知中心」（三中心扩展）。
- **功能**：team-hub 扩 `calendar_events` 表与 `/api/calendar/events`（scope 分区 + 日期窗闭区间 + 写走 handleWrite/audit/SSE 广播）；前端自研月视图 `CalendarView.tsx`（周一 7×N 网格/今天高亮/跨月切换/新建删除二次确认/事件随 scope 隔离/hub 断连 toast + 重试）。**P2-5 增强**：数据面新增 `update`（局部更新）、`conflicts`（冲突检测）、`events/by-link`（按任务/目标反查）三个端点与 `taskId`/`goalId`/`recurrence` 三列（幂等补列）；**重复事件**支持简单规则（每天/每周/每月 + 间隔 1-99 + 结束日期或次数二选一 + 例外日），规则存列、查询侧展开为实例，删除可选「仅本次」或「整串」；**视图**新增周视图（7 列列出当天全部条目、翻周、双击或＋号在该日新建）并与月视图一键切换；**编辑**为统一弹层（标题/日期/全天/开始与结束时间/重复规则/任务与目标关联），条目显示 🔁（重复）与 🔗（已关联）标记。通知中心 = audit 派生面板 `NotifyView.tsx` + 侧栏 badge，统一模型见 `workbench/src/notify.ts`（P2-4）：**分类**（任务/目标/空间/模型/技能页签 + 各类未读数）、**优先级**（high = 拦截/转派/测试报告/目标发布·收尾·取消/进入 blocked·in_review；low = 批注/目标上下文/模型清除/空间更新）、**来源**（当前唯一 = 中枢审计 hub-audit）；**批量已读**（行多选 +「标记选中已读」+「全部已读」；已读状态 = 本机连续游标 + 显式 seq 集合，压实推进，**不写 audit**，反向断言服务端零新行）；**跳转协议**（`jumpOf` 统一产出 task/goal/space/model/skill/none，动作所属域优先：目标类动作跳目标面板、任务类跳任务详情，未知动作兜底提示不崩溃）；**实时与断线恢复**（单一 `/api/events` 单流按 kind 过滤 + seq 去重；SSE 重连或检测到 seq 缺口即立即重拉补齐，15s 轮询兜底，面板显示实时连接状态与补齐次数）。
- **操作步骤**：打开日历 → 点「＋ 新建条目」或双击日期格 → 填标题/日期/时间或勾选全天，可设重复规则与任务/目标关联 → 保存（若同时段已有日程会给出重叠提示，仍可保存）；点条目：已关联任务/目标则直接跳转，否则打开编辑弹层（可改任意字段、可删除）；顶栏「月 / 周」切换视图，‹ › 翻页、「今天」回今天。通知中心 → 用分类页签或「仅未读」筛选 → 勾选多行点「标记选中已读」（或单条点开即已读、或一键「全部已读」）→ 点击行按跳转协议打开任务详情/目标面板。
- **期望结果**：按空间创建/编辑/删除日程（含重复日程按规则出现在各实例日、删单次不留空洞）；时间区间与关联信息一目了然；同一时段的日程会收到重叠提示但不被阻断；实时收到审计派生通知并标记已读；高优先级通知（如任务被拦截、进入待审）显式标红提示；断线重连后列表自动补齐、无重复条目。
- **相关设置与边界**：日历事件与通知均按空间隔离；**时间按字面本地时间保存与显示，不做时区换算**（跨时区协作需人工换算）。重复规则不支持「单次修改」（改某一次即改整串）与按星期几/第几个工作日的复杂规则；`until` 与 `count` 二选一；单窗展开上限 400 个实例（超出报错而非静默截断）。关联为双向：日程侧填任务号/目标号，任务详情侧显示「📅 关联日程」。通知不反向写 audit（零变化），避免循环；已读状态仅存本机 localStorage（跨浏览器/跨标签页不同步），游标与显式已读集合两键并存（`legion.notify.read.<scope>` / `legion.notify.readseq.<scope>`）。

### 3.15 任务收尾审计

- **入口**：任务详情「🧾 审计」区（任务收尾时展示）。
- **功能**：
  - **L1 改动文件清单 + diff**：守护在合入 worktree 改动时用 `git diff --numstat/--name-status` 解析，经 `POST /api/patch` 结构化登记（`files:[{path,status,add,del}]` + 全量 diff，任务 `patches` 列，≤40 条/40 条目上限）；详情审计区逐文件展开该文件自己的 hunks，多轮补丁历史可见。
  - **L2 逐文件批注 + 打回闭环**：`POST /api/review-notes` 保存任务/文件级批注（`ok|issue|clear`，全部留 audit）；「↩ 打回重做」自动把 issue 批注拼进原因评论 → 守护下次认领时把历史有效反馈带进 worker 提示词。
  - **L3 跨任务改动重叠**：`GET /api/overlaps?scope=&id=` 扫描空间内所有带补丁记录的任务，按「改到同一文件」分组（≥2 任务）；与 in_progress/in_review 重叠 = 黄色活风险。
  - **派工即时可见 + 证据同屏**：派工成功即写「🟢 已派 AI worker 开始执行」评论；结构化测试报告（`testReport`）+ 产物（`artifacts`）与 diff、批注并列同一审计区。
- **操作步骤**：任务收尾（待验收/已完成）→ 打开审计区 → 逐文件展开 diff 与批注 → 一键「✓ OK / ✘ 有问题」→ 打回时批注自动并入原因评论；重叠警示先看合入顺序。
- **期望结果**：完成的任务「改了哪些文件、每处改了什么、谁和它改重了」全部沉淀在任务自己的审计工作台，验收/打回在同一视图完成。

### 3.16 team-hub 数据与接口一览

- **入口**：面向使用/排障的接口层（`team-hub/server.mjs`，:8787）。
- **功能**：`team-hub/team.db`（SQLite WAL）。表：`tasks` / `members` / `roster` / `skills` / `audit` / `spaces` / `goal` / `exec_state` / `exec_requests` / `agent_models` / `space_stages` / `space_runtime`。**写纪律**：所有 POST 经统一 `handleWrite`，`by`（操作者）必填；每次写都落 `audit` 并 SSE 广播。**状态机**：`todo → in_progress → in_review → done`（`done` 仅 `by='general'` 从 `in_review` 验收）；`blocked` 受依赖阻塞（`force` 可绕）；乐观锁 `ifVersion`。
- **操作步骤**：按需查询对应接口（见下方关键接口域）；直连 API 测试时记得带 `by` 操作者身份。
- **关键接口域**：任务（board/task/create/claim/transition/advance/reassign/release-stale/comment/heartbeat）、审计（patch/review-notes/overlaps）、目标（goal/goal/status）、进展（activity）、空间/编队（spaces/roster/agents）、空间流水线与开通预检（pipeline、spaces/provision）、技能（skills）、执行编排（exec/exec/queue/exec/request）、模型配置（models/models/clear）、对话（chat/conversations、chat/messages）。
- **期望结果**：据此快速定位某个数据/接口归属，辅助平台排障与使用。

### 3.18 空间流水线与开通预检（编队即流水线）

- **入口**：数据面接口 `GET/POST /api/pipeline`（scope 维度）+ 预检 `GET /api/spaces/provision?id=<space>`；命令行导入 `node team-hub/scripts/seed-pipeline.mjs --scope <id> --file roles.json`。
- **功能**：把「该空间有哪些阶段、每阶段谁干、干完交什么」从宿主部署配置（`roles.json`）搬进 team-hub 数据面（`space_stages` / `space_runtime`）。**守护每轮扫单优先读数据面**（`GET /api/pipeline?scope=&include=active`，按内容指纹 `version` 增量刷新，未变化零成本），hub 不可达或该空间未配置时自动回退部署面 `rolesFile`——既有空间零行为差异。
- **入链规则（发布目标时生效）**：链上每一环 = **编队 ∩ 流水线启用岗位**（`enabled=false` 的岗位不入链、不派工）。编队里的非执行成员（观察员/管理员）不再被串进 `blockedBy` 链，从机制上消除「链卡在一个没人认领的阶段」。
- **写入期校验**：role 形状与唯一性、`next` 必须可达、`gate:true` 必须带 `artifact`（否则闸门永远无法通过）、`docs` 必须是仓库相对路径且不含 `..`；仅允许 general 写入；每次写入落 `audit pipeline:update`。整批提交即权威（未提交的旧阶段被删除）。
- **阶段命名**：目标链标题优先取流水线 `label`（如【需求调研】），不再是按位置套用的通用阶段名。
- **开通预检**：只读清单，逐项给出 `ok / warn / error` 与修复指引——空间是否注册、编队是否为空、流水线是否配置且与编队一致、执行配置是否开启、守护实例是否在线（**这是「目标停在 todo」的最常见原因**）、工作区是否绑定且为 git 仓库、`.legion-worktrees/` 是否已忽略、待办任务是否因无守护而停滞。
- **操作步骤**：`seed-pipeline.mjs --scope <id> --file <roles文件> [--runtime-enabled] [--dry-run]` 导入 → 观察输出里的差异/告警 → 打开 `/api/spaces/provision?id=<space>` 确认无 error（如 `daemon-offline` 就先把该空间的守护实例挂上）→ 再发布目标。
- **期望结果**：新增空间/新编队不再需要「两份数据手工对齐」；配错时（编队与流水线无交集）发布目标直接报错并回滚，而不是静默生成一条永远不动的链。
- **相关设置与边界**：部署面 `rolesFile` 仍是离线兜底；**当前仍是一空间一守护实例**（profile 里的 `legion-scrum-worker-<scope>` 行），预检会在缺实例时明确点名——多空间统一编排属下一阶段。

### 3.19 任务中心（Scrum 泳道）

- **入口**：左侧「📋 任务中心」。
- **功能**：**单一视图**——经典 Scrum 泳道（待批准 → 待认领 → 进行中 → 待验收 → 受阻 → 已完成），按工作空间（含「全部空间」聚合）查看；中枢模式下可拖拽卡片跨列迁移状态。原「🖥 指挥总览 / 📋 Scrum 看板」双 Tab 已合并，指挥总览的分组语义改为泳道顶部的**将军视角过滤**。
- **操作步骤**：进入任务中心 → 顶部「📊 视角」点「⏳ 待我决定」（= 待验收 + 受阻）即只留需要将军决策的卡片，非匹配泳道淡出并提示「（N 个不在当前视角）」，第一个有匹配的泳道自动滚进视野；点「📊 全部」恢复完整泳道。拖拽卡片到目标列即迁移状态（待验收→已完成 弹确认，待验收→待认领 需填打回原因，受阻→进行中 自动解阻）；点卡片打开任务详情（验收/打回/评论/转派/拦截/派 AI，含产出文档预览与 ❓ 就地答复）。
- **期望结果**：一个面同时满足「按状态流转（泳道 + 拖拽）」与「按将军待办决策（视角过滤）」，不必在两个 Tab 之间切换，也不会因切视图而丢失泳道结构或拖拽目标。
- **相关设置与边界**：视角记忆在 localStorage `legion.taskcenter.view`；面板只读消费看板接口，状态迁移一律经 `/api/transition|comment`（写纪律 `by` 注入）；v1 文件模式（无中枢）只读，提示改用中枢模式或「打开经典看板 ↗」调试入口。

## 5. 故障排查与术语附录

### 5.1 故障排查

| 现象 | 处理 |
| --- | --- |
| 页面打开但没数据 / 显示旧界面 | `:5173` 托管构建产物：改前端后需 `pnpm build` 再刷新；旧标签页 `Ctrl+F5` 强刷 |
| 「🧭 中枢」不可达 | team-hub 没起：`node team-hub\server.mjs`（:8787）；可改/清中枢地址（存 localStorage） |
| 发布目标没反应 | 需中枢可达 + 已选**具体**空间（不是「全部空间」） |
| 任务/目标不刷新 | 任务集与目标卡靠 board 变化 + 15s 轮询自动刷新；roster/模型配置依赖空间切换刷新 |
| 写操作报「缺少操作者身份 by」 | 直连 API 测试时漏带 `by`（workbench 会自动补 `by:'general'`） |
| 智能体点不出任务 | 确认中枢模式 + 该角色有任务；页面是旧产物时强刷 |
| git push 连不上 | 全局代理指向 `127.0.0.1:7897`（可能未运行）：`git -c http.proxy= -c https.proxy= push origin main` |
| v1 看板 401 | `serve.mjs --token` 写操作需令牌（workbench 写接口与 v2 不同源） |
| 对话中心提示「需要中枢」 | team-hub 没起或被探测失败：`node team-hub\server.mjs`（:8787）后刷新；写被 401 → 右上角「🔑 令牌」填对 token |
| AI 不回 / 回复失败（❌ 附原因） | 运行前提 = 守护进程在线 + 已配置 assistant 可用模型 + 每空间 AI 回复开关开（默认开）：看对话头部健康点——黄态按提示「⚙ 回复设置」开开关/选模型或确认守护启动，红态为最近一次失败原因；对 ❌ 消息点「↻ 重试」；修复配置后新消息自动恢复（失败文案已分类可行动，不再笼统） |
| 文件中心提示未绑定/400 | 该空间没绑本地文件夹 → 侧栏空间行「⚙」绑定；「越界/.git/.dsh-uploads 403」= 目标在文件根之外、仓库内部或上传会话目录内 |
| 文件中心上传同名文件（409） | 默认策略「每次询问」：确定=覆盖、取消=跳过（原文件不变）；也可在标题栏「冲突」下拉改为覆盖/跳过/自动改名，选择会被记住 |
| 文件中心大文件上传中断 | 重新选择**同一个文件**即可续传（提示「续传中 X%」）；会话在服务端磁盘，刷新页面/重启服务后仍有效；不想续传可点「取消」丢弃会话 |
| git 标记列不出现 | 当前目录不在 git 仓库内（或仓库根探测不到）——git 面板只在仓库目录下显示，属预期 |
| 浏览器助手「已拦截：禁止访问内网地址」 | SSRF 防护默认拒绝私网/回环目标；抓本地 mock 需 `DSH_WEB_FETCH_ALLOW_PRIVATE=1` 起 serve.mjs |
| 浏览器助手「抓取过于频繁 / 同时进行的抓取太多 / 今日抓取流量已用完」 | P2-8 按空间限流与配额：等提示的时间后重试，或调 `DSH_WEB_QUOTA_SPACE_RPM`、`DSH_WEB_QUOTA_CONCURRENCY`、`DSH_WEB_QUOTA_DAILY_BYTES`（重启 serve.mjs 生效） |
| 浏览器助手「抓取历史不可用：后端未提供 /api/web/history」 | 后端仍是旧代码（未重启 serve.mjs）或 team-hub v2 未运行；注意与「本空间还没有记录」区分——后者是接口可用但确实没抓过 |
| 浏览器助手「配额不可用 / 截图（未启用、无浏览器）」 | 与上条同理：`/api/web/meta` 不可用（需重启 serve.mjs）；截图需 `DSH_WEB_SHOT_ENABLE=1`，本机需装 Edge/Chrome |
| 浏览器助手正文里出现导航/页脚文字，或提示「整页回退」 | 该页没有 `article`/`main` 等正文容器，只能整页回退——徽标会明示策略，属抽取边界而非抓取失败 |
| 浏览器助手第二次抓同一页提示「缓存命中」 | P2-8 缓存生效（同空间 5 分钟内不重复请求）；想看实时内容用「↻ 重新抓取」或调小 `DSH_WEB_CACHE_TTL_MS` |
