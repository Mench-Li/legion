## 1. 背景：现状事实与问题

### 1.1 产品背景

手机端 PWA 的定位是「人不在电脑前时，看任务、派任务、回答问题」；桌面指挥台仍是完整操作面。手机端刻意保持零构建、零框架依赖，随 Hub 静态托管（`workbench/mobile/`），首屏要快、离线要能用。详见 `docs/MOBILE-ACCESS-RUNBOOK.md` §0、§5。

因此本目标不是把桌面 UI 搬小，而是把**手机上的主路径**做顺：单手可达、卡片可扫读、状态可切换、弱网/键盘/刘海屏不破版。

## 2. 目标与成功定义

### 2.1 产品目标

让手机端 PWA 在**单手、竖屏、弱网、软键盘、刘海屏**的真实使用姿势下，完成三件事：

1. **一眼看见要我处理的事**：打开「任务」→ 看见受阻/待验收 → 左右滑动切状态列 → 点开卡片看详情。
2. **顺手说话/派活**：在「Agent」输入、发送；键盘不遮住输入框；刷新不打断阅读。
3. **不因为视觉改版丢掉已有能力**：离线待发、离线读、提醒、通知、空间切换、中英切换、头像、N 张卡渲染全部保持。

### 2.2 成功定义（可验收）

本目标完成时，以下三条旅程在 320–430 CSS px 的手机上**不需要双指缩放、不需要横向拖动整页**即可完成：

- **J1 查看与处理**：登录 → 任务页 → 看到「待我决定」计数 → 左右滑动到「待验收」→ 点卡片 → 看到该任务的状态/进展/现有动作 → 关闭回到原列与原滚动位置。
- **J2 沟通与派单**：Agent 页 → 点输入框（页面不缩放）→ 输入多行 → 点发送 → 消息出现在时间线；键盘弹起时输入框与发送键可见。
- **J3 中断回来**：页面不在前台时收到系统通知 → 点击通知 → 应用打开并落到对应任务（P1；P0 至少不破坏应用内提醒）。

### 2.3 目标关键词 → 需求追溯

| 目标关键词 | 对应需求 |
| --- | --- |
| 更适配手机操作习惯 | R-03、R-04、R-05、R-07、R-08 |
| 视觉效果 | R-06、R-09、R-10 |
| 更多采用卡片滑动式交互 | R-05、R-07、R-13 |

| 术语 | 本文件中的确定含义 |

## 4. 用户与场景

### 4.1 主要用户

- **将军/空间负责人**：在通勤、会议间隙、床上用一只手看「有没有要我验收/解阻的事」，顺手派活或追问。
- 不是桌面指挥台的替代者：复杂验收、审计 diff、批量操作仍在桌面完成。

### 4.2 关键场景

| 场景 | 触发 | 期望 |
| --- | --- | --- |
| S1 快速巡检 | 打开 PWA | 首屏不闪登录表单；任务页一眼看到「待我决定」数量与状态列。 |
| S2 横向找状态 | 在任务页左右滑 | 列切换跟手、有页码/状态名；纵向滚动不被劫持；不会误改任务状态。 |
| S3 看一条任务 | 点卡片 | 打开轻量详情层；字段与卡片一致；现有动作可用；关闭回原位置。 |
| S4 回看对话 | 在 Agent 页向上翻 | 新消息到达时不被拽到底；有「N 条新消息」入口。 |
| S5 弱网/离线 | 地铁、锁屏唤醒 | 离线待发、离线读、提醒、N 张卡渲染不回归；旧数据仍有年龄标记。 |
| S6 系统通知 | 页面不在前台 | 点击通知能落到对应任务（P1）；至少不白屏、不丢会话。 |

## 5. 范围边界：做什么 / 明确不做什么

### 5.1 做什么（In Scope）

1. **仅移动端 PWA** 的布局、样式、交互与可访问性改造：`workbench/mobile/` 下的页面、样式、渲染逻辑、必要的纯函数与测试。
2. 手机/平板宽度、竖屏/横屏、安全区、软键盘、动态视口下的**自适应**。
3. 任务看板的**状态列卡片横向分页**（R-05）与卡片信息层级（R-06）。
4. 任务卡的**轻量详情层**（R-07），只消费现有数据与现有动作。
5. 对话时间线的**移动阅读行为**（R-08）：不强制跳底、保留阅读位置、新消息提示。
6. 视觉一致性、状态可扫读、动效与减少动态、对比度（R-09、R-10）。
7. 触控目标、拇指区、无障碍与手势替代（R-04、R-11）。
8. 既有能力的**回归保护**与证据（R-12）；P1 的卡片左滑、平板/横屏、通知深链（R-13–R-15）。
9. 受影响文档的同步：`docs/MOBILE-ACCESS-RUNBOOK.md` 中用户可见行为若变化，必须更新；本目录的阶段文档链由后续阶段维护。

| 不做 | 原因 / 边界 |
| --- | --- |
| 不改桌面 `workbench/src/`（React 指挥台） | 本目标只针对移动端 PWA；桌面视觉与交互另立目标。 |
| 不改 team-hub 服务端、API、数据库、任务状态机、鉴权、审计 | 本目标是前端适配；需要新接口/新字段的需求一律拒绝或另立目标。 |

| 不做桌面板式（多栏指挥台）、不做平板专用信息架构 | 平板只要求「可用、不破版」，不要求桌面级布局。 |
| 不做聊天「滑动回复」、不做消息虚拟列表、不做无限历史优化 | 非本目标核心；长列表性能只做不回归。 |

### 5.3 边界判定规则

下游遇到一个新想法时，用这三问判定：

1. 需要服务端新增字段/接口吗？→ 需要则**不做**，登记后续。
2. 会改变任务状态、权限、审计或跨端文案口径吗？→ 会则**不做**。
3. 只是在移动端改变「看起来/摸起来/滚动方式」吗？→ 是则**可做**，但必须落到 §9 的可测验收。

## 6. 需求清单（编号 + 优先级 + 背景 / 目标 / 验收口径）

> 每条需求都必须有「背景 / 目标 / 验收口径」三部分。P0 未全绿不得交付；P1 在 P0 全绿后纳入本轮，未完成需在 TEST_REPORT 登记为后续；P2 不在本目标验收。

### R-01 响应式布局与无横向溢出（P0）

- **背景**：F1，移动端没有宽度断点，窄屏与平板共用固定尺寸。
- **目标**：在 320–1024 CSS px 宽度下，页面按可用宽度重排；关键内容不被裁切、不重叠、不产生整页横向滚动。
- **验收口径**：
  - 在 320、360、390、414、430、768、1024 七个宽度逐一检查：`document.documentElement.scrollWidth <= window.innerWidth + 1`。
  - 320px 下：标题、状态条、页签、意图按钮、目标选择、输入框、发送键、任务卡动作均可见且可点；允许把次要头部动作收进「更多」菜单，但不允许裁切或重叠。
  - 768px 及以上：内容有可读最大宽度（建议 ≤ 720px 居中），不得把卡片/正文拉到整屏宽；允许看板显示两列，但不得横向溢出。
  - 200% 浏览器缩放（等价窄屏回流）下无横向滚动、无文字截断导致的语义丢失。
  - 图片/头像保持比例，不拉伸、不模糊；不因固定宽高导致溢出。

### R-02 安全区与动态视口（P0）

- **背景**：F8、F7；现有只处理 top/bottom，且用 `height:100%`。
- **目标**：刘海、圆角、Home Indicator、横屏左右安全区都不遮挡内容；视口高度随浏览器 UI/键盘变化。
- **验收口径**：
  - 顶栏内容不被刘海/状态栏遮挡；底部输入区不被 Home Indicator 遮挡（底部内边距 ≥ `safe-area-inset-bottom` + 8px）。
  - 横屏时左右内容不被圆角/刘海裁切（使用 `safe-area-inset-left/right` 或等价方案）。
  - 浏览器地址栏收展、软键盘弹起/收起时，主内容区高度正确变化，不出现「底部被切掉一截」或「整页被顶上去」。
  - 真机或 DevTools 设备模拟 + 源码检查双重证据；仅代码检查不算通过。

### R-03 软键盘与输入区（P0）

- **背景**：F7；输入框 14px、无 `visualViewport`、`height:100%`；当前回车直接发送。
- **目标**：聚焦输入框不触发页面自动缩放；键盘弹起时输入框、发送键、当前光标可见；手机软键盘回车默认换行，发送由明确按钮触发。
- **验收口径**：
  - iOS Safari 聚焦登录输入框与消息输入框：`visualViewport.scale` 保持 1.0；页面可双指缩放（不得用 `maximum-scale=1` / `user-scalable=no` 锁死）。
  - 键盘弹起后：输入框 caret 可见，发送按钮完整可见，输入区不被键盘遮挡；键盘收起后布局恢复，不残留空白。
  - 手机软键盘回车 = 换行；发送仅由「发送」按钮触发（物理键盘可用 Ctrl/Cmd+Enter 作为增强，但不得与软键盘冲突）。
  - 多行输入自动增高到上限后内部滚动；不把发送按钮挤出屏幕。
  - 登录页、消息输入区、任务选择下拉均满足；提醒/错误浮层在键盘弹起时不被遮挡。

### R-04 触控目标与拇指区（P0）

- **背景**：F1；现有 26–40px 的按钮（离线横幅、卡片动作、页签、头部图标、意图 chip 等）。
- **目标**：主要操作单手可达、点得准；所有可交互元素的有效命中区 ≥ 44×44 CSS px。
- **验收口径**：
  - 在 390px 宽度下枚举 `button, a, input, select, textarea, [role="button"]` 的 `getBoundingClientRect()`：不存在小于 44×44 的**有效命中区**；视觉可小，但需用 padding/伪元素补足。
  - 相邻可点目标之间至少 8px 间距；不得出现两个按钮命中区重叠。
  - 主要操作（发送、切页签、切状态列、打开卡片、关闭详情）位于屏幕下半部或可单手触及区域；不要求所有次要操作都在拇指区。
  - 卡片整块可点，而不是只有文字可点。
  - 触控目标放大后不得导致 320px 下横向溢出。

### R-05 看板状态列卡片横向分页（P0，本目标核心）

- **背景**：F2、F3；看板纵向堆叠六组，手机上滚动距离长；没有卡片滑动能力。
- **目标**：在「全部」视角下，把非空状态列变成**一屏一列**的横向分页；左右滑动切列，列内纵向滚动；保留现有视角筛选与任务顺序。
- **验收口径**：
  - 页面顺序与 `BOARD_COLUMNS` 一致（受阻 → 待验收 → 进行中 → 待办 → 未排期 → 已完成）；空列不生成页面（与现有「空列不显示」一致）；不认识的 status 仍作为单独一页/分组出现，原文标注不丢。
  - 一次只显示一列；列头（状态名 + 数量）在列内滚动时保持可见（sticky 或等价）；有明确的页码/列指示（如「第 2/5 页 · 待验收 3」或圆点），并随滑动更新。
  - 横向手势判定：水平位移 ≥ 48 CSS px 且水平位移 ≥ 1.2 × 垂直位移才切页；否则视为纵向滚动或取消。手势起点在屏幕左右边缘 20px 内时不拦截（让系统返回手势通过）。
  - 纵向滚动优先：用户从列中部上下滑时，页面不切列；斜向滑动不得同时触发切页与滚动。
  - 切页动画 180–250ms；`prefers-reduced-motion: reduce` 时无位移动画、直接切换。
  - 每列保留独立纵向滚动位置：切走再切回，回到该列上次位置（同一会话内）。
  - 除滑动外必须有可见替代：列头左右按钮、状态 chip 或键盘左右键；读屏可通过 `aria-live` 得知当前列。
  - 滑动**不得**改变任何任务状态、不得触发卡内动作、不得跳到其他页签。
  - 任务总数不丢：接口返回 N 条任务时，所有分页中的 `.task` 元素总数 = N（与现有 `mobile-logged-in-check` 的口径一致）。
  - 视角不是「全部」时保持现有平铺列表，不做横向分页（避免「已收窄还分页」的重复导航）。

### R-06 任务卡信息层级与状态可扫读（P0）

- **背景**：F4；卡片只有文字状态，缺少颜色/层级；动作按钮挤在卡内。
- **目标**：卡片在不点开的情况下能回答「哪条、什么状态、谁/什么优先级、要不要我动手」；状态用**颜色 + 文字**双重编码。
- **验收口径**：
  - 每张卡显示：任务号 + 标题、状态一句话（沿用 `taskLine`）、角色/优先级（沿用 `taskMeta`，为空则不显示）、状态色标识（左边条/徽标/图标任一）。
  - 状态色沿用现有 `tone` 语义（warn/busy/muted/ok），不得只靠颜色传达状态；色盲用户读文字也能分辨。
  - 320px 下标题最多两行、超出省略；完整标题在详情层可见；不得出现文字压住按钮或溢出卡片。
  - 卡片圆角、边框、内边距、字号来自统一令牌；同一屏内卡片风格一致，不出现「这张圆角 10、那张 6」的随机差异。
  - 卡片整块可点（R-07）；卡内动作按钮命中区 ≥ 44px 或移入详情层。
  - 「等电脑领取」与「正在执行」的文案区分保持（现有 `isWaitingForNode` 口径不回归）。

### R-07 任务卡轻量详情层（P0）

- **背景**：F6；点卡片没有详情，卡内只有两个小按钮；runbook 声称的「任务详情」在手机端并不存在。
- **目标**：点卡片打开一个轻量详情层，集中显示现有字段与现有动作；关闭后回到原列/原滚动位置。
- **验收口径**：
  - 点击卡片任意非按钮区域，200ms 内出现详情层（底部抽屉或等价展开层）；显示任务号、标题、状态一句话、角色/优先级、当前视角/所属列。
  - 现有动作可用且行为不变：「追加要求」（仅未结束任务显示，打开输入区并聚焦）、「问这个 Agent」（切到对应 Agent 的聊天）。
  - **不新增**验收/打回/评论/转派/审计 diff 等桌面能力；不新增服务端请求。
  - 关闭方式：下拉/点遮罩/返回键/Escape 任一；关闭后回到原状态列与原滚动位置；不丢失未发送的输入。
  - 焦点管理：打开后焦点进入详情层，关闭后回到触发卡片；读屏可读出层标题与关闭按钮。
  - 详情层在软键盘弹起时不被遮挡；长内容内部滚动，不撑破视口。

### R-08 对话时间线的移动阅读行为（P0）

- **背景**：F5；每次刷新/SSE 都强制跳到底部，用户无法回看。
- **目标**：用户向上阅读时不被新消息打断；在底部时保持自动跟随；提供明确的「回到最新」入口。
- **验收口径**：
  - 用户距底部 > 40px 时，任何刷新/SSE/重渲染都不得改变 `main.scrollTop`（允许 ±4px 抖动）。
  - 距底部 ≤ 40px 时，新消息到达自动滚到底部；发送成功后滚到底部。
  - 距底部 > 40px 且收到新消息时，显示「N 条新消息」浮动入口；点击后滚到底部并清零。
  - 切换到其他页签再回来，保留聊天滚动位置；切换 Agent/空间时重置到底部（这是新会话）。
  - 长消息自动换行，不出现横向滚动；320px 下气泡最大宽度约 78–86%，平板不超过可读宽度。
  - 日期分隔（今天/昨天/日期）为 P1 增强，不阻塞本目标；若实现，必须使用现有 i18n 机制。

### R-09 视觉一致性与设计令牌（P0）

- **背景**：F9；现有移动端已复用桌面 `:root` 令牌，但 manifest 与 meta 颜色不一致；状态层级弱。
- **目标**：移动端看起来是「同一个 Legion」，而不是另一套应用；卡片、状态、层级、留白形成稳定节奏。
- **验收口径**：
  - 保留现有深色令牌（`--bg/--panel/--panel-2/--line/--text/--muted/--accent/...`）；新增颜色必须来自令牌，除透明叠加/状态色外不得出现新的硬编码色值。
  - manifest 的 `theme_color` / `background_color` 与页面 `meta theme-color` / `--bg` 一致；安装启动图不闪白、不出现两种底色。
  - 正文对比度 ≥ 4.5:1，大字号（≥18.66px 或 14px 粗体）≥ 3:1，UI 边界/图标 ≥ 3:1；现有 `--muted-2` 若在 12px 文本上不足，可为移动端引入局部可访问色，但不得改桌面令牌。
  - 320 / 390 / 768 三个宽度截图并排审查：卡片间距、圆角、字号层级一致；无重叠、无截断、无「半截按钮」。
  - 不新增字体家族；沿用系统字体栈；中英切换后布局不破版。
  - 头像/图标不拉伸、不模糊；1x/2x/3x 下清晰。

### R-10 动效与减少动态（P0）

- **背景**：现有只有骨架脉冲与弹框进入动画；新增滑动/抽屉需要动效纪律。
- **目标**：动效服务于「我从哪来、到哪去」，不制造等待或眩晕；尊重系统减少动态设置。
- **验收口径**：
  - 切页、抽屉、提示动画时长 150–250ms；无无限循环动画（骨架加载态除外）。
  - `prefers-reduced-motion: reduce` 时：切页/抽屉无位移与缩放，直接显示；骨架不闪（现有规则保持）。
  - 动画期间不阻塞点击；快速连续滑动不叠加出多层页面或错位。
  - 页面进入后台、切页签、锁屏后不继续跑无意义动画。

### R-11 无障碍与手势替代（P0）

- **背景**：现有 ARIA 基础较好（tablist、role=status、aria-selected），但图标按钮缺少可访问名、手势将新增。
- **目标**：所有手势操作都有可见/可读的替代路径；读屏、键盘、开关「减少动态」用户都能完成核心旅程。
- **验收口径**：
  - 切列、打开详情、关闭详情、发送、切换页签、切换视角均有非手势替代（按钮/键盘/可聚焦元素）。
  - 图标按钮（刷新、退出、语言、通知、关闭）有可访问名（`aria-label` 或可见文字）；不能只靠 `title`（触屏无 hover）。
  - 当前列/当前视角/当前页签通过 `aria-selected` 或等价状态暴露；切页后 `aria-live` 播报「第 N 页，状态名，共 M 条」。
  - 焦点可见：键盘 Tab 时焦点环不被 `outline:none` 完全抹掉；抽屉有焦点陷阱与 Esc 关闭。
  - 颜色不是唯一信息载体；状态、错误、成功均有文字。
  - 200% 缩放/大字号下不丢操作。

### R-12 既有能力与 PWA 行为回归（P0）

- **背景**：F10–F12；移动端有大量「只在真实路径上才走到」的能力，视觉改版容易悄悄弄坏。
- **目标**：本次改造不改变数据语义、离线语义、通知语义与跨端一致性；已安装 PWA 能拿到新版本。
- **验收口径**：
  - 登录/注册、空间切换、Agent 切换、三种意图（ask/create_task/feedback）、离线待发队列、离线读缓存（消息 7 天 / 看板 1 小时）、SSE、应用内提醒、系统通知、中英切换、头像渲染全部按现有行为工作。
  - 接口返回 N 条任务时，页面 `.task` 总数 = N；未知 status 不丢；`done`/`canceled` 同列；列内按时间倒序。
  - `sw.js`：代码仍网络优先、API 仍不缓存；若新增模块，必须加入 `SHELL` 并提升缓存版本；`sw-shell.test.mjs` 通过。
  - 已安装 PWA：刷新一次即可拿到新代码，不出现「部署了但手机一直跑旧版」。
  - 不新增 API 请求；看板仍走 `compact=1`；不把 git diff/大字段带到手机。
  - 回归命令全部 exit 0（见 §9.2）。

### R-13 平铺列表中的卡片左滑快捷操作（P1）

- **背景**：F3；用户希望「卡片滑动式」不只是切列，还能在卡片上快速操作。
- **目标**：在**平铺列表视角**（boardView ≠ all）下，左滑任务卡露出 1–2 个次要动作；不误触、不与纵向滚动/切列冲突。
- **验收口径**：
  - 仅在平铺列表启用；分页看板中的横向手势始终归分页，不启用卡片横滑（避免双重手势冲突）。
  - 左滑 ≥ 48px 且水平占优时露出动作；右滑不做破坏性操作；一次只展开一张卡；点其他区域/滚动/切列自动收起。
  - 动作本身必须再点一次才执行；滑动不直接触发动作；动作均有详情层内的可见替代。
  - 纵向滚动优先；边缘 20px 不拦截；`prefers-reduced-motion` 时直接展开。
  - 动作范围只允许现有能力（追加要求、问这个 Agent）；不新增状态迁移/删除/验收。

### R-14 平板与横屏可用性（P1）

- **背景**：F1、F8、F9；现有固定手机尺寸 + portrait 锁定。
- **目标**：768–1024px 平板宽度与手机横屏下不破版；不要求桌面级布局。
- **验收口径**：
  - 768/1024px：无横向溢出；内容有最大可读宽度；看板可显示一列或两列，但不得把卡片拉到整屏宽；聊天不出现过长行宽。
  - 手机横屏（如 844×390）：顶栏/底栏使用左右安全区；输入区可见；状态列可滑动；无内容被圆角裁切。
  - 若方案阶段解除 manifest `orientation: portrait`，必须补横屏截图与手势验证；若保持锁定，浏览器横屏仍需通过上述检查。
  - 平板不新增专用导航/信息架构；不把手机布局简单放大到不可读。

### R-15 系统通知深链落到任务（P1）

- **背景**：F12；`sw.js` 点击通知打开 `#task=<id>`，但 `app.mjs` 没有 hash 处理，当前不会落到任务。
- **目标**：点击系统通知后，应用打开/聚焦并落到对应任务；任务不存在时给出明确提示，不白屏。
- **验收口径**：
  - 冷启动带 `#task=T-123`：登录/恢复会话后切到任务页，刷新任务，打开详情层并高亮；若任务不在当前空间/无权限，提示「任务不存在或无权访问」并停留在看板，不报未捕获异常。
  - 应用已打开时点击通知：聚焦已有窗口并切换/滚动到目标任务，不新开重复标签（保持现有 SW 行为）。
  - 任务存在但当前视角筛选不到时，自动回到「全部」或给出可见入口，不能「找不到」。
  - 不新增 API；只消费现有 `/api/board` 与 `openTask` 能力。

### R-16 后续候选（P2，不在本目标验收）

- 底部导航/更多拇指区重组、下拉刷新、聊天日期分隔、聊天滑动回复、长列表虚拟化、浅色主题、平板双栏、Web Push。
- 这些只登记为候选，不得挤占 P0；若实现，必须单独补验收口径。

## 7. 需求级接口 / 数据结构契约

> 本节是**下游必须消费的行为契约**，不是技术选型。具体 DOM 结构、CSS 写法、手势实现机制（Pointer/Touch/键盘）由方案与编码阶段决定，但必须满足以下语义。

### 7.1 数据来源（不变）

移动端继续只消费现有接口，不新增请求：

| 数据 | 现有来源 | 用途 |
| --- | --- | --- |
| 空间任务 | `GET /api/board?scope=<scope>&compact=1` | 看板任务全集 |
| 各 Agent 的 Attempt | `GET /api/agents?scope=<scope>` | 合并「等电脑领取 / 正在执行」 |
| 对话消息 | `GET /api/chat/messages?conv=<conv>&scope=<scope>&limit=200` | 时间线 |
| 身份/空间 | `GET /api/identity/me` | 空间切换 |
| 提醒 | `GET /api/activity?...` | 应用内提醒/系统通知 |
| 发送 | `POST /api/agent-messages` | ask / create_task / feedback |

约束：
- 不新增字段依赖；缺字段时按现有「缺了不编」口径处理（例如 `mergeAttempts` 不补假 Attempt）。
- 不改变 `taskLine` / `taskMeta` / `boardColumns` / `BOARD_VIEWS` 的输出语义；视觉层只消费。
- 不缓存 `/api/*`（SW 既有纪律）。

### 7.2 移动端视图状态（UI State）

下游实现应维护（命名可不同，语义必须等价）：

```ts
type MobileViewState = {
  view: 'chat' | 'tasks'                 // 现有两页签
  boardView: 'all' | 'busy' | 'decide' | 'todo' | 'done'
  boardPage: number                      // 当前状态列页索引；仅 boardView === 'all' 有效
  columnScroll: Record<string, number>   // 每个状态列独立纵向滚动位置（会话内）
  detailTaskId: string | null            // 当前打开的轻量详情；null = 关闭
  pendingNewMessages: number             // 用户不在底部时累计的新消息数
  gesture: null | {
    startX: number; startY: number
    dx: number; dy: number
    axis: 'undecided' | 'horizontal' | 'vertical'
    targetIsInteractive: boolean         // 起点是否在按钮/输入/链接上
  }
}
```

不变式：

- `boardPage` 只能落在「当前可见的非空列」范围内；列集合变化（刷新/筛选/空间切换）时夹取到合法页，不出现空白页。
- `detailTaskId` 指向的任务必须来自当前 `state.tasks`；任务消失时自动关闭详情并提示。
- `pendingNewMessages` 只在「用户距底部 > 40px」时累加；滚到底部清零。
- `columnScroll` 只影响滚动，不影响数据。
- 手势状态不写持久化存储；切页签/切空间/关闭详情时重置。

### 7.3 手势契约（切列 / 卡片展开 / 纵向滚动）

| 阶段 | 语义 | 必须满足 |
| --- | --- | --- |
| 开始 | 记录起点、目标元素 | 起点在 `button/a/input/select/textarea/[role=button]` 上时，不启动切列手势（让控件自己处理）；起点在屏幕左右 20px 内不启动（系统返回手势优先）。 |
| 判定 | 轴锁定 | 先超过 8px 的位移决定轴：`|dx| > |dy|` 且 `|dx| >= 48` 才可能横向；`|dy| > |dx|` 立即进入纵向滚动，不再切列。 |
| 提交 | 切页/展开 | 横向提交后切到相邻合法页；到边界时回弹，不循环。 |
| 取消 | 回弹 | 未达阈值、垂直占优、起点在边缘/控件、多指手势 → 回弹，无副作用。 |
| 结束 | 清理 | 移除监听，恢复滚动；不残留 `transform`。 |

硬性约束：

- 手势**永不**调用任务状态迁移 API。
- 手势**永不**在 `input/textarea/select` 上启动。
- 手势**永不**阻止纵向滚动；不得使用 `preventDefault` 拦截所有 `touchmove`。
- 所有手势都有按钮/键盘替代（R-11）。

### 7.4 任务卡显示契约

```ts
type TaskCardViewModel = {
  id: string
  title: string
  statusLine: string        // 来自 taskLine(task)
  metaLine: string          // 来自 taskMeta(task)；空串则不显示
  tone: 'warn' | 'busy' | 'muted' | 'ok'  // 来自 BOARD_COLUMNS / 状态映射
  waitingForNode: boolean   // 来自 isWaitingForNode(task)
  canAppendFeedback: boolean// 来自 canAppendFeedback(task)
  actions: Array<'append_feedback' | 'ask_agent'>
}
```

约束：
- 所有用户可见文案仍走现有 i18n（中文原文为 key，英文覆盖）；不得新增未登记的硬编码中文。
- 状态色与文案同时存在；未知 status 保留原文并标注，不丢弃。
- 卡片不显示桌面才有的字段（diff、审计、完整评论）。

### 7.5 视觉令牌与尺寸

- 保留现有 `:root` 深色令牌；新增布局令牌（间距、圆角、安全区、卡片高度上限）必须集中定义，不散落硬编码。
- 状态色映射沿用 `tone`：`warn`/`busy`/`muted`/`ok` 对应现有 CSS 颜色；不得引入第二套状态色。
- 断点仅作为**验收宽度**：320 / 360 / 390 / 414 / 430 / 768 / 1024；实现可自行选择具体媒体查询值，但必须覆盖这些宽度的验收。
- 内容最大可读宽度：手机不限（占满可用宽度减安全边距）；平板建议 ≤ 720px 居中。
