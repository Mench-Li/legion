### 0.4 本轮关键澄清结论（先看这 8 条）

1. **本目标不是重做登录**：登录/注册/刷新/忘记口令已存在且可用；本目标补的是「登录之后的账号中心」。
2. **主语是「当前登录的我自己的账号」**：P0 只做自助账号管理；管理员对他人账号的既有能力保留但不扩展；多账号列表/快速切换不在本目标。
3. **「基础信息」在 P0 = 显示名**：新增 `displayName`，默认等于用户名，可改；**用户名不可改**。头像为 P1，内置选择、不上传。
4. **「账号信息」= 只读总览**：用户 ID、用户名、显示名、系统角色、空间角色、注册时间、账号状态、当前会话、活跃会话数、执行设备数；数据来自服务端，不编造。
5. **安全能力复用而非重造**：改口令、登录会话列表/撤销、退出登录已经存在；本目标把它们集中到账号页并逐条验收，不改变语义。
6. **明确不做**：邮箱/手机号绑定、OAuth/SSO、2FA、账号注销/自助停用、换用户名、头像上传、手机端新增「我的」页。
7. **接口是追加式**：扩展 `GET /api/identity/me`（新增 `displayName`/`avatar`/`createdAt`/`disabled`），新增一个只更新本人的资料写接口；旧字段/旧客户端不变，旧数据回退用户名。
8. **P0/P1 分开验收**：P0 = R-01–R-10；P1 = R-11–R-13；P1 未完成必须登记，不得伪装成 P0 完成。

## 1. 背景：现状事实与问题

### 1.1 产品背景

Legion 是本地优先的多智能体协作平台。人类以「将军（general）」身份登录 Web 军团指挥台，发布目标、组织空间和编队；team-hub v2 是数据与 API 中枢，负责空间、目标、任务、会话、技能、规范、审计和**用户身份**。

身份体系已经存在且可用：

- 登录/注册/刷新/登出：`POST /api/identity/{login,register,refresh,logout}`；
- 自助改口令：`POST /api/identity/password`；
- 登录会话列表与撤销：`GET /api/identity/sessions`、`POST /api/identity/sessions/revoke`；
- 管理员能力（服务端）：用户列表、停用/启用、邀请码、一次性口令重置码；当前界面暴露用户列表、重置码、邀请码，「停用/启用」只有服务端接口、没有按钮。
- 执行设备（电脑节点）：配对、列表、撤销、换令牌；
- 本机单机部署使用机器令牌时，整块账号面板不渲染（`AccountPanel`/`DevicePanel` 的 `hasSession()` 判据）。

**因此本目标不是「从零做登录」，而是把「登录之后，我是谁、我的账号有哪些信息、我能改什么、我在哪些地方登录/连接」补成一个完整、可管理的账号中心。**

## 2. 目标与成功定义

### 2.1 产品目标

让已登录的用户在**一个地方**完成四件事：

1. **知道我是谁**：看到用户名、显示名、用户 ID、系统角色、加入的空间与角色、注册时间、账号状态。
2. **管理我的基础信息**：在不改变登录名的前提下，修改「别人看到的名字」（显示名）。
3. **管理我的账号安全**：改口令、看当前登录会话、踢掉其它设备、退出登录。
4. **知道我的连接**：看到执行设备（电脑节点）与登录会话是两件事，分别管理。

### 2.2 成功定义（可验收）

本目标完成时，以下旅程可完成：

- **J1 查看账号**：登录 → 设置 → 「连接与令牌」（或改名后的「账号与连接」）→ 一眼看到显示名、用户名、用户 ID、系统角色、空间角色、注册时间、账号状态；不需要去开发者工具或数据库查。
- **J2 改显示名**：在同一页把显示名从「alice」改为「Alice（产品）」→ 保存 → 页面立即显示新名字 → 刷新/重新登录后仍是新名字；登录仍用原用户名 `alice`。
- **J3 账号安全**：看到当前登录会话与其它会话 → 踢掉一台不认识的 → 那台下次请求被要求重新登录；改口令后其它会话全部退出、当前会话保留。
- **J4 连接设备**：看到「登录中的设备」与「执行设备」是两个列表；配对一台电脑、撤销一台丢失的电脑，行为与现在一致。
- **J5 权限边界**：普通用户看不到管理员区块；任何跨用户读取/修改请求都被服务端拒绝；本机机器令牌模式不出现账号/退出按钮。

## 3. 术语与口径（无歧义定义）

| 术语 | 本文件中的确定含义 |
| --- | --- |
| **账号 / 用户** | `hub_users` 中的一条人类用户记录；有登录名、口令哈希、系统角色、空间角色。**不是** AI 成员（Agent）。 |
| **用户名（username / login name）** | `hub_users.name`，登录时输入的名字；大小写不敏感唯一（`name_key`）；**本目标中不可修改**。 |
| **显示名（displayName）** | 人类用户对外展示的名字；默认等于用户名；可修改；**不参与登录、不要求唯一**；本目标新增。 |
| **基础信息** | 本目标限定为「显示名」（P0）与「头像」（P1，可选）。不包含邮箱、手机、生日、地址等。 |
| **账号信息** | 用户 ID、用户名、显示名、系统角色、空间与空间角色、账号状态、注册时间、当前会话、活跃会话数、执行设备数。 |
| **登录会话（session）** | 一次登录产生的访问/刷新令牌对；在「登录中的设备」中展示，可撤销。 |
| **执行设备（device / node）** | 一台接入 Hub 的电脑执行节点；在「执行设备」中展示，可配对、撤销、换令牌。**与会话是两件事**：踢会话不等于撤销设备。 |
| **空间角色** | `hub_space_roles` 中的 `(space, role)` 对，如 `software（member）`。 |
| **系统管理员** | `hub_users.system_role === 'admin'`；管的是「造邀请 / 停用账号 / 重置口令」，**不自动等于能读所有空间数据**。 |
| **成员 / 编队 / Agent** | `roster` 中的 AI 员工（role/name/avatar/kind）。本目标**不修改**成员名称、头像、编队与 Agent 管理；T-195 已单独处理其命名与头像。 |
| **账号管理页** | 设置中的「连接与令牌」页（路由 id `settings-connections` 保持不变）；本目标在其中重组出「账号」区域。 |
| **P0 / P1 / P2** | P0 = 本目标必须通过；P1 = P0 全绿后纳入本轮，未完成需在 TEST_REPORT 登记；P2 = 不在本目标验收。 |

> **关键区分**：本目标的「头像」是**人类账号**的头像，不是 `roster.avatar` 的 Agent 人形令牌；本目标的「名称」是**人类账号显示名**，不是 Agent 成员名。两者不得互相写入、不得共用唯一约束。

## 4. 用户与场景

### 4.1 主要用户

- **将军 / 空间负责人**：需要确认「我现在用哪个账号、加入了哪些空间、在哪些设备上登录着」，并在怀疑账号泄露时快速改口令、踢会话。
- **普通成员**：需要改自己的显示名、看自己的角色和账号状态；不需要管理员能力。
- **系统管理员**：除自助能力外，服务端已支持用户列表、停用/启用、一次性重置码、邀请码；界面现有用户列表/重置/邀请，保留现状，不在本目标新增停用/启用按钮。

### 4.2 关键场景

| 场景 | 触发 | 期望 |
| --- | --- | --- |
| S1 首次进入 | 登录后打开设置 | 一眼看到账号摘要；不闪「正在读取」后空白；读失败有明确提示和重试。 |
| S2 改显示名 | 用户不喜欢登录名被直接展示 | 输入新显示名 → 校验 → 保存 → 立即生效；用户名不变；刷新/换设备仍生效。 |
| S3 怀疑泄露 | 看到不认识的会话 | 能识别「这台」与「其它」；一键踢掉其它；当前会话不受影响。 |
| S4 改口令 | 定期更换或怀疑泄露 | 输入当前口令 + 新口令；成功后其它会话退出、当前保留；提示踢掉几个。 |
| S5 换电脑 | 新电脑要接 Hub | 在「执行设备」生成配对码；旧电脑丢失时撤销；不会误操作「登录会话」。 |
| S6 管理员操作 | 有人忘记口令/要入伙 | 在管理员区生成重置码/邀请码；普通成员看不到这些区块。停用/启用目前只有服务端接口，不在本目标新增按钮。 |
| S7 本机单机 | 没启用远程身份 | 设置页只看到中枢地址/令牌；不出现账号、退出、设备区块。 |

## 5. 范围边界：做什么 / 明确不做什么

### 5.1 做什么（In Scope）

1. **账号页信息架构（P0）**：在 `settings-connections` 内重组「账号」区域，划分为基础信息、账号信息、账号安全、登录中的设备、执行设备、管理员工具（仅管理员）。
2. **显示名（P0）**：新增可持久化的 `displayName`，默认等于用户名；本人可改；用户名不可改。
3. **账号信息总览（P0）**：用户 ID、用户名、显示名、系统角色、空间角色、注册时间、账号状态、当前会话、活跃会话数、执行设备数。
4. **账号安全（P0）**：保留并整合改口令、登录会话列表/撤销、退出登录。
5. **权限与越权防护（P0）**：自助接口只作用于本人；管理员区块与接口保持服务端强制；本机机器令牌模式不渲染账号区。
6. **错误、空态、加载态、无障碍（P0）**：所有新增/重组区域可读、可键盘操作、错误可行动。
7. **回归保护（P0）**：登录/注册/忘记口令/邀请/重置/停用/设备配对全部不回归；手机端 IA 不变。
8. **文档同步（P0）**：`docs/FEATURES.md` 与 `README.md` 中用户可见的账号管理说明按实际行为更新。
9. **头像（P1）**：从内置人形头像集合中选择，或使用默认占位；不做上传。
10. **显示名跨面传播（P1）**：在「当前用户」展示面使用显示名；审计/归属仍用稳定用户名或 userId。
11. **最近登录记录（P1）**：展示最近若干条会话（含已撤销/过期）的登录时间、最近使用、状态。

### 5.2 明确不做什么（Out of Scope）

| 不做 | 原因 / 边界 |
| --- | --- |
| 不改登录/注册/刷新/忘记口令的协议与页面主流程 | 已有能力稳定；本轮只做账号管理，不重做认证。 |
| 不允许修改用户名（`hub_users.name`） | 用户名是登录身份，`name_key` 唯一；改名会影响登录、会话、审计与邀请。若确需改名，另立目标并处理迁移/唯一性/审计。 |
| 不做邮箱/手机号绑定与验证 | Hub 没有邮件/短信通道（`AccountPanel.tsx:173-175` 已明确「Hub 没有邮件通道」）；无验证的联系方式只会制造「以为能找回」的假能力。账号恢复继续走管理员一次性重置码。 |
| 不做 OAuth / SSO / 第三方登录 | 自托管身份体系已存在；引入外部 IdP 是另一个安全与部署目标。 |
| 不做 TOTP/短信二次验证、恢复码 | 同上；需要新的密钥管理、恢复流程与威胁模型。 |
| 不做账号注销、自助停用、删除数据 | 涉及数据归属、空间移交、审计保留；管理员停用能力已存在。另立目标。 |
| 不做头像上传/裁剪/图片存储 | 需要文件上传、尺寸校验、存储与清理；P1 只做内置头像选择。 |
| 不做管理员「查看/编辑所有用户资料」的扩展 | 现有管理员能力（用户列表、重置、邀请；停用/启用为服务端接口）保留；不新增「管理员改别人显示名/头像」。 |
| 不改变成员（Agent）名称/头像/编队 | 那是 roster 域，T-195 已单独处理；本目标不得写 `roster`。 |
| 不在手机端新增「我的」页或改变两页签 IA | 手机端产品定义是「看着我的人干活」（`app.mjs:1126-1133`）；账号管理留在桌面/网页端。手机端只保留现有退出登录。 |
| 不做多账号列表/快速切换 | 本目标管理「当前登录的一个账号」；多账号需要凭据隔离、切换协议与安全设计，另立目标（见 R-14）。 |
| 不改变登录会话/执行设备的安全语义 | 会话 = 登录凭据；设备 = 可领任务的执行节点。两者不得合并。 |
| 不改变审计 `by` 身份、任务归属、空间角色语义 | 显示名只是展示层；归属仍用稳定标识。 |
| 不引入新的运行时依赖或构建步骤 | 仓库纪律；现有 React/Node 能力足够。 |
| 不把「假设」写成结论 | 所有未拍板项集中在 §11，带默认执行口径。 |

### 5.3 边界判定规则

下游遇到一个新想法时，用这三问判定：

1. 需要新增**认证协议、外部 IdP、邮件/短信通道、文件上传**吗？→ 需要则**不做**，登记后续目标。
2. 会改变**用户名、登录身份、空间角色、审计归属、成员 roster** 吗？→ 会则**不做**。
3. 只是让「已登录用户查看/编辑自己的展示信息、会话、设备」更清楚吗？→ 是则**可做**，但必须落到 §9 的可测验收。

## 6. 需求清单（编号 + 优先级 + 背景 / 目标 / 验收口径）

> 每条需求都必须有「背景 / 目标 / 验收口径」三部分。P0 未全绿不得交付；P1 在 P0 全绿后纳入本轮，未完成需在 TEST_REPORT 登记为后续；P2 不在本目标验收。

### R-01 账号页信息架构与入口（P0）

- **背景**：F1、F7。账号、设备、中枢连接混排；管理员工具与自助工具没有清晰分区。
- **目标**：在设置「连接与令牌」（`settings-connections`）内建立清晰的账号区域，让用户按「我是谁 → 我的安全 → 我的连接 → 管理他人（若管理员）」的顺序阅读。
- **验收口径**：
  - 路由 id `settings-connections` 与现有入口不变；左侧设置仍可到达；页面标题可从「连接与令牌」调整为「账号与连接」，但不得改变 hash/路由 id 导致旧链接失效。
  - 有用户会话时，页面按顺序出现：**账号摘要 / 基础信息 / 账号信息 / 账号安全（改口令、退出登录）/ 登录中的设备 / 执行设备 / 账号管理（仅系统管理员）**；具体视觉分组可等价，但语义区块必须齐全。
  - 无用户会话（本机机器令牌模式）时，不渲染账号摘要、基础信息、账号安全、登录设备、执行设备、管理员区块；只保留中枢地址/写操作令牌。
  - 非管理员不渲染「账号管理（管理员）」区块，且不因读取管理员数据产生 403 提示（沿用 `AccountPanel.tsx:53-55` 的克制）。
  - 现有 `DevicePanel` 的配对/撤销/换令牌能力保留，不得为了「合并页面」而删除或弱化。
  - 任意区块读取失败不得让整页空白：失败区块显示错误与重试，其它区块仍可用（沿用 `AccountPanel.tsx:56-60` 的「不抹掉整节」纪律）。

### R-02 基础信息：显示名查看与编辑（P0，本目标核心）

- **背景**：F2、F4、F5。只有登录名，没有可编辑的展示名；直接改登录名风险高。
- **目标**：新增「显示名」作为人类账号的可编辑展示字段；默认等于用户名；登录名保持不变。
- **验收口径**：
  - 账号摘要与基础信息区同时显示**用户名（登录名）**与**显示名**；两者标签不得混用；显示名默认等于用户名（旧数据无显示名时回退用户名，不得显示空白）。
  - 显示名可编辑并保存；保存成功后：
    - 当前页面立即显示新显示名，无需整页刷新；
    - 刷新页面、关闭后重新登录、在另一浏览器登录，显示名均为新值；
    - 用户名、登录行为、已有会话、空间角色、审计归属均不变。
  - 校验规则：去首尾空白后长度 **1–64** 字符；拒绝空/全空白、超过 64 字符、含 C0 控制字符（U+0000–U+001F、U+007F）或换行的输入；错误码 `IDENTITY_INVALID_INPUT`；失败时不得写库、不得部分更新。长度口径与现有用户名校验一致（`String.length`，UTF-16 code unit），避免前后端对 emoji/CJK 计数不一致。
  - 显示名**不要求唯一**；两个用户可以同名。管理员用户列表与任何需要区分人的地方，必须同时展示「显示名（用户名）」或等价的两个字段，不能只显示显示名。
  - 用户名不可编辑：请求中携带 `name`/`nameKey`/`userId` 等非允许字段时，按未知字段拒绝（`IDENTITY_INVALID_INPUT`），不得静默修改。
  - 显示名按**纯文本**渲染，不执行 HTML/脚本；长度与字符校验在服务端与客户端同时存在（服务端为准）。
  - 保存动作写入审计 `identity:profile-update`，包含操作者 userId 与被修改字段名；不得记录口令、令牌或哈希。
  - 并发保存采用「后写覆盖」并在响应中返回最终生效值；页面以服务端返回值回填，不假设本地草稿一定生效。

### R-03 账号信息总览（P0）

- **背景**：F3、F10。本人看不到用户 ID、注册时间、账号状态；这些信息分散在管理员接口里。
- **目标**：在账号页集中展示「我是谁」的只读信息，数据全部来自服务端，不伪造。
- **验收口径**：
  - 展示字段至少包含：**用户 ID、用户名、显示名、系统角色（系统管理员/普通成员）、账号状态（正常/已停用）、注册时间、空间与空间角色列表、当前会话标识、活跃会话数、执行设备数**。
  - 每个字段与对应接口读数一致；缺失字段显示「—」或「未知」，不得编造默认值；空间列表为空时显示「还没有加入任何空间」（沿用 `AccountPanel.tsx:124-126` 的口径）。
  - 注册时间由服务端 ISO 时间派生，按用户本地时区展示；原始 ISO 值可在调试/测试中断言。
  - 当前会话必须能被识别（与 `/api/identity/sessions` 的 `currentSessionId` 对应）；「这台（现在）」标识保留。
  - 活跃会话数 = 未撤销会话数；执行设备数 = 未撤销设备数；两个数字分别来自会话/设备接口，不能用其中一个冒充另一个。
  - 本人账号状态通常显示「正常」；账号被停用后无法登录、不能停留在账号页，因此「已停用」主要出现在管理员用户列表；不得把「读不到」显示成「已停用」或「正常」。
  - 任一数据源失败时，该字段/区块显示「读取失败」与重试入口；不得把失败显示成 0 或空列表。
  - 页面与接口响应中**永远不出现** `password_hash`、访问令牌、刷新令牌、邀请码明文、重置码明文（管理员刚生成时的一次性展示除外，见 §7.1 的既有行为）。

### R-04 账号安全：自助改口令（P0，既有能力保留）

- **背景**：F11。改口令能力已存在，但必须保证在账号页重组后行为不变。
- **目标**：用户用当前口令换新口令；成功后踢掉其它会话、保留当前会话。
- **验收口径**：
  - 当前口令与新口令均为必填；新口令长度 8–512；新口令不得与当前口令相同；当前口令错误返回 `IDENTITY_WRONG_PASSWORD`（HTTP 401）。
  - 成功后：其它所有未撤销会话被撤销，**当前会话保持有效**；响应返回 `revokedOtherSessions` 数量；页面提示「已退出 N 个其它登录」并刷新会话列表。
  - 口令输入框始终 `type="password"`、不回填、不在日志/审计/URL 中出现明文。
  - 失败时不得修改口令哈希、不得撤销任何会话；错误信息可行动（当前口令错误 / 新口令太短 / 新旧相同）。
  - 该能力在非管理员与管理员账号上行为一致；不得因显示名/头像改动而改变会话撤销范围。

### R-05 登录会话管理（P0，既有能力保留）

- **背景**：F6、F11。会话列表与撤销已存在；账号页必须让「这台」与「其它设备」一眼可分。
- **目标**：用户能查看并撤销自己的登录会话，不能撤销当前会话（用退出登录）。
- **验收口径**：
  - 列出所有未撤销会话的标签、创建时间、最近使用时间；当前会话标记「这台（现在）」；列表按最近创建时间倒序（沿用服务端 `listSessions` 顺序）。
  - 只对非当前会话显示「退出这台」；对当前会话不提供撤销按钮（避免「点一下把自己踢掉」的误解）。
  - 撤销成功后该会话从活跃列表消失；被撤销会话的下一次请求返回 401（`IDENTITY_SESSION_REVOKED`/`IDENTITY_TOKEN_EXPIRED` 之一），客户端切回登录屏并给出明确提示（401 处理按 R-09 的会话恢复要求；刷新凭据轮换与单飞逻辑见 `identity.ts:262-279`）。
  - 撤销失败（网络/401/403）不得从列表移除该项，不得显示成功。
  - 普通用户不能撤销他人的会话；服务端仍按 `identity.mjs:435-451` 强制，前端隐藏不是安全边界。

### R-06 退出登录（P0，既有能力保留）

- **背景**：F1、F8。退出登录必须仍然可用且语义清楚。
- **目标**：退出当前会话并清除本地凭据；本机机器令牌模式不出现该按钮。
- **验收口径**：
  - 点击「退出登录」→ 调用 `POST /api/identity/logout` → 无论请求成功与否都清除 `sessionStorage` 访问令牌与 `localStorage` 刷新凭据 → 整页回到登录屏。
  - 退出后浏览器后退/刷新不得回到已登录界面；重新登录需要重新输入口令（除非未来另立「记住我」目标）。
  - 本机机器令牌模式（无用户会话）不渲染退出按钮；不能把「退出本机 Legion」与「退出账号」混淆。
  - 退出不删除账号、不撤销执行设备、不清空空间数据；只撤销当前登录会话。

### R-07 权限与自我边界（P0）

- **背景**：F12。现有服务端边界正确；重构 UI 与新增资料接口时最容易把「前端隐藏」误当安全。
- **目标**：所有自助接口只作用于当前令牌对应的用户；管理员能力保持服务端强制；本机模式不被账号体系污染。
- **验收口径**：
  - 新的资料更新接口只从 Bearer 令牌解析 userId；请求体中的 `userId`/`name` 不得改变目标；跨用户写入尝试返回 400/403，且不产生任何数据变更。
  - `GET /api/identity/users` 仍要求系统管理员；非管理员 403；前端不得为了「看起来完整」而提前调用并吞掉 403。
  - 停用账号：不能登录；已存在会话被撤销；刷新令牌失败（`IDENTITY_SESSION_REVOKED`）；携带旧访问令牌请求 `/me` 也返回 401（`IDENTITY_SESSION_REVOKED`）；账号页不显示为「正常」。
  - 未登录调用 `/api/identity/me`、`/sessions`、`/password`、新资料接口均返回 401 与具名 code；不得回退到机器令牌身份。
  - 任何跨用户读取（包括显示名、会话、设备）不得通过新接口暴露；管理员列表是唯一例外且必须要求系统管理员。
  - 本机机器令牌模式：`hasSession()` 为 false 时整块账号区域不渲染；不得出现「账号」「退出登录」等误导性入口。

### R-08 输入校验与错误契约（P0）

- **背景**：F4、F5。新增可写字段必须有确定的服务端校验与错误语义，否则下游只能靠字符串匹配。
- **目标**：所有账号写操作使用统一的 `{ok:false, code, error}` 错误形状与具名 code；前端按 code 分支，不按中文文案匹配。
- **验收口径**：
  - 显示名校验按 R-02；未知字段拒绝；请求体非对象/缺少字段返回 `IDENTITY_INVALID_INPUT`。
  - 错误码至少覆盖：`IDENTITY_INVALID_INPUT`、`IDENTITY_FORBIDDEN`、`IDENTITY_TOKEN_MISSING`、`IDENTITY_TOKEN_EXPIRED`、`IDENTITY_TOKEN_MALFORMED`、`IDENTITY_TOKEN_BAD_SIGNATURE`、`IDENTITY_SESSION_REVOKED`、`IDENTITY_WRONG_PASSWORD`、`IDENTITY_USER_NOT_FOUND`、`HUB_UNREACHABLE`（客户端网络失败）。
  - 前端错误展示为可行动的中文，不展示堆栈/HTML；401 会话过期走既有单飞刷新，刷新失败回登录屏。
  - 任何写操作失败都不得产生部分写入（例如资料已改但审计未写、或口令已改但会话未撤销）；事务边界由服务端保证。
  - 空/超长/控制字符输入在客户端先给出提示，但服务端必须独立拒绝（客户端校验不是安全边界）。

### R-09 加载、空态、错误与无障碍（P0）

- **背景**：F1–F3；账号页是低频但敏感页面，空白/卡住会被误读为「账号没了」。
- **目标**：页面在任何数据状态下都能解释自己；键盘与读屏用户能完成核心操作。
- **验收口径**：
  - 初次加载显示明确的加载文案/骨架；不得先渲染空表单再跳变。
  - 账号页的身份读取（`/me`、`/sessions`、`/devices`）收到 401 时，应尝试一次既有单飞 `recoverSession()`；刷新成功则重试原请求，刷新失败才清会话并回登录屏。不得把「访问令牌过期（15 分钟）」直接显示成「账号读取失败」。
  - 每个区块有独立空态（无会话、无设备、未加入空间、读不到用户列表）与独立错误态；错误态有「重试」。
  - 表单控件有可见标签；保存/撤销/退出按钮有可访问名；忙碌时禁用并防重复提交；保存成功/失败通过 `role="status"` 或 `aria-live` 播报。
  - 键盘可完成：进入账号页 → 编辑显示名 → 保存 → 改口令 → 撤销会话 → 退出登录；焦点顺序合理，焦点环可见。
  - 状态不只靠颜色表达（「正常/已停用」「这台/其它」「在线/离线/还没连过」均有文字）。
  - 长显示名/长设备名不撑破布局；在窄屏（桌面窗口最小宽度）下不横向溢出。

### R-10 回归与兼容（P0）

- **背景**：账号页与登录门、设备管理、管理员工具共用同一批接口；任何重构都可能悄悄改坏。
- **目标**：本目标只增加账号管理能力，不改变既有认证、会话、设备、邀请、重置、停用语义。
- **验收口径**：
  - 登录、注册、忘记口令、刷新、退出、邀请、口令重置、停用/启用、设备配对/撤销/换令牌全部按现有行为工作。
  - 本机机器令牌模式、手机端 PWA、桌面任务/对话/文件/日历等功能不回归；手机端不新增账号页。
  - `GET /api/identity/me` 的新增字段是**追加式**；旧客户端只读 `user.userId`/`user.name`/`roles`/`systemRole` 仍正常。
  - `hub_users.name`、`name_key`、口令哈希格式、令牌格式/TTL、会话撤销语义、审计 `by` 语义均不变。
  - 不新增运行时依赖/构建步骤；不联网安装。
  - §9.2 的回归命令全部 exit 0；新增测试覆盖 R-01–R-09。

### R-11 头像选择（P1）

- **背景**：F2；人类账号没有头像，而 Agent 已有 `human:<key>` 人形令牌体系。不能把两者混用。
- **目标**：用户可选择一个内置人形头像，或使用默认占位；不做上传。
- **验收口径**：
  - 头像来源限定为内置的合法令牌集合（与现有 Agent 头像资产同一视觉体系，但使用**账号头像字段**，不得写 `roster.avatar`）；空值 = 默认占位。
  - 非法令牌、旧 emoji、任意 URL、HTML 一律拒绝（`IDENTITY_INVALID_INPUT`），不得原样落库；渲染失败回落确定性默认占位，不出现破图。
  - 头像在同一账号的账号摘要与基础信息区一致；刷新/重新登录后保持。
  - 头像不改变登录名、显示名、会话、设备或 Agent 成员头像；不得把账号头像写进 `roster`，也不得把 roster 头像当作账号头像。
  - 若 P1 未完成，账号页不得出现空白头像框或 emoji；可以只显示显示名首字/中性占位，并在 TEST_REPORT 登记 P1 未完成。

### R-12 显示名在「当前用户」展示面的传播（P1）

- **背景**：R-02 的显示名如果只出现在账号页，价值有限；但全局替换展示名会影响归属与审计，需单独验收。
- **目标**：凡展示「当前登录用户」名字的地方，优先显示显示名；认证与归属仍用稳定用户名/userId。
- **验收口径**：
  - 至少覆盖：账号摘要、账号信息区、对话中「我」的身份标识（若现有界面显示当前用户名）。
  - 登录页、会话校验、管理员用户列表、审计 actor 仍显示/使用用户名；管理员列表可同时显示「显示名（用户名）」。
  - 修改显示名后，上述展示面在刷新/重新进入后显示新值；旧用户名仍可用于登录。
  - 不改变任何 API 的 `by`/`author`/`actor` 字段值；不把显示名当作身份键。
  - 若 P1 未完成，P0 的账号页显示名仍必须正确（R-02），不得因此阻塞 P0。

### R-13 最近登录记录（P1）

- **背景**：F6；用户需要判断「有没有人在别处登录过」。
- **目标**：在「登录中的设备」之外，展示最近若干条登录记录（含已撤销/过期），帮助识别异常。
- **验收口径**：
  - 展示最近 5 条会话记录：设备标签、创建时间、最近使用时间、状态（当前/活跃/已撤销/已过期）；数据来自现有 `GET /api/identity/sessions`，不新增敏感字段。
  - 不展示 IP、地理位置、浏览器指纹等未存储或未验证的信息；不得编造。
  - 撤销/退出后，记录状态在下次加载时更新；不把已撤销记录算进「活跃会话数」。
  - 普通用户只能看自己的记录；管理员不通过此区查看他人记录（管理员用户列表保持现状）。

### R-14 后续候选（P2，不在本目标验收）

- 账号注销 / 自助停用 / 数据导出与删除；
- 用户名修改（含迁移与审计）；
- 邮箱/手机号绑定与验证、邮件/短信找回；
- OAuth / SSO / 企业 IdP；
- TOTP/短信二次验证、恢复码；
- 头像上传、裁剪、图片存储；
- 登录历史 IP/地理/设备指纹；
- 多账号快速切换。

以上只登记为候选，不得挤占 P0/P1；若实现，必须另立目标并补验收口径。

## 7. 需求级接口 / 数据结构契约

> 本节是**下游必须消费的行为契约**，不是技术选型。具体表结构、SQL、组件拆分、CSS 由方案与编码阶段决定；但对外字段语义、默认值、错误码与权限边界必须一致。若方案阶段选择等价路径，必须在 `RESEARCH.md` 登记并保持同一语义。

### 7.1 既有接口（复用，不改变语义）

| 能力 | 接口 | 现有行为 |
| --- | --- | --- |
| 能力发现 | `GET /api/identity/status` | `enabled/bootstrapped/remoteAuthRequired/registration` |
| 登录/注册/刷新/登出 | `POST /api/identity/{login,register,refresh,logout}` | 令牌发放、轮换、撤销 |
| 本人信息 | `GET /api/identity/me` | `user{userId,name}`、`roles`、`systemRole` |
| 会话列表/撤销 | `GET /api/identity/sessions`、`POST /api/identity/sessions/revoke` | 本人会话、当前会话 id |
| 改口令 | `POST /api/identity/password` | 校验当前口令、撤销其它会话 |
| 管理员用户 | `GET /api/identity/users`、`POST /api/identity/users/disable` | 系统管理员 |
| 邀请/重置/角色 | `POST /api/identity/{invites,password/reset-code,password/reset,roles/grant,roles/revoke}` | 既有权限规则 |
| 设备 | `GET /api/devices`、`POST /api/devices/{pairing,pair,revoke,rotate}` | 本人/管理员边界 |

### 7.2 账号数据模型（语义字段）

在现有用户记录上**追加式**补充以下语义（内部列名可由方案阶段定，但必须可持久化、可迁移、旧数据可回退）：

| 字段 | 类型/默认 | 语义 | 约束 |
| --- | --- | --- | --- |
| `userId` | 稳定 ID | 用户唯一标识 | 不可变；对外展示用于支持排查 |
| `name` | 字符串 | 登录用户名 | **不可变**；大小写不敏感唯一；继续用于登录与审计 actor |
| `displayName` | 字符串，默认 `name` | 人类可读展示名 | 1–64 字符；trim；非唯一；不参与认证 |
| `avatar` | 字符串/空，默认空 | 账号头像令牌（P1） | 仅允许内置合法集合；空 = 默认占位 |
| `createdAt` | ISO 时间 | 注册时间 | 只读 |
| `disabled` | 布尔 | 账号是否停用 | 只读（本人）；管理员可改 |
| `systemRole` | `admin`/`none` | 系统管理员 | 只读（本人）；管理员操作受服务端约束 |
| `roles` | `[{space,role}]` | 空间角色 | 只读（本人）；变更走既有 grant/revoke |
| `sessions` | 会话列表 | 登录会话 | 不落新表；复用 `hub_user_sessions` |
| `devices` | 设备列表 | 执行设备 | 不落新表；复用设备存储 |

**不变式**：

- `name`/`name_key` 不因本目标改变；`displayName` 不写回 `name`。
- 资料更新不得触碰 `password_hash`、`disabled_at_ms`、`system_role`、`hub_space_roles`、`roster`。
- 旧数据没有 `displayName` 时，所有读取投影必须回退为 `name`；不得出现空显示名。
- 旧数据没有 `avatar` 时，投影为空/默认，不得回退到 Agent 头像或 emoji。

### 7.3 `GET /api/identity/me` 扩展契约

保持现有字段不变，追加本人可见的账号信息：

```json
{
  "ok": true,
  "user": {
    "userId": "user-...",
    "name": "alice",
    "displayName": "Alice",
    "avatar": "",
    "createdAt": "2026-10-29T08:00:00.000Z",
    "disabled": false
  },
  "roles": [{ "space": "software", "role": "member" }],
  "systemRole": "none"
}
```

约束：

- `user.name` 仍是登录用户名；`displayName` 是展示名；二者不得合并。
- 不返回 `password_hash`、`name_key`、任何令牌或哈希。
- 旧客户端忽略新增字段即可；不得要求旧客户端升级才能登录。
- `disabled` 对本人通常为 `false`（能拿到有效令牌说明未停用）；保留字段用于契约完整性，不能据此替代服务端鉴权。

### 7.4 新增资料更新契约（建议 `POST /api/identity/profile`）

> 路径名可由方案阶段调整，但请求/响应/错误/权限语义必须保持；若调整，必须在 `RESEARCH.md` 与 `TASK_BREAKDOWN.md` 登记，并同步测试与文档。

**请求**：

```http
POST /api/identity/profile
Authorization: Bearer <user access token>
Content-Type: application/json

{ "displayName": "Alice" }
```

- 只接受 `displayName`（P1 可追加 `avatar`）；不接受 `userId`、`name`、`nameKey`、`password` 等字段。
- userId、操作者身份一律从 Bearer 令牌解析，不信任请求体。
- 请求体为未知字段/非对象/缺少 `displayName` → `400 IDENTITY_INVALID_INPUT`。

**成功响应**（200）：

```json
{
  "ok": true,
  "user": {
    "userId": "user-...",
    "name": "alice",
    "displayName": "Alice",
    "avatar": "",
    "createdAt": "2026-10-29T08:00:00.000Z",
    "disabled": false
  }
}
```

**错误语义**：

| HTTP | code | 触发 |
| --- | --- | --- |
| 400 | `IDENTITY_INVALID_INPUT` | 缺失/空/超长/控制字符/未知字段 |
| 401 | `IDENTITY_TOKEN_MISSING` | 没有 Bearer |
| 401 | `IDENTITY_TOKEN_MALFORMED` / `IDENTITY_TOKEN_BAD_SIGNATURE` / `IDENTITY_TOKEN_EXPIRED` | 令牌无效/过期 |
| 401 | `IDENTITY_SESSION_REVOKED` | 会话已撤销或账号停用 |
| 403 | `IDENTITY_FORBIDDEN` | 无权操作（服务端判定） |
| 404 | `IDENTITY_USER_NOT_FOUND` | 令牌指向的用户不存在（异常数据） |

**副作用与审计**：

- 只更新当前用户的显示名（P1 头像）；不撤销会话、不改口令、不改角色。
- 写审计 `identity:profile-update`，scope `global`，detail 至少包含 `{ fields: ['displayName'] }`；可记录新旧值（显示名非秘密），不得记录口令/令牌。
- 失败时不得产生部分写入；整个更新在一个事务内完成。

### 7.5 前端视图状态（语义等价即可）

```ts
type AccountPageState = {
  me: {
    userId: string
    username: string
    displayName: string
    avatar: string
    systemRole: 'admin' | 'none'
    status: 'active' | 'disabled'
    createdAt: string
    roles: Array<{ space: string; role: string }>
  } | null
  sessions: { rows: SessionRow[]; currentId: string | null }
  devices: DeviceRow[]
  currentSession: SessionRow | null
  editingDisplayName: boolean
  draftDisplayName: string
  busy: boolean
  loadError: string | null       // 整体读取失败
  sectionErrors: Record<'sessions' | 'devices' | 'users', string | null>
}
```

不变式：

- `draftDisplayName` 只在编辑态存在；取消编辑恢复为 `me.displayName`。
- `me === null` 且未加载完成 → 加载态；加载失败 → 错误态 + 重试；`me === null` 且无用户会话 → 整块不渲染。
- `sessions.rows` 只显示未撤销会话（P1 最近登录区可读取全量，但必须显式区分状态）。
- `devices` 与 `sessions` 是两份独立数据；任一失败不得把另一份清空。
- 保存成功后用服务端返回的 `user` 回填，不以本地草稿为准。

### 7.6 审计与事件

- 资料更新：`identity:profile-update`。
- 既有口令修改、会话撤销、用户停用/启用、邀请、重置、设备操作继续走现有审计动作，不改名、不改 scope。
- 新增字段不得进入 SSE 高频事件；账号资料是低频读，不要求实时广播。

## 11. 待将军确认（显式问题，不悄悄留给下游）

> 以下每项都有**默认执行口径**；默认口径足以让下游开工。将军若改变口径，请直接在该项下批注，需求版本随之更新。

1. **❓ 「账号管理」是只管理我自己的账号，还是也要管理别人的账号？**
   默认：本目标 = **自助账号管理**；管理员现有的用户列表/重置/邀请（停用/启用为服务端接口）保留，不新增「管理员编辑他人资料」。
   备选：若要管理员统一维护所有人的显示名/头像，属于新目标，需要补权限与审计设计。
   倾向：目标原句是「我登录的账号」，自助范围最贴合。

2. **❓ 是否允许修改用户名（登录名）？**
   默认：**不允许**；只新增显示名。用户名是登录身份，改名会影响登录、唯一约束、会话与审计。
   备选：若必须改名，另立目标，设计迁移、唯一性、旧名保留与审计。
   倾向：显示名已能满足「展示名字」的诉求，风险最低。

3. **❓ 头像要做到什么程度？**
   默认：P1，从内置人形头像集合选择或使用默认占位；不做上传。
   备选：若要上传/裁剪，需要文件存储、尺寸校验、清理与安全设计，另立目标。
   倾向：先复用现有离线自足的头像资产体系，不引入上传面。

4. **❓ 是否需要邮箱/手机号等联系方式？**
   默认：**不做**。Hub 没有邮件/短信通道，未验证的联系方式会造成「以为能找回」的假能力；账号恢复继续走管理员一次性重置码。
   备选：若要做，需先有邮件/短信服务与验证流程，另立目标。
   倾向：保持现有带外恢复口径。

5. **❓ 手机端要不要账号页？**
   默认：**不做**；手机端保持 Agent/任务两页签，账号管理留在桌面/网页端（与现有产品口径一致）。
   备选：若要手机端只读账号摘要，可作为 P1/P2 另立，且需补 i18n 与移动布局验收。
   倾向：不改变手机端 IA，避免与「看着我的人干活」的产品定义冲突。

6. **❓ 是否要支持账号注销/自助停用？**
   默认：**不做**；管理员停用能力已存在。注销涉及数据归属、空间移交、审计保留，另立目标。
   备选：若要做，需先定义「注销后任务/会话/设备/审计归谁」。
   倾向：先补「看得见、改得了、踢得掉」，不做不可逆动作。

7. **❓ 显示名要不要唯一？**
   默认：**不唯一**；允许重名，管理员列表与需要区分的地方显示「显示名（用户名）」。
   备选：若要求唯一，需要新的唯一约束与冲突错误码，且会限制常见昵称。
   倾向：显示名是展示属性，不是身份键；唯一性交给用户名。

8. **❓ 显示名是否要在对话/审计等所有地方替换？**
   默认：P1 只在「当前用户」展示面替换；登录、审计 actor、`by` 归属仍用用户名；P0 只保证账号页正确。
   备选：若要求全局替换，需要逐面审计并接受「显示名重名导致归属歧义」的风险。
   倾向：先展示层替换，身份层不动。

9. **❓ 「我登录的账号」是当前一个账号，还是多个已登录账号？**
   默认：本目标管理**当前登录的一个账号**；不做账号列表、快速切换或多账号同时在线。
   备选：若要「记住多个账号并一键切换」，需要凭据隔离、切换协议、会话清理与安全设计，另立目标（R-14 已登记候选）。
   倾向：目标上下文与常规账号管理语义都指向「当前账号的资料与安全」。
