## 一、★★★★★ 缺陷甲：中途抛错 ⇒ 后面的变异**根本没跑**，而输出**看起来一样**

旧实现：

```js
try { m = applyMutation(ORIG, from, to, opt?.all === true) }
catch (e) { throw new Error(`${name}: ${e.message}`) }   // ← 整个循环在这里中断
```

某条变异的**锚点没命中**就 `throw` ⇒ 循环中断 ⇒ 排在后面的变异**一条都没跑**，
而末尾那段总结**永远不打印**。

> 一个「破验输出里没有"没咬住"，所以都咬住了」的印象，
> 与一个「脚本在中间那个锚点没命中时抛异常退出，后面那些变异根本没跑」的事实，
> 在我数输出行数与 `MUT` 条数对不对得上之前是同一个东西。

★ 这不是假想的：**今天（本轮）就踩了两次**（守卫破验的 M5/M6 锚点没命中，当场中断）。

**修法**（三道防线）：

1. 每条变异**独立 `try/catch`** —— 锚点没命中就**记一条并继续**，绝不中断整轮；
2. 总结里**永远**打印 **`跑了 N/M 条`**，并把「锚点没命中」**单列**成一类；
3. 「锚点没命中」与「真缺口」**都**让退出码非零 —— **"没跑成"不等于"通过"**。

新的总结长这样：

```
  **跑了 9/9 条**（咬住 9；真缺口 0 条；可证等价 0 条；**锚点没命中 0 条**）
```

★ 另外 `runMutations` 现在**返回**一份结构化总结（`{declared, processed, complete, bitten, gaps,
equivalent, anchorMissed, restoredByteIdentical}`），所以它能被**判据**检查，而不是只能靠人读输出。

## 二、★★★★★ 缺陷乙：父进程是 `node --test` ⇒ 子进程**一个文件都没跑**

`node --test` 会把 **`NODE_TEST_CONTEXT` 导出给子进程**。于是当"跑破验的进程"本身也是
`node --test` 起的（比如**给破验工具自己写判据**），子进程那次 `node --test <file>` 会认为
自己在**嵌套**：

```
Warning: node:test run() is being called recursively within a test file. skipping running files.
```

然后**一个测试文件都不跑**。后果的形态极其危险：

> 子进程跑 **0** 个测试 ⇒ 输出里没有 `ℹ fail 0` ⇒ 被读成"没绿" ⇒ 读成
> "**这个变异被咬住了**" ⇒ **每一个变异都"咬住"**，而**一个测试都没跑**。

> 一个「我起个子进程跑另一个套件，看它绿不绿」的印象，
> 与一个「父进程是 `node --test`，它把 `NODE_TEST_CONTEXT` 传给了子进程，
> 于是子进程一个文件都没跑就说 skipping」的事实，
> 在我看到那行 warning 之前是同一个东西。

**修法**：子进程的 `env` 里**删掉** `NODE_TEST_CONTEXT`（顺带 `NODE_OPTIONS`）。

★★ 这是 **failure class #25**，与切片 51 的「代理判据」同类 ——
**读数来自一个什么都没跑的运行**。（#24 是"判据够不到那一层"，#25 是"跑了零个测试"。）

## 三、为什么"搬进仓库"本身是这一轮的事

> 一个「我这套破验一直在跑，所以这些读数可信」的印象，
> 与一个「跑它的那个文件**不在仓库里**、随工作树一起消失」的事实，
> 在我把它 `git add` 进来之前是同一个东西。

★ 与切片 51 那条「全量回归 82 套件全绿 ⇒ 我这一片的判据也在这 82 里」的错觉**同类**：
**读数来自一个不可复现的东西**。区别只是那次是"选择器够不到"，这次是"文件不在版本控制里"。

★ 保留了 `.worktrees/_prt-handoff/mutate-lib.mjs` 作为**再导出**：
二十来个 `mutate-*.mjs` 是历史破验的**现场记录**，它们 `import './mutate-lib.mjs'`；
留一层转发比改二十个文件稳，而且**只有一份实现**。

## 四、判据（`scripts/prt/mutate-lib.test.mjs`，6 例）

| # | 钉住什么 |
| --- | --- |
| ① | ★★★★★ **中间一条锚点没命中 ⇒ 后面的变异照样跑**，`processed === declared`、`complete === true`、`anchorMissed` 单列、收尾**逐字节还原** |
| ② | 全部命中锚点 ⇒ 一轮完整、没有"没跑成" |

★ ① 就是那个坑本身：旧实现下它**必然失败**（M3 根本没跑）。

★ 判据里造了一个**故意没被覆盖**的导出（`UNCHECKED`）来当"真缺口" ——
`VALUE` / `OTHER` 被断言、`UNCHECKED` 不被断言，三种结果（咬住 / 没跑成 / 真缺口）各有一条。
