## 一、缺陷 21：一个查询参数把只读接口打成 500

原式（切片 50 原样搬过来的）：

```js
const limit = Math.min(Number(url.searchParams.get('limit') ?? 50) || 50, 500)
```

**只夹了上界**：

| 输入 | 旧行为 | 为什么 |
| --- | --- | --- |
| `2.7` | **500** | 值是 2.7（没取整）⇒ 原样进 `LIMIT ?` ⇒ SQLite 抛错 ⇒ `handle()` 兜底成 500 |
| `-5` | **全部**（60 条） | `Math.min(-5,500) = -5`，而 SQLite 的**负** `LIMIT` 意思是**不限制** |
| `0` / `abc` | 50 | `0 \|\| 50` / `NaN \|\| 50` |

> 一个「`Math.min(x, 500)` 已经把 limit 夹在合理范围里了」的印象，
> 与一个「它夹的是**上界**，下界和整数性都没管，而 SQLite 会因此抛错」的事实，
> 在我把 `2.7` 真的发一次之前是同一个东西。

**修法**（两处一起治，因为同一个"没有下界"的根）：

```js
const n = Math.trunc(Number(url.searchParams.get('limit') ?? 50) || 50)
const limit = Math.min(Math.max(n, 1), 500)
```

★ **刻意保持不变的**：`0` 与 `abc` 仍回落到 **50** —— `|| 50` 在 `Math.trunc` **之前**，
所以 `0` 仍然是 falsy。这一点很容易在"顺手重写"时改掉，所以判据里单独钉了。

★★ `-5` 从"给我全部"变成 **1**，修掉的是那句话的另一半：

> **一个"限制条数"的参数，不能被用来取消限制。**

## 二、缺陷 20：把**值**写在了**键**的位置上

```js
code: CONTEXT_PLAN_ERRORS.TEAM_PLAN_NOT_FOUND,   // ← 取到 undefined
```

`CONTEXT_PLAN_ERRORS` 的键是
`PLAN_NOT_FOUND / PLAN_INVALID / PLAN_FROZEN / MANIFEST_NOT_FOUND / MANIFEST_INVALID / PLAINTEXT_SECRET / SCOPE_UNKNOWN`
—— **没有 `TEAM_PLAN_NOT_FOUND` 这个键**。取到 `undefined`，而 `JSON.stringify`
**把 undefined 的字段整个丢掉** ⇒ 404 里**根本没有 `code`**。

> 一个「404 里带着 `code: 'TEAM_PLAN_NOT_FOUND'`，装配器照着它翻成"有原因的 missing"」的印象，
> 与一个「那个对象上从来没有这个键，于是这一格是**空的**」的事实，
> 在我把 `CONTEXT_PLAN_ERRORS` 的键逐个列出来之前是同一个东西。

★★★ **这个错法特别像对的**：`PLAN_NOT_FOUND` 的**值**恰好就是 `'TEAM_PLAN_NOT_FOUND'`
—— 写出来的那一行**读起来完全正确**。⇒ **值当键用**是一种"看起来对、取出来是 `undefined`、
而且被 `JSON.stringify` 静默吞掉"的错法。

★ 影响面正好是这一族存在的理由：`sources-loader.mjs` 要把 404 翻成 `null` + 带原因的
`missing` 候选，而**机器可判的那一格不见了**。

**修法**：`code: CONTEXT_PLAN_ERRORS.PLAN_NOT_FOUND`（值不变，走对的键）。
★ 现在 404 的 `code` 是 `'TEAM_PLAN_NOT_FOUND'` —— **响应与原来"打算发的"完全一致**。

## 三、★★★★★ 修完之后，"钉住"要**翻面**，而且翻面时会踩到一个坑

两条缺陷原来各有一条**钉住缺陷**的判据（钉的是"错的行为"）。修完它们必须翻面。

### 坑：反例抄在同一段注释里，被自己的"不许退回去"断言命中

我给修复配了反向断言，例如：

```js
assert.ok(!/CONTEXT_PLAN_ERRORS\.TEAM_PLAN_NOT_FOUND\b/.test(src), '不许退回把值当键用')
```

★★★ 它**当场报红** —— 因为我在**同一段注释里**把旧写法当**反例**抄了一遍（那正是给下一个人看的）。
那条断言扫的是**整个文件**，于是它命中的是**我自己的注释**。

> 一个「我加了一条"不许退回去"的断言，它会守住这个修复」的印象，
> 与一个「那条断言扫的是**整个文件**，而我**在同一段里把旧写法抄了一遍**，
> 于是它守的是我自己的注释」的事实，
> 在它在我刚写好的修复上报红之前是同一个东西。

**修法**：判之前**先剥掉注释**（去 `/* */` 与整行 `//`），再跑正/反向断言。
★ 这是「**文档里越诚实地写出旧写法，这类断言越容易误报**」——
所以"扫整个文件"的源码断言**必须**先剥注释。
