# PRT-316 切片 6：第六族（secrets）—— 第一次搬**前缀**路由，两个洞同时露出来

> 业主 2026-09-20 裁决：「乙：按一片一次对拍开工」，照 `PRT-315` 先例逐片提取。
> 硬约束（`spec :1282`）：**每片能独立对拍与回滚**。
> 切片 1 = `db8e2cc`；2 = `3aec3cd`；3 = `993853a`；4 = `fd668ff`；5 = `045e57f`。

## 0. 这一片的真正产出：前五族**没有**、也不可能暴露的两个洞

前五族有一个共同点：**全是等值路由**（`path === '…'`）。于是有两个维度
在它们身上**根本不存在**，而这个不存在被读了五次"全绿"：

| 维度 | 前五族 | 本族 |
| --- | --- | --- |
| **匹配方式** | 只有 `===` | `===` / `startsWith` / `startsWith + endsWith` 三种 |
| **从 URL 取参数** | 不取（参数全在 query / body） | `path.slice('/api/secrets/'.length, …)` |

本片一搬这两条，前五片里两个**隐性的洞**立刻变成可观测的失败。

## 1. ★★ 洞一：`ctx` 成员被"登记成可用"，却**没有真的绑定**

生成器有一个自由标识符核对：函数体里出现的名字，必须在
「注入项 ∪ 局部绑定 ∪ 内置 ∪ 结构性」里，否则生成期直接失败。

`path` 与 `url` 都被登记成"结构性"，**理由是**：

> 把它们登记下来是**断言**：`router.dispatch` 必须把 `{ path, url }` 传进 ctx，
> 否则本族里用到 `url.searchParams` 的那几条会在运行时抛错。

而生成器**实际发出去的包装签名只解构了 `url`**：

```js
async run(req, res, { url }) { … }      // ← path 不在里面
```

于是凡是用 `path` 的体：名字核对说"它是结构性的、通过"，运行时 `path` 是 `undefined`。
本族的 rotate / delete 正是 `path.slice(...)` ⇒ 直接 `Cannot read properties of undefined`。

> 一个"把名字登记成可用"的白名单，与一个"真的把它绑进来"的解构，
> 在没人用那个名字的时候是同一个东西。

**修法不是加一个名字，而是改掉判据的形状**：逐条算出"这一条的体真的用了 ctx 的哪些成员"，
按需解构（体里一个都不用就不发空解构）。生成日志现在会逐条打印绑定结果：

```
✔ ctx 绑定逐条核算：GET /api/secrets/status→{—}; …; POST /api/secrets/→{path}; DELETE /api/secrets/→{path}
```

## 2. ★★ 洞二：段首注释里的**理由**被前几片丢掉了（本次回补）

生成器原来把每个族的段首注释替换成一行 `// ── … —— 已提取到 ./routes/x.mjs ──`。
而段首注释装的通常不是"这段代码做什么"，而是**为什么这么做**。

用一条与对拍无关的判据扫（"源头段首注释里 >30 字的那几行，在搬过去的模块里还在吗"）：

| 族 | 段首说明 | 模块里缺失 |
| --- | --- | --- |
| chat | 1 行 | **1 行** |
| calendar | 3 行 | **3 行** |
| compaction | （源头本来没有） | — |

`// P2-5：+ 更新（局部）/ 冲突检测（只读提示，不阻断）/ …` 与 chat 的那一行，
**在仓库别处都搜不到**，只在 git 历史里。

> 一个"搬走了代码、留下了指针"的提取，与一个"搬走了理由、留下了结论"的提取，
> 在用例全绿、对拍逐字节相同的时候是同一个东西。

★ 对拍为什么没发现：它比的是**函数体**，而理由从来不在函数体里。

**两处修**：① 生成器从此**逐字搬走**段首说明（并在生成期核对"每行都出现在产物里"）；
② chat / calendar 的历史欠账本次回补（差异**只有注释行**，`git diff` 逐行确认过）。

## 3. 判据一：逐字对拍（六族）—— 全绿

六族 ① 逐条对应（方法 / 匹配方式 / 顺序）、② 体逐行按位置相同、③ 取族口径残留 0、
⑤ **独立口径**残留 0；`router.dispatch` 调用点恰好 **6** 处；`handle` 里剩余 **152** 条。

新增判据 ④ 的装配核对覆盖本族 4 个注入项；另加一条**跨族遮蔽**检查
（本片是第一次出现"共享 dispatch 点上，一条前缀路由可能被原文在它**后面**的族抢走"）：

| 请求 | 原文序胜者 | 族序胜者 | 结论 |
| --- | --- | --- | --- |
| `POST /api/secrets/<ref>/rotate` | `/api/secrets/` | `[secrets] /api/secrets/` | ✔ 同 |
| `DELETE /api/secrets/<ref>` | `/api/secrets/` | `[secrets] /api/secrets/` | ✔ 同 |

⇒ **没有跨族遮蔽**。这条检查留作后续每片的前置核对（前缀族会越来越多）。

### 3.1 ★★ 这道检查第一次跑出一个**假发现**，而假的原因在检查自己身上

接线**之后**再跑它，输出变成了 `★ 2 处会改判`：

```
★ POST /api/secrets/some-ref/rotate
    原文序胜者: （无）          ← 基线是空的
    族序胜者:   [secrets] /api/secrets/
```

`（无）` 是全部线索：那时 secrets 已经搬走，**当前** `server.mjs` 里不再有任何
`/api/secrets` 条件，于是"原文序"这一侧被算成了**空集**。
一个空基线拿去和一个有内容的表比较，结论必然是"不一致"。

> 一个"基线被清空"的对照，与一个"真的发生了遮蔽"的对照，
> 输出的都是"两边不一致"。

**修法**：基线固定取 **PRT-316 第一片（切片 1）的父提交** `db8e2cc^`——
那是六族都还在原处的状态；并加一条**基线自检**：若某条前缀路由在基线里
一条条件都找不到，就直接抛错，而不是继续比较。

修正后：基线 **188** 条条件，两条前缀路由都能在基线里找到，结论仍是 **没有跨族遮蔽**。

★ 顺带得到一个**独立的一致性旁证**：六族已搬走 **36** 条 + `handle` 里剩余 **152** 条
= **188**，与平台契约基线里的 `httpRoutes` **188** 条**恰好相等**。
（基线里那 188 条是"整个 hub 声明了哪些端点"，而 PRT-316 开工前它们**全部**住在
`handle()` 里——两套独立计数对上了，说明"152 条剩余"这个数不是估的。）

### 4.1 K2：一个"前缀 + 后缀"的匹配，与一个"只有前缀"的匹配

既有 15 例只打过 `POST /api/secrets//rotate`（空 ref）与 `DELETE`，
从没打过一个"**前缀对、后缀不对**"的路径。于是丢掉 `endsWith` 之后，
`POST /api/secrets/<任意东西>` 会被当成一次轮换请求，而**没有任何用例说过这件事**。

> 一个"前缀 + 后缀"的匹配，与一个"只有前缀"的匹配，
> 在用例只喂过**后缀刚好正确**的那些输入时是同一个东西。

★ 这一类洞只有在**第一次出现前缀路由**时才有机会露出来——前五族"全等值"，
"匹配方式"这一维在它们身上不存在。

### 4.2 K6 / K8 / K10：三条漏网是**同一个根因**，而且不在被搬的代码里

运行中的 hub 里 `secretAdmin()` 是**懒构造、且没有注入点**的
（`server.mjs` 写死 `createHubSecretAdmin({ env: process.env })`），
所以 CI 上它一定打不开 ⇒ 三条**写**路由一律回 503
⇒ "删除该调 `remove` 还是 `list`"、"响应里有没有夹带明文"在 **HTTP 面**上**不可观测**。

> 一个"写路径全都 503"的环境，与一个"写路径的语义都正确"的实现，
> 在只看状态码的用例上是同一个东西。

**处置**：判据改打在**缝**上——直接构造 `createSecretsRoutes` 并注入**计数桩**
（与切片 4/5 同一手法，缝以下不需要真实密钥库）。补了 6 条注入桩契约后 11/11。

★ 过程中两次自我纠正：
1. 我第一版把 `/api/secrets/rotate` 列进"必须 404"的越界样本里 —— **它错了**：
   前缀与后缀都命中、切出的 ref 恰好是空串 ⇒ 400 MISSING_PARAM，这是**合法匹配**。
   > *一个"看起来像后缀本身"的路径，与一个"前缀加一个空 ref"的路径，
   > 在字符串上是同一个东西* —— 只有真跑一遍才知道它归谁。
2. `handleRun` 桩一开始不写响应，于是 `sent` 是空的，
   而"响应里没有明文"在空响应上**恒真**——那正是要防的假绿。
   > *一个"没观测到"，与一个"观测到没有"，在断言上是同一个 `false`*。

### 4.3 顺手记录一处**既有不对称**（本片不改，只钉住）

| 路由 | 多段 ref（`a/b`） |
| --- | --- |
| `POST /api/secrets/a/b/rotate` | **被认领**（没有 `includes('/')` 判据） |
| `DELETE /api/secrets/a/b` | **400** `BAD_ID_ENCODING` |

这是搬运**之前**就有的差异。本片只搬路由、不改语义，所以把它钉成契约；
否则下一个人会把"删除会拒多段"顺手推广到轮换，或者反过来，而两者都是行为变更。
