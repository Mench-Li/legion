## 1. ★★ 通用探测脚本自己的两个缺陷

把上一片的临时探测脚本泛化成 `probe-family.mjs`（给族名自动定位区间）之后，
它连报两件假事：

**(a)** 对**每一族**都报"（首行没有…条路由这种自称，无法交叉核对）"。
原因：段首第一行通常是 `// ── F-20 能力包安装事实 ──` 这种**分段标题**，
"四条路由，围绕着…"在第二行。而我只看了 `sect[0]`。

> 一个"核对器自己没找到"与一个"原文根本没自称"，
> 在没有交叉核对输出的时候是同一行字。

**(b)** 注入清单里**没有 `db`**。因为 `db` 是以 `db,` 这种"裸传"形式出现的
（既不调用也不取成员），而我只扫 `name.` 与 `name(`。

> 一个"漏报一个依赖"的扫描器，与一个"这一族真的不用它"的扫描器，
> 在输出上是同一个空行。

★ (b) 与切片 8 生成器那个 `...foo` 缺陷是**同一条**：
"按前后字符判断这是不是一个独立引用"的判据，只在遇到它被设计时想到的那种写法时才对。
修法也同一条：先把字面量抹掉，再同时认 `name.`／`name(`／**裸标识符**。

## 3. ★★★ 我判错了两次，两次都不是产品的错

### 3.1 第一次：同一行代码出现**两次**，我拿其中一次的等价性去解释了另一次

破验第一轮 8 咬住 / 6 漏网。我读完 store 就宣布 K8（`packId` 的规整）是**可证等价**：
store 里是

```
if (packId !== null && packId !== undefined && String(packId).trim() !== '')
```

⇒ 空串与 `null` 都**不进** WHERE 子句。看起来严密。**但是错的。**

那个表达式在路由里出现**两次**，而两次的下游完全不同：

| 位置 | 用途 | `''` 与 `null` 等价吗 |
| --- | --- | --- |
| 响应体里的 `packId` | **回显** | **不等价**（两个不同的值） |
| 传给 store 的 `packId` | 查账 | 等价（store 自己会规整） |

K8 的变异打的正是**回显**那一处。我是拿**另一次**的证明去回答它。

> 同一个表达式出现两次时，"我证明了它等价"这句话是**不完整的** ——
> 它必须说清是**哪一次**。不说的那一次，读者会替你选一个。

⇒ K8 改判为**真缺口**，补一条判据（回显必须是 `null`、且回显不是"永远 null"、
且**钉住"路由传给 store 的是原始值"这个真实契约**）。

> 一个"我读懂了这行代码"的判断，与一个"我知道这行代码**这一次**在做什么"的判断，
> 在只看这一行的时候是同一个东西。

### 3.2 第二次：两条断言描述的是**我以为的代码**，不是代码

**第一处**：我顺手写了 `assert.equal(args.packId, null)`（空 `packId` 应折成 null）。
实测 `''`。原因正是 3.1：L117 传的是**原始**值。
⇒ 删掉这条错判据，换成一个**记录**该契约的断言（并说明它安全的前提是 store 会规整）。

**第二处**：我断言 `?limit=-3` 应当折成 `null`。实测 **-3**。
原因：`optionalIntParam` 只要求"安全整数"，`-3` 是安全整数 ⇒ 原样下传；
真正忽略它的是 store 里的 `limit > 0`。

> 一条照着"我脑子里那个实现"写出来的断言，
> 与一条照着真实实现写出来的断言，在**它通过**的时候是同一个东西。

⇒ 改为断言**真值**（`-3` 原样下传）+ **钉住** store 的 `limit > 0` 兜底。
这也是既有的**不对称**之一（`scope` 用 `length > 0`、`enabled` 不判），
本片只把它记成契约，**不顺手改行为**（零改写是纪律）。

## 4. ★★ 新观察：替身能让"HTTP 面上等价"的变异被咬住

K9（`sinceSeq` 的 `?? 0` 被去掉）在 **HTTP 边界上确实是等价**：
store 里 `Number.isInteger(sinceSeq) && sinceSeq >= 0 ? sinceSeq : 0`
⇒ `null` 与 `0` 落到同一个 SQL 参数。但它**仍然被咬住了** ——
因为新加的缝上契约用**记录实参的替身**验这一层，而替身看得到真 store 会抹平的那个差别。

> 一个用替身验"传下去的实参"的判据，能看见真 HTTP 面**看不见**的差别。
> 所以"咬住"回答的是"这套用例分不分得清"，**不是**"产品行为变了没有"。

这条与切片 8 的"没咬住有三种"是**对偶**的：那一片说明"没咬住"不等于"漏网"，
这一片说明"咬住"也不等于"行为变了"。两次都要求报告里写清**分类**。
