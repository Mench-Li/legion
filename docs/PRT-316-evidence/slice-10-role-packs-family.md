## 0. 选族

`role-packs`（冻结的岗位包）3 条路由、跨度 69 行、**无夹入他族**，
有整套**真 HTTP** 判据（`role-pack-http.test.mjs`，10 例，多条 ★★★：
同版本换内容 409、同版本同内容 200 且 `created:false`、坏事实一条都不落盘）。
段首说明自称「三条路由」而实测 3 条 —— **一致**，与 `packs` 同为反面控制。

★ 它是**第一个带连字符的族名**，而这一片的主要产出正是那两个因此暴露的脚本缺陷。

## 1. ★★ 生成器：`role-packs` → `createRole-packsRoutes`（一个语法非法的标识符）

工厂名的推导原来是：

```
create${name[0].toUpperCase()}${name.slice(1)}Routes
```

对**前九族**（`rules` / `permissions` / `chat` / `calendar` / `compaction` /
`secrets` / `automation` / `experience` / `packs`）**全部正确** —— 因为它们都是**单个词**。
第一次遇到 `role-packs`，它吐出 `createRole-packsRoutes`：一个**语法上就非法**的标识符。

> 一条"把首字母大写"的规则，与一条"把族名转成驼峰"的规则，
> 在每一个族名都是单个词的时候是同一个东西。

★ 这与切片 8 的 `...foo`、切片 9 的 `db,` 是**同一族**：
判据只在"它被设计时想到的那种输入"上被验证过，而前九个输入恰好都在那个范围里。
**三个假象、三个不同位置、一个机制。**

修法：`camel()` 做连字符→驼峰，并**额外断言**生成的工厂名是合法标识符
（把"变成非法标识符"从一次诡异的语法错误变成一次明确的失败）。

## 2. ★★ 接线脚本：那个断言**抓住了它**

`wire-family.mjs` 里有一句：

```
if (factory !== exportName) throw new Error(`工厂名不一致：${factory} vs ${exportName}`)
```

它当场报 `createRole-packsRoutes vs createRolePacksRoutes` 并**拒绝接线**。

这句断言当初写下来只是"顺手对一下参数"，而它这次恰好是唯一挡住
"把非法名字写进 `server.mjs`"的东西 —— 如果当时图省事直接用了传进来的
`exportName`，那这一片会以一次**静默的半接线**收场。

> 一条"顺手核对两个来源是否一致"的断言，
> 与一条"我们靠它挡住错误接线"的断言，在它**从来不触发**的时候是同一个东西。

修法：两边用**同一条** `camel()` 推导（各写一份是刻意的 —— 那句断言就是为了让
"两份推导不一致"变成一次响亮的失败，而不是一次安静的错接线）。

## 3. ★★ 遮蔽检查：同一个缺陷的**反方向**

修好生成器、接线成功之后，`check-shadowing.mjs` 直接崩：

```
ENOENT: no such file or directory, open 'team-hub\routes\rolepacks.mjs'
```

它把工厂名**逆推**回文件路径（`createRolePacksRoutes` → `rolepacks.mjs`）。
反向同样不可逆：`rolepacks.mjs` 与 `role-packs.mjs` 都可能是对的。

> 一个"把驼峰拆回连字符"的推导，与原文里那个**字面量**路径，
> 在每一族都是单个词的时候是同一个东西。

**修法（比打补丁更根本）**：不再推，改成从 `server.mjs` 的 **import 语句**里取
**字面量**路径 —— 那才是权威，而且顺带把"接线了但没 import"也变成一次响亮的失败。
升级后的检查仍然报 `✔ 没有跨族遮蔽`，并打印 10 族 55 条路由。

★ 同一个"名字与文件名的映射"缺陷，在**两个方向**各坏一次（生成端吐出非法名、
检查端推出不存在的路径）。两次都不是产品的错。

## 5. 判据二（破验）：16 条 → 15 咬住 / 0 真缺口 / 1 可证等价

第一轮 13 咬住 / 3 漏网，查完后：

| 类 | 条数 | 明细 |
| --- | --- | --- |
| ① **真缺口** | 2 | K5 空白 `scope`、K10 `?limit=` —— 补判据后咬住 |
| ② **可证等价** | 1 | K6 `frozenBy` 的 `?? null` |

**K5（空白 `scope`）**：用例有 3 处 `scope=`，但**没有一处是空白** ⇒"规整"整个没被验过。
★ 真行为差异：`scope: '   '` 会把这一版冻进字面量 `'   '` 空间，之后按正常 scope
查不回来 —— **冻结没丢，但读不回来，而账看起来完全正常**。（与切片 8 的 K10 同一条。）

**K10（`?limit=`）**：整份用例**一次都没用过**这个参数。
★ 这是**连续第二族**出现同一个缺口（切片 9 的 `packs` K11 也是它）——
两族的 `limit` 都接了线、都从没被测过。

> 一个"接了线但从没被喂过"的参数，与一个"根本不存在"的参数，
> 在用例的眼里是同一个东西。

**K6 的等价证明**：store 里是

```
input.frozenBy === undefined || input.frozenBy === null ? null : String(input.frozenBy)
```

⇒ 路由端给 `null` 还是 `undefined`，到 SQL 都是 `null`。处置同前两片：
**不写"实参必须是什么"**，而是**钉住 store 那处兜底**（它一变就红）。
