## 一、选族

## 二、★★★ 本族的两个"第一次"，都命中搬运工具的结构性假定

### 2.1 第一次被**内部子分隔符**切成两段

```
// ── F-15 用量汇总 ────────────────   ← 族的分隔符
if (… '/api/usage/totals') { … }
if (… '/api/usage/rollup') { … }
// ── F-15 告警与降级（第 23 轮）────   ← **第二个**分隔符，还在族内
if (… '/api/usage/alert')  { … }
```

接线脚本原来的区间算法是"从本族第一条路由往上找到第一个 `// ──`，
从最后一条往下**遇到第一个 `// ──` 就停**"。对前十三族这是对的 —— 它们都是一个分隔符一族的。

> 一个"族是一整段"的假定，与一个"族可以被子分隔符切成几段"的事实，
> 在这一族恰好没有子分隔符的时候是同一个东西。

**它是响亮的**：产物里会有 3 条而区间只装得下 2 条，守卫报"边界抓错了"。
拦住的是"我没搬完"，不是"我会搬错" —— 这个区别重要，因为前者会红，后者会绿。

修法：区间按**族**算（本族所有路由的最小起点到最大终点），
终点不在路由的**体中间**停（先求最后一条路由体的收尾 `}`），
并断言"本族路由之间不许夹别的族的条件行"。

### 2.2 第一次有**不止一段**说明

`usage` 的第一段说明 6 行（"两条只读路由…"），第二段 **25 行**，
是那段 ★★★ 推理：**为什么本接口故意不去读模型绑定里的 `perRunBudget`**。

生成器"段首说明一起搬走"的能力是**切片 6** 才加的，而它取的是：

```
const sect = sectionCommentOf(routes[0].srcLine)   // ← 只取**第一条路由之上**那一块
```

⇒ 第二段说明**不在模块里**，而接线脚本会把整个区间**删掉**
⇒ 那 25 行推理**只留在 git 历史里**。

> 一次"族只有一段说明"的搬运，与一次"族可以有好几段说明"的搬运，
> 在前十三族都只有一段的时候是同一个东西。

这与切片 6 是**同一条**，只是深了一层：那一次是"说明与代码分家"，
这一次是"**说明不止一份**，而搬运只认第一份"。

## 三、★★★ 于是加了一件新判据 —— 它立刻翻出前六片的问题

逐字对拍只比**路由的体**。一族里凡是**不属于任何一条路由的体**的东西 ——
段首说明、**子段说明**（上面那 25 行）、族级分隔符 —— 对拍**全都够不着**，
而搬运会把它们全删掉。

> 一条"路由体逐字相同"的判据，与一条"原件一行都没丢"的判据，
> 在原件里除了路由体没有别的东西的时候是同一个东西。

新判据 `.worktrees/_prt-handoff/check-region-lines.mjs`：
用与接线脚本**同一套**区间算法（刻意各写一份，两边不一致时要响）算出"会被删掉的区间"，
逐行取出来，去掉缩进后每一非空行都必须在产物模块里**找得到**。

先排除两类**故意**不在产物里的行（否则判据会把"缝的设计"报成"丢行"）：
路由**条件行**（在产物里变成 `method:`/`match:`/`path:` 三条）、
每条路由体**末尾那个 `return`**（产物里由 `dispatch` 返回 true + 调用点 `return` 承担）。

**结果**：

| secrets | 118 | 48 | 0 | 0 |

★★★ 两条结论：

1. **切片 8～13 各自丢了注释行**：experience **11**、tool-calls **10**、
   model-profiles **7**、connectors **4** —— 共 **32** 行。
   其中 model-profiles 那 7 行正是**我自己上一片**丢的（那段"probe 的位置必须在
   那批 `startsWith` 之前，否则 `/p1/probe` 会被当成 id 为 `p1/probe` 去查"的推理）。
2. **代码行十四族全部零丢失** —— 逐字对拍确实守住了它守的那部分。

切片 1～5（chat 3、compaction 10）属于**另一个**原因：那时生成器还没有搬注释的能力
（切片 6 才加的）。判据把它们标成"已知偏差"，不混进本片。

★ 这两个问题的**修复**（把那 32 行逐字补回各自的模块，纯追加、零行为变化）
属于**另一片**，不在本片夹带 —— 本片只把它**量出来**。
（*一个"我知道有东西丢了"的印象，与一个"东西真的没丢"的状态，
在没有逐行判据的时候是同一个东西。*）
