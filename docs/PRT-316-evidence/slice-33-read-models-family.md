## 5. ★★★ 两个检查器有同一个盲点：参数位上的**数组解构**

生成期核对报：

```
✖ 有未登记的名字（要么加进 deps，要么它是本体内局部绑定）：
    list  ← /api/missions
```

`list` 来自 `.map(([role, list]) => {` —— 它是**箭头函数的解构参数**，实实在在是局部绑定。

★ 两处**独立**的检查器都漏了它：

1. `gen-family.mjs` 的 `localsOf()`：它**早就**处理了 `const/let/var` 那侧的解构
   （`const { a } = …`），但**参数**那侧只做裸标识符切分 ⇒ `'[role'` / `'list]'` 都过不了正则。
2. `check-free-identifiers.mjs` 的 `declared()`：它处理了参数里的**对象**解构（`{ url }`），
   也处理了 `const` 那侧的解构，**同样**漏了参数里的**数组**解构。

> 一个"两份独立实现互相校验"的设计，与一个"两份是**从同一个想法里长出来的**、
> 于是有同一个盲点"的事实，在它们从来没被第三种输入逼过的时候是同一个东西。

★ 修的时候还**再错一次**：第一版把数组解构的扫描写进了"按逗号切之后的碎片"那一层，
而 `[role, list]` 的**方括号正好被逗号劈成两半**，两边都不构成 `[…]`，一个都没认出来（读数仍是 1）。

> 一个"里面有 `[…]` 就去找 `[…]`"的扫描，与一个"那对括号早被上一层按逗号劈开了"的事实，
> 在我没有把扫描放在**劈之前**那一层的时候是同一个东西。

修完：**31 个模块，未绑定名字合计 0** ✓

★ **同一件事（"解构"）在三处被想到过两次、漏掉一次** —— 声明侧想到了，参数侧想到了对象、漏了数组。

```js
const role = t.role ?? t.soldier ?? 'unassigned'
```

> 一个"我给的只是个无关的标记字段"的印象，与一个"那个字段**正是**分组键的回退来源"的事实，
> 在我没有把回退链读全的时候是同一个东西。

⇒ 补了 ⑲d 把这条**三层**链钉住（`role` → `soldier` → `unassigned`）。

实际是 `['from-task','from-member']` —— 两段 SQL **各自有序、拼起来不保证有序**。
（这处不对称本片**不修**，只把真实读数钉住。）
