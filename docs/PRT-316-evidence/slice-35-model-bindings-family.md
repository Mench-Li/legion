# PRT-316 切片 35：第三十三族 = 岗位模型绑定与 fallback（3 条）

> 上一片（34）的结论是「**有没有人在看**」。这一片反过来：
> 这一族**有两套判据、33 个请求点**守着 —— 于是问题变成了「**看的是不是这些**」。

## 1. ★★★ 这一族是**切片 23 留下的那条账**，而它要的两样东西后来都做出来了

`gen-family.mjs` 里**本来就有**一个 `model-bindings` 条目，写于切片 23，带着一个 `blocked:`：

```
deps: ['bindingStore'],
blocked: '前缀跨两个作用域（3 条在块外 + 2 条在块内），需拆族或加"显式路径集"能力',
```

它旁边的注释把结论写得比我今天重新量的还清楚：

> 前缀 `/api/model-bindings/` 会捞到 **5 条**路由、横跨**两个作用域** ——
> 3 条扁平的（`/api/model-bindings` GET+POST、`/api/model-bindings/resolve` GET）在块**外面**，
> 2 条在块**里面**。生成器当场**拒了**（✔ fail closed）。
> ⇒ 它要么**拆成两族**、要么给接缝加"显式路径集"，那是一件**独立的**事。

**那两样东西后来都做出来了**：切片 31 立了「显式路径集」（`F.paths`，为 `run-budget` 立的），
而"拆族"从头到尾就是一个可选项。本片只是把这条账**结掉** ——
用 `F.paths` 取扁平那 3 条（见 §2），块内那 2 条改名 `model-bindings-by-path` 留在原地等下一片。

> *一个「这条 `blocked` 是环境问题、要等外部条件」的印象，
> 与一个「它要的两样东西**后来都做出来了**、只是没人回来把它结掉」的事实，
> 在我没有去认领**自己留下的那条账**的时候是同一个东西。*

## 2. ★★ 为什么必须用「显式路径集」而不是前缀

前缀 `/api/model-bindings` 会**同时**圈住块内那两条（`GET`/`DELETE /api/model-bindings/<scope>/<role>`）——
它们是另一个作用域的形状，取进来就会把 `parts()` 那个共享局部一并拖走。
而块内那两条与本族**在源文件里本来就是分开的**，中间还夹着 model-migration 的接缝：

```
L5522-5529  段首说明（岗位模型绑定与 fallback）
L5530-5573  本族 3 条（扁平）          ← 本片搬这段
L5574-5576  ── model-migration 的接缝 ──
L5577-5610  块内 2 条（<scope>/<role>） ← 下一片
```

★★ 顺带一条**顺序即契约**：`/api/model-bindings/resolve` 同时满足块内那条前缀
（`'/api/model-bindings/resolve'.startsWith('/api/model-bindings/')` 为真）。
两族一前一后装配，本族的 dispatch **必须**排在 `model-bindings-by-path` 前面，
否则 `/resolve` 会被后者抢走、报成"路径段数不对"。

## 3. ★★★ 生成期**第一次**拿到「区间内没有接缝」的正面证据

D 段断言的原话：

✔ 反向自检：路径表 3 条**全部命中**，且 (方法, 路径) 两两不同

前 32 片里，这条断言一直是**否定式**的（"区间里没有别人的条件"）。
本片是第一次它**同时**证明了"没有接缝" —— 因为 `paths` 是我一条条点名的，
区间是被**构造**出来的，不是被前缀**圈**出来的。

## 6. M7 / M8 是**可证等价**，不是缺口

路由里这两个默认值与**仓储自己的**默认值重复。`team-hub/binding-store.mjs` 的 `upsert`：

```
L163  const fallbacks = input.fallbackProfiles ?? []
L168  const budget = validatePerRunBudget(input.perRunBudget ?? null)
```

路由把 `undefined` 递下去之后，仓储**照同一套规则**补成 `[]` / `null` ——
落库、回执、`*Unreadable` 三个读数全都一样。⇒ 去掉路由里那句是**不可观测**的。

这与切片 34 的 M29 同类。「没咬住」**有三种**：真缺口 / 可证等价 / 早就被别处守着。

## 7. ★★ 生成器报的「分段 1」是**错的** —— 这个簇里明明有一条接缝

`group-remaining.mjs` 把这一簇报成 `5 条 L5530-5609 80 行 外来 0 分段 1 ← 干净`。
实际上 L5576 就有一条 `router.dispatch`（model-migration 的接缝），

如果照它报的"分段 1"去做单片，就会把**别人的接缝**一起搬走 ——
而 D 段断言（"区间里不许有接缝"）会拦住（**守卫是对的，工具是错的**）。

1. 切片 31 前缀跨过接缝
2. 切片 32 路径跨过方法
3. 切片 33 `startsWith('/api/task')` 吞掉 `/api/task-feedback`
4. 切片 34 混合命名空间**没有共同前缀** + **CRLF 让提取器返回 `null`**
5. 切片 35 **分段计数**把"有接缝"报成"分段 1"

## 8. ★ `wire-family.mjs` 里有一处**与对拍同一个**换行敏感（已顺手加固）

`wire-family.mjs` 读模块的 `(方法, 路径)` 用的是：

```js
const mp = /^\s+path: '([^']+)',$/.exec(line)
```

—— 与切片 34 修掉的 `modulePathsOf` **同一个 `',$` 坑**。它的失效文案会是
「模块里读不出任何 (方法, 路径)」，**读起来像模块生成坏了**，其实只是 `\r`。
本片生成出来的模块是 LF（`gen-family` 硬编码 `eol = '\n'`），所以**这次没有发作**；
按切片 34 的教训**防御性地**先剥掉行尾 `\r`。
