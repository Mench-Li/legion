# PRT-316 切片 36：第三十四族 = 岗位模型绑定（按路径读/删，2 条）

> 这一片是**切片 23 留下的那条账的另外一半**。切片 35 结掉了"块外 3 条"，
> 本片结"块内 2 条" —— 而它一开工就把**生成器自己**的三处潜在缺陷全撞了出来。

## 1. 本族长什么样

```js
L5534  if (path.startsWith('/api/model-bindings/')) {        ← 块的 { 在**行尾**
L5535    const BINDING_PREFIX = '/api/model-bindings/'
L5536    const parts = () => {                               ← 共享局部
L5539      const raw = path.slice(BINDING_PREFIX.length)     ← 在 parts **体内**
L5540      const segs = raw.split('/')
L5541      if (segs.length !== 2) return null
L5543      return [decodeURIComponent(segs[0]), decodeURIComponent(segs[1])]
L5545      return 'BAD_ENCODING'
L5548    if (req.method === 'GET' && path.startsWith(...)) {   ← 路由 1
L5560    if (req.method === 'DELETE' && path.startsWith(...)) { ← 路由 2
L5567  }
```

★★ 两条路由都**不看**外层那层 `if`，却都**依赖**它声明的 `BINDING_PREFIX` 与 `parts()`。
所以搬这一族不只是"搬两条 if"，而是"**把包住它们的那一层块一起搬走**"。

## 2. ★★★ 三处潜在缺陷，一处修好才看得见下一处

本片开工时生成器报的是「有未登记的名字：`parts`」。顺着它往下挖，**连着挖出三层**：

### 2a. `blockOf` 只认「`{` 独占一行」的块 ⇒ 根本看不见这一族的块

切片 23 给这条目留下的备注写的是：

> 生成器的"块前言"机制（自动找包住本族的那个块）**正好吃**这种形状。

**那句是错的。** `blockOf` 的判据是 `t === '{'`，而这一族的块是 `if (...) {` ——
`{` 在行尾。于是它一路往上、撞到 L5533 那条更靠左的非 `{` 行，按"已经出了这一层"返回 `-1`。

> *一个「前言机制**正好吃**这种形状」的印象（写在备注里、从没跑过），
> 与一个「它只认 `{` 独占一行、这一族的块根本不会被认出来」的事实，
> 在我真正把这一族喂进去之前是同一个东西。*

修法：**加一个按族开的开关**（`F.inlineOpen`），开了才认行尾 `{`。
★ 为什么是开关而不是直接放宽 —— 见 §4。

### 2b. `proAllowed` 是**死代码**：算出来、打印出来，从没被用过

第 909 行 `const proAllowed = new Set(pro.declared)`，第 916 行把它打印成
「声明了共享局部：…」，然后**再没有任何地方读它**。
第 966 行的放行名单是 `['json', ...INJECT, ...allowedBase]` —— **没有 `proAllowed`**。

后果：前言声明的名字**永远**不在放行名单里，凡是「前言声明、路由体使用」的名字
一律被判成"未登记"。也就是说 —— **前言机制从立起来那天起就没接上**。

★★ 它的第一个（也是当时唯一的）用户 `model-profiles` **根本生成不出来**，
报的还是「有未登记的名字」，**读起来像"这一族少登记了依赖"**。

> *一个「前言机制早就有了、`proAllowed` 都算好了」的印象，
> 与一个「它算完就扔了、一行都没用上」的事实，
> 在我没有去数**那个变量到底被谁读过**的时候是同一个东西。*

★★★ 这一条直接解释了「9/32 族不可逐字节复现」里的一部分：
生成器对它们是**抛异常**的，而不是"生成得不一样" ——
两者在"复现性检查"的眼里都只是"不通过"。

### 2c. `declared` 把嵌套作用域**摊平**了 ⇒ 生成出来的文件语法都不过

修好 2b 之后，生成器往前走了一步，然后 `node --check` **响亮地**响了：

```
SyntaxError: Identifier 'segs' has already been declared
```

原因：`declared` 是一行一条正则扫过去的，**不看花括号深度**。
于是 `parts()` **体内**的 `raw` / `segs` 被当成了前言这一层的声明，
生成出来的工厂写了 `return { BINDING_PREFIX, parts, raw, segs }` ——
而 `raw`/`segs` 在那个作用域里根本不存在；同时路由体里又写着 `const segs = parts()`，与解构进来的 `segs` **重名**。

> *一个「前言声明了哪些名字」的问题，
> 与一个「前言里**嵌套函数体内**声明了哪些名字」的问题，
> 在那一层恰好没有嵌套的时候是同一个问题。*

修法：按花括号深度取，只看前言**自己那一层** ⇒ 名单变成 `BINDING_PREFIX, parts` ✓。

### 2d. 三层的关系

**在 2b 修好之前，生成器是停在更早一步（「`parts` 未登记」）的** ——
2c 那个语法错误**根本浮不出来**。修一层、露一层。

## 3. ★★★ `wire-family` 的**孤儿块**：计数守卫和 `node --check` 都看不见

上下界的规则不一样，而本族正好卡在中间。上扫从第一条路由（L5548）往上走，
会**穿过**前言、在 L5533 的 `router.dispatch`（model-migration 的接缝）上 `break` ——
于是区间从 **L5548** 开始，删完之后源文件里会剩下：

```js
if (path.startsWith('/api/model-bindings/')) {   ← 孤儿
  const BINDING_PREFIX = ...; const parts = ...
}                                                 ← 加上它自己这个 }
```

★★ 而且这**两道守卫都拦不住**：
- `nCond !== expected`：区间里仍然"恰好 2 条方法条件"，**对得上**；
- `node --check`：那是一段**没人用的死块**，语法完全合法。

> *一个「区间里方法条件的条数对得上」的判据，
> 与一个「区间**从错的地方开始**、把前言留成了孤儿块」的事实，
> 在那一族恰好没有块前言的时候是同一个东西。*

修法：给 `wire-family` 加显式开关（第 4 个参数 `block`），开了才向上找**块的起始行**并把上界提前。
实测：`区间上界由 L5553 提前到块首 L5539` ✓。默认路径对已有 33 族**一个字符都没变**。

## 6. ★★ 几处实测的边界（本片**不修**，只钉读数）

- **`/api/model-bindings/resolve/coder` ⇒ 404 `没有这个岗位绑定：resolve/coder`** ——
  它不是"`/resolve` 后面多了个段"，而是 `scope=resolve, role=coder`。
  两个族共享一个命名空间，**顺序即契约**：扁平族在前 ⇒ 精确的 `/resolve` 归它，
  `/resolve/<x>` 落到本族。有一条判据专守这个顺序。
- **GET 与 DELETE 的信封不同**：GET 回 `{ok, binding, serverTimeMs}`；
  DELETE 回 `{ok, scope, employeeRole, deleted}`（走 `handleRun`）。
- **坏编码与坏形状是两个码**：`BAD_ID_ENCODING` vs `MISSING_PARAM`（判据已钉）。
- **两段各自解码**：`/sc%20x/co%2Fder` ⇒ `['sc x', 'co/der']` ——
  role 里的 `%2F` 解成 `/` 而**不被**当成段分隔（这正是 `parts()` 里那句注释说的）。
