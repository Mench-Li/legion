## 二、★★★ 那两条"纪律"此前没有任何东西守着

### 纪律①：「任务不存在」与「这个任务没有反馈」是**两件事**

源码注释把理由写得很清楚：回 `{feedback: []}` 会让两者**在调用方那里长得一样**，
而装配器要靠 404 才能把它翻成 `null`、再由 `sources.mjs` 决定是不是致命。

- **M3**（把 404 改成 200 空数组）⇒ 既有判据**一个都没红**；
- **M4**（保持 404 但把 `code` 换掉）同理。

★ 本片钉住了两件事**分得开**：不存在 ⇒ `404 TASK_NOT_FOUND`；
存在但没反馈 ⇒ `200 {ok:true, count:0, feedback:[]}`。

### 纪律②：**跨空间越权读取**

任务 id 是全库唯一的，但**装配是按空间做的** —— 拿别空间的 id 来问仍是一次越权读取。

- **M5**（整条校验删掉）⇒ 漏网；
- **M6**（判定反过来，`!==` 改 `===`）⇒ 漏网；
- **M7**（删掉 `scopeParam.trim() !== ''` 那道闸，让空 `scope` 也去校验）⇒ 漏网。

★ 本片把三种情形都钉死了：`scope` 对得上 / 没给 / **给了空白** ⇒ 放行；
只有**给了且对不上**才 404，且**一个字节的 feedback 都不许漏**。

## 三、★ 顺手钉住的两处细节

- **`taskId` 判空用的是 `.trim() === ''`** ⇒ 全空白也算缺参数（M9 钉住）。
  而**查库前**同样要 `trim()`（M11 钉住），所以 `?taskId=%20trimme%20` 能查到。
- **坏 JSON ⇒ 空数组而不是 500**：`feedback` 列被写坏时 `parseJson(…, [])` 回落，
  回 `200 count:0`（不是崩，也不是 404 —— 因为"行在"与"列坏了"是两件事）。
- 心跳侧：`kind` 非字符串 ⇒ `unknown`；`model` 只有一半是字符串 ⇒ **仍然落库**、缺的补空串
  （M18/M19 钉住）；两个字段都不是字符串 ⇒ **不写** `model`。
