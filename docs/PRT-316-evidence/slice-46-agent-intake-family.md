## 四、★ 一处「看着能分辨、其实分辨不了」的用例

M24（`roles` 不再 `String()`）第一遍也没咬住。我的用例是 `roles: [1]` ——
但 `String(1)` 在目录里**查不到**，不 `String()` 在 SQLite 里同样**查不到**：
**两种写法都 `added: 0`**，分不开。

★ 真正分得开的是**数字形的 role**：role 正则是 `^[a-z0-9]...`，所以 `'123'` 是个**合法角色名**。
传数字 `123` 时 `String(123) === '123'` 命中；不 `String()` 则 SQLite 拿 INTEGER 去比 TEXT 列，
**匹配不上** ⇒ `added: 0`。

> 一个「我传了个数字，没报错，那这条就测到了」的印象，
> 与一个「两种写法在这组数据上给出**同一个**结果」的事实，
> 在我找到那个「数字与字符串长得一样」的角色名之前是同一个东西。

## 六、★ 本片唯一的 `prefix+suffix` 形状

`POST /api/spaces/:id/agents` 的匹配是

```js
if (req.method === 'POST' && path.startsWith('/api/spaces/') && path.endsWith('/agents'))
```

⇒ 生成器如实产出了 `match: 'prefix+suffix'` + `path: '/api/spaces/'` + `suffix: '/agents'`。
★ 判据钉住了**两端都得对上**：`/api/spaces/t/other`（后缀不对）与 `/api/other/t/agents`（前缀不对）
都**不许**命中，`/api/spaces/t/agents/`（多一个斜杠）也不许。
★ 空间 id 从**原始 path** 里切出来并 `decodeURIComponent`，切完还要过一遍 id 正则。

## 七、钉住的语义（21 例判据）

### `POST /api/agents`（PRT-402）

- `role` 匹配 `^[a-z0-9][a-z0-9-]{0,63}$`；`name` 非空白；**非法时一行都不落库**。
- roster 幂等 upsert，`sort` 从 0 递增，`avatar` 缺省 `🤖`、`kind` 缺省空串；审计 `agent:create`。
- ★★★ **没给边界内容 ⇒ 一份清单都不写**（`employeeManifest: null`，`employee_manifests` 里没有行）
  —— 写空清单等于给模型一条**假规则**。
- ★★★ 给了边界（任一字段非 `null`/`undefined`，`limits: {}` 也算）⇒ 写清单，
  回 `{role, version, created}`。
- ★★★ `employeeId` 缺省是 **`${scope}/${role}`**（岗位在空间里的**地址**，不是「某个人」）；
  显式传则照用；**全空白等于没给**。
- 边界的三个数组缺省 `[]`、`approvalPolicy` 缺省 `null`、`limits` 缺省 `{}`。

### `POST /api/spaces/:id/agents`（选人入编）

- 从**全局目录**按 role 复制 `name/kind/avatar` 进该空间。
- ★★★ **目录里没有的 role 静默跳过**，且**不计入 `added`**（不凭空造岗位）。
- ★★★ `roles` **去重 + `String()`**；数字形的 role 靠 `String()` 才对得上 TEXT 列。
- ★ 是**只增不减**（不像流水线那样删没提交的），`sort` 接着最大值排。
- 审计记在**目标空间**的 `space:add-agents` 上（不是来源空间）。
