## 一、★★★★★ 同一个魔数被追上**第二次** —— 这次把形状改对

`baseline-snapshot.mjs` 里的 `MIN_ROUTES` 是一道"抽取器是不是和源码脱节了"的护栏。

- **切片 45**：`server.mjs` 里剩下 **9** 条，撞上下限 10 ⇒ 报红。当时的处置是**降到 5**。
- **切片 49（本片）**：剩下 **4** 条，**又**撞上下限 5 ⇒ 报红。

★★★ 切片 45 的处置**重复了它自己刚诊断出的那个错误**：它写下"降到 5 仍然能抓住
抽取器彻底脱节（提取到 0 或个位数）"—— 可 `server.mjs` 里剩下的条数**正要走到 0**，
所以 5 只是把同一个问题往后推了四片。**任何正数下限都会被追上。**

> 一个「10 太高了，降到 5 就安全了」的印象，
> 与一个「它守护的那件事每成功一步，真实值就朝阈值走一步，所以**任何**正数都会被走到」的事实，
> 在我第二次撞上同一道红之前是同一个东西。

**改法（结构性，不是再降一次）**：不再用绝对条数当护栏。
真正该守的是"搬家的账要对得上" —— `snapshot()` 里 `httpRoutes` 是
**`extractRoutes(server.mjs)` ∪ 各族 `extractDeclaredRoutes`** 的并集，
`diffSnapshots` 拿它和基线比：

- 抽取器若脱节，`server.mjs` 那部分**塌**，并集就**少掉**那些路由，
  `listDiff` 会**逐条把名字列出来**（`- 路由: GET /api/activity` …）；
- 这道判据**不依赖任何魔数，剩下 0 条时照样成立**。

⇒ `MIN_ROUTES` 归 **0**（不再设绝对下限），并在 `snapshot()` 的并集处
逐字注明"这里才是护栏"。

★★ **同时**，仓库里那条盯着这个下限的用例（「路由数量崩到阈值以下必须抛错」）
**必然失效** —— 但我**没有把它删掉充数**：改成
① 验证**机制**仍在（显式 `extractRoutes(src, { min: 5 })` 照样抛）；
② 新增一条证明**接替它的判据**：把 server 侧塌成空，并集就少掉那一份。
⇒ 基线套件 **25 → 26** 例，26/26 绿。

## 二、★★★★★ 我自己的判据有一个正则漏洞，藏住了**五条**过期警告

切片 45 立的那道"兄弟警告不许过期"的判据，在切片 45/46/48 **都报"过期 0"**。

★★ 本片把它换个写法重跑，一次报出**五条**：

```
✖ L5364 过期：POST /api/spaces 已不在 server.mjs
✖ L5364 过期：POST /api/pipeline 已不在 server.mjs
✖ L5364 过期：POST /api/goal 已不在 server.mjs
✖ L5364 过期：POST /api/agents 已不在 server.mjs
✖ L5407 过期：GET /api/documents 已不在 server.mjs
```

**原因是我自己的正则**：

```js
// verify45/46/48 里用的（漏了一半）：
const WARN = /别顺手搬走）\s*[:：]\s*(.+)$/      // ← 要求一个右括号
// verify49 里改成：
const WARN = /别顺手搬走）?\s*[:：]\s*(.+)$/     // ← 括号可选
```

★ 源码里两种写法都有：`（别顺手搬走）：A` 和 `别顺手搬走：A, B, C`。
前者的正则**要求 `）`**，于是**整条 `别顺手搬走：…` 都被跳过**，三片都报"过期 0"。

> 一个「这道判据每一片都跑过、都报过期 0」的印象，
> 与一个「它的正则要求一个右括号，而五条警告里一条都没有那个括号」的事实，
> 在我把 `）` 改成 `）?` 的那一次之前是同一个东西。

★★★ 这与切片 47 的 `blank()` 内层反引号是**同一类**：
**判据自己的模式太窄，而"0 个问题"读起来像"全都查过了"。**
★ 差别是这次代价更大：**五条**警告已经过期好几片（`POST /api/spaces`/`pipeline`
是切片 45 搬的，`/api/agents` 是切片 46，`/api/goal` 是 40/48），
而**仓库里根本没有这道判据** —— 它只在助手区。

⇒ 两条警告整条删掉（它们列的路由**一条都不剩**了）。
★ 顺带把本片自己那**两条**点名 `may-switch-model` 的警告也删了
（一条在 `run-budget` 接缝 L5306、一条在 `runtime-verification` 接缝 L5317）
⇒ 警告从 6 条降到 **1 条**，过期 **0** 条。

## 四、★★★ 一个**不忠实的桩**，与一个被它掩盖的变异

破验 M18（把显式五字段投影换成 `return { ...d }`）**第一遍没咬住**。

> 一个「我断言了返回的键集合，所以多带字段会被抓住」的印象，

## 五、钉住的语义（12 例判据）

- ★★★★★ **缺价目表 ⇒ 409**（不是 400、不是 200），`ok:false`、`code:'PRICE_TABLE_GONE'`；
  ★ 文案要写明**被守住的那条规矩**（"不得在未获用户批准时自动切换到更昂贵模型"）
  和**拒绝的那条捷径**（"不能靠'查不清'来满足"）—— 否则下一个人只看到"缺张表"。
- ★★★ 缺表时**根本没走到域层**：若走到域层会是 400（域层自己抛），
  而 409 证明是**路由这一层**拦住的。
- ★★ 版本号缺失 / `null` / 数字都走同一条 409，且 `JSON.stringify` 如实写进文案。
- ★★★ 成功形状 = `handleRun` 包的 `{ok:true}` + **显式五个**字段
  （域层的 `message`/`reason` **不许**出现）。
- ★★★ `approved` 是**严格真值**：只有 `=== true` 才算批准（`'true'`/`1`/`'yes'` 都不算）。
- ★★★ 查表用的是 `body.priceTableVersion`；★ **拼错键名的表现是 409**（"缺表"），不是 400
  —— 排错时要认得出这个信号。
- ★★★ 409 那条路上**只能写一次响应**（`handleRun` 的 `headersSent` 那条）。
