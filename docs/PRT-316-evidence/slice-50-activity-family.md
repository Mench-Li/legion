## 一、★★★★★ 一条真缺陷：`limit=2.7` 把只读接口打成 **500**

```js
const limit = Math.min(Number(url.searchParams.get('limit') ?? 50) || 50, 500)
```

★ 这个算式**只夹了上界**。`limit=2.7` ⇒ 值是 **2.7**（没有取整）⇒ 原样绑定进
`LIMIT ?` ⇒ SQLite **抛错** ⇒ `handle()` 的兜底把它变成 **500**。

**影响面不止是"少给几条"：一个查询参数能把只读接口打成 500。**
只读接口本该"给什么参数都回 200"。

> 一个「`Math.min(x, 500)` 已经把 limit 夹在合理范围里了」的印象，
> 与一个「它夹的是**上界**，下界和整数性都没管，而 SQLite 会因此抛错」的事实，
> 在我把 `2.7` 真的发一次之前是同一个东西。

★ 已核对：本片**只搬路由**、体逐字节相同（对拍通过）⇒ **搬之前就有的**缺陷。
★ 记为第 **21** 条钉住未修的缺陷。★ 判据把它**钉住**（含"若算式被改成取整则说明已修"的反自检）。

★★ 顺带量出**两条**同源的性质，都不是"少给几条"那么轻：

| | 现象 | 为什么 |
| --- | --- | --- |
| `limit=0` | 拿到 **50** 条，不是 0 条 | `0 \|\| 50` 里 `0` 是 falsy |
| `limit=-5` | 拿到**全部** 60 条 | `Math.min(-5,500) = -5`，而 SQLite 的负 `LIMIT` 意思**不限制** |
| `limit=abc` | 回落到 50 | `NaN \|\| 50` |

★★★ 「我只要 5 条」变成「给我全部」这一条尤其值得记：
**一个"限制条数"的参数，可以被用来取消限制。**

## 二、★★★ 四个分支的**顺序就是语义**

```js
if (goalIdParam) { … } else if (taskIdParam) { … } else if (scopeParam) { … } else { … }
```

★ 换一下顺序，**同一条请求读到的是另一批行，却都返回 200**。
⇒ `goalId` 赢过 `taskId`、赢过 `scope`；`taskId` 赢过 `scope`。
★ 判据逐个钉住（`goalId&taskId` 两个都给、`goalId&taskId&scope` 三个都给、`taskId&scope`）。
★★ `verify50` 另外逐字核了这四个 `else if` 的**出现顺序**。

★ 还有一处**不对称**（照搬，非本片引入）：`goalId` / `scope` / 全量三条都带 `LIMIT`，
**`taskId` 那条没有** —— 于是 `?taskId=T&limit=5` 也返回该任务**全部**事件。
★ 三条分支是 `ORDER BY seq DESC`（新在前），`taskId` 那条是 `ORDER BY seq`（升序）。

★ `goalId` 分支还有**两半**：`goalId = ?` **或** `taskId ∈ (该目标下的任务)` ——
后半段是反查，判据用"目标链任务的事件也应出现"独立钉住。

## 三、★★★ 破验：两个**变异体本身**有毛病（不是判据漏了）

**(a) M5 是一个恒等变异。** 我第一版把 `… OR (taskId IN (SELECT …))` 改成
`… OR (taskId IN (SELECT …)) OR 0` —— 而 **`X OR 0` 恒等于 `X`**：
整个查询一字未变，破验报"没咬住"。

> 一个「我改了一句 SQL，所以这条判据该响」的印象，
> 与一个「我加的 `OR 0` 在布尔代数里是恒等元」的事实，
> 在我把那句 SQL 真的求值一次之前是同一个东西。

⇒ 改成把 `AND 0` 塞进**子查询**（`WHERE goalId = ? AND 0` 恒假）⇒ 反查那一半真的失效。

**(b) M7 是可证等价。** 删掉 `?? 50` 之后是 `Number(url.searchParams.get('limit'))`，
不给 limit 时 `get` 返回 **`null`**，`Number(null)` 是 **`0`** —— 后面那个 `|| 50` **照样接住**。

> 一个「`?? 50` 是那条默认值，删掉它默认值就没了」的印象，
> 与一个「`Number(null)` 恰好是 0、而 0 是 falsy，所以后一道 `|| 50` 会兜住」的事实，
> 在我把 `Number(null)` 求一次值之前是同一个东西。

★ 判据**补不出来**（没有行为可断言）。可记的事实是：**那两道默认值互相冗余**，
去掉任意一道都不改变行为 —— `verify50` 把这条算式逐字钉住了。
