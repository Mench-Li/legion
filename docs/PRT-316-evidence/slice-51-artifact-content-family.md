## 一、★★★★★ 那个最像它的套件，测的是**它下面那一层**

`artifact-content.test.mjs` 名字、路径、断言都对得上这一族。不给我方判据时破验报
**1 咬住 / 18 漏网** —— 其中最刺眼的是 `M4`：

> **把状态码写死 `200`**（于是「路径不在允许读取范围」的 **403 变成 200**）⇒ **全绿通过**。

我没有把这条"漏网"当成结论就写下去，而是**手工核了一遍**：

```
artifact-content.test.mjs
  走 HTTP 吗 = false
  import 的来源 = node:test , node:assert/strict , node:fs , node:os , node:path
  提到 '/api/artifact/content' = true
  提到 'artifactContent(' = true
── 未变异基线 ──   ✔ 绿
── 施加 M4（写死 200）──  ✖ 仍然绿 ⇒ 真的没咬住（没有判据覆盖）
```

★★★ 它 `import` 的是**域层函数** `artifactContent(`，**一次 HTTP 都不走**。
（另一个 `task-records-routes.test.mjs` 走 HTTP，但只提到这个路径、不断言状态码。）

> 一个「`artifact-content.test.mjs` 覆盖了 400/403/404 各种情形，所以这条路由的行为是被测住的」的印象，
> 与一个「那个套件 `import` 的是**域层函数**、一次 HTTP 都不走，所以它测的是**域层**，而路由那一层一个判据都没有」的事实，
> 在我把「状态码写死 200」投进去、它**全绿通过**之前是同一个东西。

★★★ 这是第 **23** 类失败：**判据测的是接缝\*\*下面\*\*那一层，而它的"绿"被读成了对接缝的覆盖。**
它是切片 44/47/48（有套件但不覆盖）的**镜像** —— 那些是「没测到这一层」，这个是「测的是**另一层**」。
★ 两者在破验里的读数**一模一样**（都报漏网），**只有手工打开那个文件才分得开**。

★ 这一条同时解释了我方判据为什么值钱：`M4` 在**19/19** 里是被咬住的。

## 二、★★★★★ 全量回归的**选择器**看不见我这一片的判据

写完判据我照例跑全量回归，读数是 **82 套件 / 1403 例** —— **与切片 50 一模一样**。

Get-ChildItem team-hub -Filter *.test.mjs | Where-Object { (Get-Content $_.FullName -Raw) -match 'server\.mjs' }

（`import { createArtifactContentRoutes } from './routes/artifact-content.mjs'`），
**一个字节都不提 `server.mjs`** ⇒ **被静默排除**。

**量出来的数**：`team-hub` 下共 **110** 个套件，旧选择器只选 **82** 个；
其中提到 `from './routes/'` 的有 **30** 个，而 **29 个**同时也走一遍 HTTP（所以还是提到了
`server.mjs`），**只有本片这一个**是纯桩 ⇒ 落空。

> 一个「全量回归 82 套件全绿 ⇒ 我这一片的判据也在这 82 里」的印象，
> 与一个「选择器的判据是"文件里出现 `server.mjs`"，而我这一片用的是**纯桩**、一个字节都不提它」的事实，
> 在套件数**从 82 变成 82**（而不是 83）的那一眼之前是同一个东西。

★★★ 发现它的**唯一线索就是计数没涨** —— 而这个计数**照样"健康"**：

## 二、★★★★★ 这一族的语义 = 「域层说什么就是什么」

```js
const result = artifactContent(url.searchParams.get('task') ?? '', url.searchParams.get('i') ?? undefined)
json(res, result.status, result.body)
```

状态码是**域层决定的**：400（缺参 / 无登记产物 / 序号越界 / 非 `file`）、
**403（路径不在允许读取范围内）**、404（取不到任务 / 文件不存在）、200（成功）。

⇒ 判据要钉的**不是**「返回 200」，而是**「路由一个字都不许改」**：
`json(res, result.status, result.body)` **逐字**、路由体里**没有** `try/catch`、
**一个写死的状态码都没有**（★ 最后那条是判据第 ⑪ 例，专门盯"友好化 403"这个入口）。

★★ `M9`（加 `try/catch` 把异常吞成 500）是**唯一**被既有套件咬住的一条 ——
说明既有覆盖里有一条是真的碰到路由层了；而其余 18 条的漏网**都属于 §一那类**。

★ 还有一条边界：域层返回 `status: undefined` 时，路由**照发 `undefined`**（第 ③ 例）——
"原样透传"意味着**路由不替域层兜底**。

## 三、★★★ 两个查询参数的缺省值**不对等**（且下游冗余）

| 写法 | `task` | `i` |
| --- | --- | --- |
| 全不给 | `''` | `undefined` |
| `?i=` | `''` | **`''`** |

★★ 而域层那边是 `rawI === undefined || rawI === null || rawI === ''` **三个一起判** ——
⇒ 这两种在**下游完全等价**。这个不对称是**冗余**的，不是缺陷。

> 一个「路由把 `i` 分成了 `undefined` 和 `''` 两种，域层大概会区别对待」的印象，
> 与一个「域层把 `undefined` / `null` / `''` 三个一起当"没给"」的事实，
> 在我把域层第一个判断读出来之前是同一个东西。

★ 与切片 50 的 `M7`（`?? 50` 与 `|| 50` 互相冗余）是**同一类可证等价**：
**两个看着像"两道保险"的地方，其实只有一道在起作用。**

★ 判据另外钉住：参数**原样**进域层（不 `trim`、不 `Number`、不去空）——
`?task=%20T%20&i=01` ⇒ `[' T ', '01']`。
