## 二、★★★★★ 为什么"按值搬"是**静默错误**（实测）

写了一个探针，把两种注入形态并排跑：

```
── 形态 A：按值注入（"零注入改写"唯一允许的形态）──
  装配那一刻的值 = 0
  之后账本真实值 = 3
  路由读到的值   = 0
  ✖ ★★★★★ 路由报的是一个冻结在装配时刻的值 —— 永久落后，且不报错、不变红

── 形态 B：thunk 注入（切片 19 的 precedent：live: () => ({ … })）──
  装配那一刻的值 = 0
  之后账本真实值 = 3
  路由读到的值   = 3
  ✔ 一致
```

> 一个「按值注入只是把那个数字传进去，行为不会变」的印象，
> 与一个「装配只在模块加载时发生一次，所以路由会**永久**报那一刻的值（通常是 0），而且不报错」的事实，
> 在我把真实值推到 3 再看路由读到什么之前是同一个东西。

★★★ 这一条尤其危险：**body 逐字节相同、对拍会通过、回归会全绿**，而那个计数器**从此永远错**。

## 三、两条出路，**都要动 body**

| 出路 | body 是否逐字节相同 | 代价 |

## 四、★★ 两种处置，我都能立刻执行

### 处置 1：照搬（放宽逐字对拍）

- 按**形态 B** 搬，并把 `event-delivery` 与 `events` 分成两片；
- ★ 每片的判据要**额外**钉住那件事：**访问器是活的**（装配后推一次计数，路由必须读得到新值）；
- ★★ 只有 `event-delivery` 那一族能保持"读"，`events` 要有写入口；
- ★★★ 这将是**49 片以来第一次** body 不再逐字节相同 ⇒ **对拍口径要写清楚怎么放宽**，并存档。

### 处置 2：判定不该提取，留在 `server.mjs`，写明理由

- 理由**不是**"做不完"，而是：这两条路由与 `handle()` 的**生命周期**
  （连接所有权、心跳清理、那个跨三处共享的可变计数器）绑得比前 49 族紧；
  硬搬只是把耦合换个地方，还会让一个**可变计数器跨越模块边界**；
- ⇒ 记成一条**有出处的裁定**（而不是"没做完"），并把"剩 0 条"做成判据之外的**显式豁免**；
- ★ 台账口径随之明确：`188 = 186 已搬 + 2 裁定不搬`。

★ **无论哪一种，本轮的守卫都该在** —— 它把"按值搬"这个静默错误变成一次报错。

## 五、本轮的守卫（已落地）

`scripts/prt/sse-tail-guard.mjs` + `scripts/prt/sse-tail-guard.test.mjs`（**13 例**）。它核：

1. `server.mjs` 里剩下的**恰好**是那一对（多一条、少一条、换一条都报，且**列出实际剩下什么**）；
2. 那个绑定**仍是模块级 `let`**、且**除声明外真的被写过**；
3. ★★★★★ 若那对**已被搬走**，新模块的注入面**不许按值**给那个绑定。

★★ **守卫自己的破验（8/8 咬住）当场抓出它自己两个洞**：

- **洞一**：我原本用 `writeCount < 1` 判"真的被写过吗" —— 而 `let x = 0` 的**声明本身**就带一个 `=`
  ⇒ 这个计数**永远至少是 1** ⇒ **那道守卫一次都不会响**。
  > 一个「我查了『这个绑定真的被写过吗』」的印象，与一个「`let x = 0` 的声明自己就带 `=`，所以计数永远 ≥ 1」的事实，
  > 在我把测试里那次"本该响却没响"读出来之前是同一个东西。
  ⇒ 改用 `mutationCount`（**排除声明**）。
- **洞二**：我原本判"按值"的规则是「名字后面跟着 `,` 或 `}`」——
  而 `bookkeepingFailures: () => deliveryBookkeepingFailures,` 里那个名字**也**跟着 `,`
  ⇒ 它会**把正确的访问器写法报成错误**（错在**危险的方向**）。
  ⇒ 改成认**简写属性**（名字由 `{` 或 `,` 直接领着）。

★ 还有**第三个**洞：破验报 `M5 ★★★ ③ 那条整体不生效` **没咬住** ——
因为 ③ 只在"那对已被搬走"时才生效，而真实仓库里它们还在
⇒ **一条判据都碰不到**。⇒ 给 `checkSseTail` 加了 `opts.files` 以便把 ③ 真正跑到。

★★★ 这三条**都在同一个守卫里**，而它们**都是"判据自己长了一个洞"**这一类 ——
与切片 45/49（正则太窄）、切片 51（代理判据）同类。
