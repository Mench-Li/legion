# T-006 需求说明：Markdown 待办清单 Web 应用

> 阶段：需求澄清（requirement） ｜ 任务：实现一个 Markdown 待办清单 Web 应用
> 原始描述：本地运行的单页待办应用：支持增删改查、Markdown 渲染、localStorage 持久化，纯静态部署

## 1. 背景与目标

提供一个**零后端、纯静态**的单页待办（Todo）应用：用户用浏览器打开一个本地 HTML（或任意静态托管地址）即可使用；待办条目内容以 **Markdown** 书写并渲染展示；全部数据保存在浏览器 **localStorage** 中，刷新/关闭重开后不丢失。

目标用户：个人轻量任务记录者，注重低门槛（双击 HTML 即可用）与数据私有（不出本机）。

## 2. 范围

### 2.1 范围内（In Scope）

- 单页应用（SPA）：单个入口页面，无路由跳转需求。
- 待办条目的**增、删、改、查**（CRUD）。
- 待办内容支持 Markdown 语法并**渲染为富文本**展示。
- 完成状态切换（done / todo）。
- 数据持久化到 **localStorage**，跨会话保留。
- **纯静态交付**：构建产物为 HTML/CSS/JS，可被 `file://` 直接打开或任意静态服务器托管。

### 2.2 范围外（Out of Scope）

- 多用户 / 账户体系 / 服务端同步。
- 多设备数据同步、导入导出（v1 不做，列入遗留问题）。
- 拖拽排序（v1 用固定排序规则，见 §6 遗留问题）。
- 移动端原生 App、PWA 离线安装（静态托管天然可缓存，但不强制 manifest）。
- Markdown 编辑器所见即所得（WYSIWYG）——v1 为「源码输入 + 渲染预览」即可。

## 3. 术语与数据模型

### 3.1 待办条目（TodoItem）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 唯一标识（如 `Date.now().toString(36)` + 随机后缀） |
| `title` | string | 纯文本标题，必填，用于列表行首显示 |
| `content` | string | Markdown 源文本，可空 |
| `done` | boolean | 完成状态，默认 `false` |
| `createdAt` | number | 创建时间戳（ms） |
| `updatedAt` | number | 最近修改时间戳（ms） |

### 3.2 存储约定

- localStorage 键：`md-todo:v1`（带命名空间与版本号，便于未来迁移）。
- 值：JSON 序列化的 `TodoItem[]`。
- 读取失败（JSON 损坏/键不存在）时降级为空数组，**不得**导致白屏。

## 4. 功能需求（FR）

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| FR-1 | 新增待办：输入标题（必填）与 Markdown 内容（可空），保存后出现在列表顶部 | 空标题提交被拒绝并提示；新增后立即可见且 `createdAt` 正确 |
| FR-2 | 列表查看：展示全部条目，未完成的在前 / 已完成的在后（或明确标注），显示标题与渲染后的内容 | 渲染结果与 Markdown 语义一致（见 FR-4） |
| FR-3 | 编辑待办：可修改标题与内容，保存后更新 `updatedAt` | 编辑回填原文（Markdown 源码），取消不改变数据 |
| FR-4 | Markdown 渲染：至少支持标题（#）、加粗、斜体、行内代码、代码块、无序/有序列表、链接、删除线 | 对给定样例 Markdown 渲染出对应 HTML 结构 |
| FR-5 | 渲染安全：Markdown 中的原始 HTML/脚本必须被**转义或过滤**，禁止 XSS（如 `<img onerror>`、`<script>` 不执行） | 注入测试样例不弹窗、不执行脚本 |
| FR-6 | 完成切换：单击复选框/按钮切换 `done`，界面即时反馈（如删除线/置灰） | 刷新后状态保持 |
| FR-7 | 删除待办：删除前需确认（confirm 或二次点击） | 确认后条目从列表与 localStorage 同时消失 |
| FR-8 | 持久化：所有写操作（增/改/删/切换完成）即时写入 localStorage | 每次操作后 `md-todo:v1` 内容同步更新；刷新页面数据完整恢复 |
| FR-9 | 纯静态运行：构建产物不依赖任何后端 API；用 `file://` 直接打开 `index.html` 可正常全部功能 | `file://` 打开下 FR-1~FR-8 全部通过 |

## 5. 非功能需求（NFR）

| 编号 | 需求 | 口径 |
| --- | --- | --- |
| NFR-1 | 浏览器兼容：最近两个大版本的 Chrome / Edge / Firefox | 手动冒烟通过 |
| NFR-2 | 无联网依赖：运行期不请求任何外部 CDN/字体/脚本（Markdown 解析库须打包进产物或自实现） | 断网/`file://` 下功能完整 |
| NFR-3 | 体积：构建产物总体积（gzip 前）≤ 500 KB | 构建后统计 |
| NFR-4 | 空态与极值：0 条时显示空态提示；单条内容 ≤ 10 000 字符不卡顿；条目数 500 内滚动流畅 | 手动验证 |
| NFR-5 | 可访问性基础：主要操作可键盘完成，按钮有可读标签 | 手动验证 |

## 6. 已澄清的关键结论（对原始描述的裁决）

1. **「Markdown 渲染」的边界**：渲染对象是每个待办条目的 `content` 字段；标题 `title` 保持纯文本不渲染（避免标题注入结构混乱）。编辑时是 Markdown 源码 + 预览，非所见即所得。
2. **Markdown 解析方案**：优先复用仓库/生态已有的轻量解析器；若无可复用项，允许自实现受限子集（FR-4 列表），**不得联网下载依赖**（仓库纪律）。FR-5 的 XSS 防护是硬性要求。
3. **排序规则**：v1 固定为「未完成在前（按 createdAt 倒序）、已完成沉底」，不做拖拽排序。
4. **「纯静态部署」口径**：产物须同时满足 (a) 任意静态服务器可托管，(b) `file://` 双击可运行——因此构建须避免绝对路径与裸 ES module 跨文件引用带来的 `file://` CORS 问题（打包为单文件或相对路径 + 内联）。
5. **数据迁移**：localStorage 键带版本号 `md-todo:v1`；v1 阶段不做旧数据迁移。
6. **删除保护**：删除必须二次确认，防误删。
