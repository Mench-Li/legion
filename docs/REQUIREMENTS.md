## 1. 背景与目标

提供一个**本地可自托管**的多用户实时协作白板：多名用户同时打开同一画板，可绘制/编辑图形元素、实时看到彼此的操作、看到彼此的光标位置，并可各自撤销/重做自己的操作；数据持久化，刷新/重启不丢。

目标形态：一个静态前端 + 一个单进程 Node/WebSocket 服务，`docker compose up` 即可在本机跑起来，无需任何外部云服务。

目标用户：小团队即时协作（头脑风暴、草图沟通），注重**零外部依赖、最简运维、单机自托管**。

## 2. 范围

### 2.1 范围内（In Scope，v1）

- 单房间/单画板（一个白板 = 一份共享文档）；进入即用。
- 图形元素绘制与编辑（见 §4.4 元素/操作清单）。
- 多用户实时同步（Yjs CRDT，见 §4.1）。
- 协同光标 + 在线用户列表（awareness 独立通道，见 §4.3）。
- 每用户局部撤销/重做（见 §4.2 与 §5.3 待裁决的 redo 语义）。
- 无限画布 pan/zoom（视口变换，不入文档）。
- 持久化：服务重启/页面刷新后数据恢复（见 §5.2 待裁决的介质）。
- 断线重连：网络抖动后的状态重新对齐（**不含**完全离线时的本地编辑缓存）。
- 自托管部署：单容器 Docker + docker-compose + `/healthz`（见 §4.5）。

### 2.2 范围外（Out of Scope，v2 或明确排除）

- 多选（框选/多选）、图片、元素旋转、编组、橡皮擦、压感笔迹、富文本。
- 账号体系 / 登录鉴权；v1 为匿名，进入时本地随机分配昵称+颜色。
- 多实例横向扩展（v1 显式声明单实例，不承诺水平扩容）。
- 多房间/多画板管理、分享链接（❓见 §11 遗留问题 Q1）。
- 完全离线编辑（本地 IndexedDB 缓存 + 重放合并）（❓见 §11 遗留问题 Q2）。
- 导入导出、模板、深色主题（❓见 §11 遗留问题 Q3）。

## 3. 术语与数据模型

### 3.1 术语

| 术语 | 定义 |
| --- | --- |
| 文档（Doc） | 一份 Yjs `Y.Doc`，承载全部持久态（图形元素），是同步与持久化的最小单元 |
| 持久态 | 图形元素及其样式，写入 `Y.Doc`、进入 undo 历史、参与持久化 |
| 临态（presence） | 协同光标 / 在线列表，走 `y-protocols/awareness` 独立通道，**绝不**入 `Y.Doc` / undo / 持久化 |
| 视口（viewport） | pan/zoom 的本地视角变换，只存在于客户端渲染层，不入文档 |
| 房间（room） | v1 中即「单板」，一个房间对应一份 `Y.Doc`；room id 由服务端派生 |
| 收敛 | 所有在线副本停止写入后，各自 `Y.Doc` 状态最终完全一致 |

### 3.2 元素数据模型（持久态，写入 Y.Doc）

每元素一个 `Y.Map`，字段如下（v1 全集，字段名仅作契约示意，最终以 coder 落地为准）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 全局唯一（crypto.randomUUID 或等价） |
| `type` | enum | `rect` \| `ellipse` \| `line` \| `freehand` \| `text` |
| `geom` | object | 按 `type` 变化：`rect/ellipse={x,y,w,h}`；`line={x1,y1,x2,y2,arrow:boolean}`；`freehand={points:[{x,y}...]}`；`text={x,y,text}` |
| `stroke` | string | 描边/文字颜色（十六进制） |
| `fill` | string | 填充色（`rect`/`ellipse`，可空） |
| `strokeWidth` | number | 线宽（px，含自由手绘笔迹粗细） |

- 元素集合用 `Y.Map<id, element>` 存储（删除 = `map.delete(id)`，天然支持 CRDT 墓碑）。
- 文本为**单行纯文本**，渲染/导出时按纯文本处理；v1 无换行、无富格式。

### 3.3 临态数据模型（awareness，不入文档）

- 光标：`{ x, y, color, name }`（世界坐标），节流 20Hz 发送。
- 在线列表：由各客户端 awareness 状态聚合得出，客户端断开即自动剔除。

### 3.4 身份约定

- v1 匿名：进入时生成随机昵称（如 `user-<4hex>`）与颜色，存 `localStorage` 复用以保持会话内身份稳定。
- 每客户端有稳定 `clientID`（Yjs 提供），作为「每用户局部撤销」的作用域标识（`Y.UndoManager` 的 `trackedOrigins`）。

## 4. 已收敛定稿基线（✅，6 项）

> 以下 6 项已达成全员一致或 7/8 压倒性一致，下游可直接依此开工，**不再列为分歧**。

### 4.1 同步引擎 = Yjs(CRDT) + y-protocols/awareness

- requirement 已正式放弃 OT/ShareDB，全员一致。
- 理由（已具备落 ADR 条件）：局部撤销语义天然对齐 `Y.UndoManager`（`trackedOrigins` 按用户隔离）；离线/重连近乎免费；单机自托管最简（y-websocket 服务端即轻量 relay）。
- 契约：所有元素变更经 Yjs 更新同步；乱序/重复/丢包后各副本仍强最终一致（收敛）。

### 4.2 撤销作用域 = 每用户局部撤销

- 每位用户只能撤销/重做**自己**的操作；全局/协作撤销（撤销他人最近一步）**明确排除 v1**。
- 实现锚点：`Y.UndoManager` + 按 `clientID`/origin 过滤，保证「撤自己不撤别人」。
- redo 的**并发语义**仍有一处 6:2 分歧，见 §5.3（待裁决），不影响本条的撤销作用域定稿。

### 4.3 状态分层：持久态与临态物理分离

- 持久态（图形元素）→ 进 undo / 进持久化；临态（光标/在线列表）→ awareness 独立通道。
- 硬性不变量：**presence 绝不入文档、绝不入 undo 历史、绝不入持久化**（列为 ADR「状态分层」+ 可断言门禁）。

### 4.4 v1 元素/操作清单（全票收敛）

- **元素**：矩形、椭圆、直线（含箭头）、自由手绘、单行纯文本。
- **操作**：单选、移动、元素缩放、删除、改色、线宽调整。
- **画布**：无限画布 pan/zoom（视口变换，不入文档）。
- **v2**：多选、图片、旋转、编组、橡皮擦、压感、富文本、账号体系、多实例横向扩展。

### 4.5 部署形态（全票收敛）

- 单容器 Docker + docker-compose + 静态前端 + 单进程 Node/ws + `/healthz`。
- v1 显式声明**单实例**、不承诺横向扩展；不引入 Redis/消息队列/外部数据库服务。

### 4.6 量化基线（大部分收敛）

以下数字已收敛（门槛 gate = 验收门槛；soak = 压测档），仅「断线重连恢复时限」与「陈旧光标 TTL」两处仍分裂（见 §5.4）：

| 指标 | 门槛（gate） | soak |
| --- | --- | --- |
| 并发连接数 | 20 | 50 |
| 操作→远端可见延迟 | P95 ≤ 200ms | 同 |
| 收敛 | 停止操作后 ≤ 1s | 同 |
| undo 深度 | ≥ 100 步 | 同 |
| 单板元素数 | 1000 | 5000 |
| 光标节流 | 20Hz | 同 |

## 5. 待将军裁决的实质分歧（⚖️，4 项）

> 每项给出「分歧点 / 双方主张 / 影响 / 建议默认值 / 需将军确认的裁决口径」。未裁决前，M2 渲染、持久化、撤销用例无法开工。

### 5.1 渲染方案（7:1）

- **多数方（7/8）**：Canvas 2D 单画布统一渲染（形状+笔迹同层）+ 独立透明 presence overlay；`Renderer` 接口解耦。
- **少数方（coder）**：SVG（形状，白嫖 DOM 命中检测）+ Canvas2D（笔迹）+ 第三个 presence overlay。
- **影响**：命中检测 / 文本编辑态 / Z 序的代码路径选择；SVG+Canvas 混合需维护两套坐标变换与 Z 序，边界 bug 高发；单 Canvas 命中检测为标准几何（1000 元素线性检测 <1ms）。
- **建议默认值**：Canvas 2D 单画布 + 独立 presence overlay + `Renderer` 接口（依赖最薄、路径单一、可替换）。
- **裁决口径**：将军只需确认「采纳建议默认」或「改选 SVG+Canvas 三层」；同时明确交付优先级是「可控/最薄依赖」还是「最快交付」（若为最快交付，整条自研流水线应改 fork tldraw，需单独定夺）。

### 5.2 持久化介质（7:1）+ RPO/RTO 口径

- **多数方（7/8）**：SQLite（WAL）单文件嵌入式 + `StorageProvider` 抽象接口。
- **少数方（coder）**：y-leveldb（LevelDB 嵌入式文件，自带 WAL）。
- **共识部分**：二者数据模型同为「快照 + 增量 update 日志」，均为**零外部依赖**的嵌入式文件存储；分歧仅在「原子写/崩溃一致性由谁保证 + 工具链成熟度」。
- **连带定死（无论选谁）**：
  - **RPO ≤ 1s**：崩溃时最多丢失 ≤1s 内已提交的写（WAL 落盘间隔）。
  - **RTO**：进程重启后服务恢复可用（含数据回放）须有明确上限（建议 ≤5s，含进程拉起）。
  - **原子写/崩溃安全**：`kill -9` 后存储文件可打开、不损坏、回放后状态完整（无半条记录）。
- **建议默认值**：SQLite（WAL），理由：与 y-leveldb 在「零外部依赖」上等价，但备份（拷单文件）、查询、迁移工具链更成熟；`StorageProvider` 接口保证后续可替换为 y-leveldb 而不动上层。
- **裁决口径**：将军确认介质 + RPO(≤1s)/RTO 上限 + `kill -9` 恢复口径。

### 5.3 redo 语义（6:2，Y.UndoManager 经典隐藏 bug）

- **多数方（6/8）**：「撤销后，若远端并发操作先落到本人历史作用域 → **本地 redo 栈清空**」（确定性高、可断言）。
- **少数方（breaker/coder）**：「保留 redo、仅重放本人 op、由 CRDT 独立收敛」（接近 Yjs 库默认行为）。
- **影响**：两种策略在「A 撤销 → 远端 B 的并发操作穿插进来 → A 按 redo」时的最终状态不同，测试用例方向相反；不写死则撤销/重做验收留确定性黑洞。
- **建议默认值**：redo 栈清空（可预测、可测试、避免重放他人历史导致的意外状态）。
- **裁决口径**：将军确认「清空」或「保留重放」，写入「撤销语义」ADR 并落为单一测试契约。

### 5.4 量化基线两处数字分裂（每处 2~3 个候选值）

- **① 断线重连恢复时限**：5s（requirement/researcher/breaker/tester/devops）vs 10s（coder/reviewer）vs「10s 门槛 + 5s 目标」（test-designer）。
- **② 陈旧光标 TTL**：5s（requirement/researcher/tester）vs 10s（breaker/test-designer/coder/reviewer/devops）。
- **影响**：性能用例无唯一 PASS/FAIL 通过线。
- **建议默认值**：① 采用「10s 门槛 + 5s 目标」双档（门槛=CI 必须通过，目标=优化方向）；② TTL=10s（非正常断开的陈旧光标在 10s 内从他人 overlay 消失，正常断开立即消失）。
- **裁决口径**：将军确认两处各自唯一值（或采纳「门槛/目标」双档写法）。

### 6.2 量化指标埋点/测量方法（补齐「数字不可验证」缺口）

> 无测量方法的数字等于不可验证。下表把每个量化指标绑定到可机器断言或可手测的测量方式，作为 tester 用例与 devops CI 门禁的公共口径。

| 指标 | 口径 | 测量/埋点方法 |
| --- | --- | --- |
| 并发 20/50 | 单板同时在线连接数 | 压测脚本开 N 个 ws client 持续互发 op；gate=20、soak=50 下全部满足延迟/收敛指标 |
| 操作→远端可见 P95≤200ms | op 从 A 提交到 B 的 UI 反映 | 每条 op 打 `clientTs` 元数据，B 记录「收到→渲染完成」时间；采集 N 样本取 P95；探针埋点在同步层出口与渲染入口 |
| 收敛 ≤1s | 停止写入后各副本一致 | 停止注入后每 100ms 对各副本取 `Y.Doc` 状态哈希，断言 ≤1s 内全副本哈希一致 |
| undo ≥100 步 | 本人连续撤销次数 | 脚本连发 100+ 次本人操作后全量 undo，断言 `Y.Doc` 回到基线且无他人 op 被撤销 |
| 单板 1000/5000 元素 | 元素数量下的可用性 | 加载 N 元素后测交互帧率与命中检测耗时：gate=1000、soak=5000，帧率不低于阈值（建议 ≥30fps 交互、命中检测单次 <1ms） |
| 光标节流 20Hz | 每客户端光标更新频率 | 统计单客户端 1s 内发出的 awareness 更新条数，断言 ≤20 条 |
| 断线重连恢复 ⚖️ | 重连到全量对齐 | 客户端断网→恢复连接，测「恢复连接→`Y.Doc` 全量同步完成+presence 可见」耗时；gate=10s、目标=5s（默认，待 §5.4 裁决） |
| 陈旧光标 TTL ⚖️ | 非正常离线光标消失 | 客户端非正常断开（不发送 leave），测其他端该光标从 overlay 消失的耗时；默认 TTL=10s（待 §5.4 裁决），正常断开立即消失 |
| RPO ≤1s | 崩溃数据丢失上限 | `kill -9` 服务端，重启后比对「崩溃前最后可见状态」与「回放后状态」，丢失 ≤1s 内提交的写 |
| RTO | 崩溃后恢复可用 | `kill -9` 后计时至 `/healthz` 恢复 200 + 数据可读，建议 ≤5s |

| FR-11 | 渲染安全 | 文本元素按纯文本渲染/转义，恶意 HTML/脚本不执行（防 XSS） |

## 9. 关键澄清结论（对模糊点/矛盾点/缺失边界的裁决与口径）

1. **「撤销重做」语义**：已定「每用户局部撤销」（§4.2）；全局/协作撤销排除 v1；redo 并发语义仍待 §5.3 裁决。
2. **「多用户」规模口径**：并发 20（门槛）/50（soak）（§4.6），单板 1000/5000 元素，单实例不横向扩展。
3. **「图形元素」范围**：v1 全集 = 5 类元素 + 6 类操作 + 无限画布（§4.4）；多选/图片/旋转/编组/橡皮擦/压感/富文本 = v2。
4. **「本地可自托管」口径**：单容器 Docker + docker-compose + 静态前端 + 单进程 Node/ws + `/healthz`，零外部数据库/队列（§4.5）。
5. **「画板」与「图形元素」形态矛盾**：已定「矢量图形元素为主 + 自由笔迹为辅」，统一走 `Y.Doc` 同步，渲染层按 §5.1 裁决。
6. **持久态 vs 临态**：物理分离，presence 独立通道（§4.3）——这是 undo/同步正确性的根基。
7. **身份与房间**：v1 匿名（随机昵称+颜色）；房间 = 单板单文档（多房间留 §11 Q1）。
8. **崩溃恢复口径**：RPO≤1s + RTO 上限 + `kill -9` 原子写（§5.2）——补齐持久化介质之争下被忽略的「介质 vs 崩溃安全」本质。
