## 1. 背景与目标

提供一个**面向边缘节点的轻量、离线优先、对等（peer-to-peer）分布式任务队列**，满足四项原始诉求：

| 原始诉求 | 澄清后的可验收口径 |
| --- | --- |
| 离线可用 | 节点在断网/弱网下仍可本地入队并执行任务；网络恢复后与对等节点同步对账 |
| 断点续传 | 进程崩溃/掉电/重启后从本地持久化（WAL/outbox）恢复，不重做已完成副作用、不丢已提交意图 |
| 多节点协调 | 多节点通过**对等同步**协调任务归属（lease/claim/takeover），**无中心 broker** |
| 幂等投递 | 投递 = at-least-once + 幂等键 = **effective-once**；**全网禁 exactly-once**（明确声明不承诺） |

**本系统自设的可验证承诺（诚实边界）**：不承诺 exactly-once、不承诺 per-key FIFO；对不可逆副作用（Class C）的保护上限 = 在栅栏边界内拦截 + 意图先持久于外溢，**无法向外部系统承诺“绝对不会多执行一次”**。任何把这两条边界擦掉的需求表述都视为 exactly-once 幻觉复发。

## 2. 范围

### 2.1 范围内（In Scope，v1）

- 本地任务入队与 WAL/outbox 持久化（崩溃安全）。
- 离线执行与断点续传（崩溃/重启后精确续跑）。
- 多节点对等同步与任务归属协调（lease/claim/takeover/heartbeat），无中心 broker。
- 副作用级分类（effects[] + class A/B/C + 派生 task_gate）。
- 栅栏边界路由（B1/B2/B3）与分层吸收（L1..L4）。
- 幂等投递（幂等键 + 去重）与意图对账（L4）+ 审计痕迹。
- 双活窗口建模（W，zombie 时长项入式）。
- 两套验证载体：协议层确定性模拟 + 耐久层真实二进制（kill -9 / 掉电 / ENOSPC）。

### 2.2 范围外（Out of Scope，v2 或明确排除）

- exactly-once 投递（**全网禁**，不是 v2 而是原则性排除）。
- per-key FIFO / 序列屏障（**明确放弃**，降级最终一致 + 业务层版本序）。
- 中心化 broker / 协调器（定位已排除）。
- 跨第三方边界「幂等键不可得」场景的自动兜底（❓见 §12 Q1，默认显式降级为「不支持」）。
- 单次损失的货币化定价（❓见 §12 Q2，默认 v1 不定价、只做「有痕迹/无痕迹」定性断言）。

## 3. 术语与数据模型

### 3.1 核心术语

| 术语 | 定义 |
| --- | --- |
| task（任务） | 一个工作单元 = 副作用清单（manifest）+ 状态 + 租约（lease）+ 去重键 |
| effect（副作用条目） | 任务声明的每一条对外副作用，形如 `{effect_id, class, …}` |
| class（副作用类） | `A`=幂等/CAS（可版本化写/幂等键，重复执行自坍缩）；`B`=可补偿（有逆操作）；`C`=不可逆（如短信、物理执行器，无逆操作） |
| task_gate | `max(effects[].class)`，**派生字段，禁手填**；是 claim/takeover 决策的承重墙 |
| manifest（副作用清单） | 任务声明期的副作用分类清单，只负责 claim 路由，**不逐 effect 落盘** |
| intent（意图写） | 仅对 Class II/III 存在的 per-effect 耐久写，保证「意图先 durable 于外溢」 |
| 栅栏边界（fence boundary） | B1 状态层不吸收 / B2 token 条件写 / B3 自栅栏，见 §4.3 |
| 吸收层（absorption layer） | L1 队列状态层（记账）/ L2 唯一硬吸收层 / L3 补偿兜底 / L4 意图对账，见 §4.3 |
| lease（租约） | `lease_TTL` / `heartbeat` / `takeover_latency` 三元组；判死与接管的时间参数 |
| W（双活窗口） | `lease_TTL + takeover_latency + max_declared_side_effect_duration`，zombie 时长项已入式 |
| Z（孤儿自栅栏残漏窗口） | `self_fence_interval + in-flight duration`，Class III 第二窗口（⚖️ 未入 schema，见 §5.4） |
| double_active_probability（P双活） | 双活（两节点同时认为持有任务）的概率 |
| E[SilentDamage] | `Σ P(双活) × P(未检测) × 单次损失`，静默损坏期望（⚖️ 可测性见 §5.3） |
| oracle / 信任根 | 提供「地面真值」的裁判；**栅栏边界 = oracle 边界** |
| trust-root registry（信任根在册） | 每个被依赖的信任根的可交付/可审计条目清单，见 §6 |

### 3.2 关键不变量（可断言门禁）

1. **I1 派生禁手填**：`task_gate = max(effects[].class)`，任何手填 `task_gate` 的写入 CI REJECT。
2. **I2 意图先于外溢**：Class II/III 的每条 effect，其 intent 写必须 durable 之后才允许外溢（发起对外副作用）。
3. **I3 栅栏边界 = oracle 边界**：任何吸收/对账动作的终止点必须落在在册信任根上，不得落在「本系统自己的 ledger」上（否则递归不回原点）。
4. **I4 全网禁 exactly-once**：任何以 exactly-once 为交付承诺的路径 CI REJECT；有效承诺上限是 effective-once。

## 4. 已收敛定稿基线（✅，6 项）

> 以下 6 项已七人合流，可直接据此搭底座，**不再回撤**。

### 4.1 定位 = 本地 WAL/outbox + 对等同步，非中心 broker

- 无中心 broker/协调器；任务先在本地 WAL/outbox 落盘，再与对等节点同步。
- 投递语义 = at-least-once + 幂等键 = effective-once；**全网禁 exactly-once**（第二次 exactly-once 幻觉已处决，不得复活）。

### 4.2 分类粒度 = 副作用级 effects[]，task_gate 派生禁手填

- 每条副作用 `{effect_id, class∈{A幂等/CAS, B可补偿, C不可逆}}`。
- `task_gate = max(class)` 为派生字段、权威在清单，**禁手填**。
- 「CAS + append + SMS 混合任务」已证伪「任务级单字段」——一个任务含 Class A（CAS 条件写）、Class B（append 可补偿）、Class C（SMS 不可逆）时，任务级单一 class 无法同时表达「可自动接管」与「不可逆不可自动接管」。
- 结构区分（researcher 钉死，防止「一个机制三用途」复活）：
  - **分类清单（manifest）**：便宜、可派生，只管 claim 路由，**不逐 effect 落盘**。
  - **意图写（intent）**：只对 Class II/III 存在，per-effect、happens-before 外溢。
  - 二者生命周期不同，**不得焊成「一个结构」**（否则 Class I 付了不需要的账、Class II/III 又没买到需要的耐久）。

### 4.3 吸收按「栅栏边界」路由（B1/B2/B3）+ 分层 L1..L4

| 层 | 角色 | 定稿口径 |
| --- | --- | --- |
| B1 状态层 | 本地状态机读写 | **不吸收**，只是记账 |
| B2 token 条件写 | 落地前的原子条件写 | **唯一硬吸收层**，仅可版本化写（CAS/idempotent-key） |
| B3 自栅栏 | 不可逆动作发起前拦截 | Class C 发起前检查租约/栅栏 |
| L1 队列状态层 | 记账 | 不吸收 |
| L2 token/栅栏层 | 硬吸收 | **唯一硬吸收层** |
| L3 补偿 | Class B 逆操作 | 兜底 |
| L4 意图对账 | intent reconciliation | **条件观测**：`P(未检测 | intent durable) = 0`；devops 已收回「最便宜硬保证」 |

### 4.4 有序 = 放弃 per-key FIFO，最终一致 + 业务层版本序

- 放弃 per-key FIFO、不补序列屏障。
- 降级为最终一致 + 业务层版本序（version 字段由业务自管）。

### 4.5 验证载体 = 确定性模拟 + 真实二进制，两套 harness 互相校验

- 协议层：确定性模拟（注入乱序/重复/丢包/分区/双活交错）。
- 耐久层：真实二进制 `kill -9` / 掉电 / ENOSPC。
- DSH 插件仅作协议内循环，不作为耐久裁判。

### 4.6 双活窗口 W 入式

- `W = lease_TTL + takeover_latency + max_declared_side_effect_duration`（zombie 时长项已入式）。
- 注意：W 的**公式**已定，但 `lease_TTL` / `takeover_latency` 的**数值**属待裁决（§5.1），在输入补齐前不得给具体数。

## 5. 待裁决分歧（⚖️，3 条核心 + 1 条 schema）

> 三条互相缠绕，缺一不得进入任务拆解。每条给出根因、双方主张、缺失输入、建议默认值与需将军确认的裁决口径。

### 5.1 ⚖️-1 SLO/lease 推导链断裂（因果错置）

- **根因（已由 coder/test-designer 钉死）**：`I_max = D/(M×K)` 只产**吞吐（rate 量纲）**，产不出 **lease（时间量纲）**；`lease = f(假死时长分布, per-class 双活代价)`，与磁盘预算**正交**。
- **矛盾表现**：同一 Class I lease 出现 5/10/15/20 四个互斥值（tester 5s / coder 10s / reviewer 15s / devops 20s），全部标「派生非手填」；将军「不得单方面报数」被违反四次。根因不是纪律问题，而是 lease 根本不在「存储预算反推」链的射程内。
- **缺失输入（补齐前 lease 列整列置空）**：
  1. **假死时长分布**（fake-death duration distribution）——devops **实测认领**（由真实 harness / 混沌注入测得，不得手填）。
  2. **per-class 双活代价 / 损失定价表**——**业务认领**，技术角色不得自填。
  3. **唯一去重键大小**（32/48/64B 三选一，吞吐结果 ±2×）——将军/业务定。
- **建议默认值**：
  1. 输入补齐前，`lease_TTL / heartbeat / takeover_latency` 三列**整列置空**；CI 增设 **lineage 门禁**——任何带数 lease 单元格 REJECT（derive trace 缺失即拒绝）。
  2. 采纳 breaker 的「设计界 vs 实测值」两态拆分：设计期只给**推导链 + 约束**（不给具体 lease 数值）；实测值由 harness 上线后回填。
- **裁决口径（将军逐项确认）**：
  1. 是否接受「lease 列整列置空 + lineage 门禁」作为转 breaker 的前置条件？
  2. 是否采纳「设计界 vs 实测值」两态拆分作为解锁手段？
  3. 三钉之一「离线时长」的权威解释：是**保留窗口**（存储策略，去重键/账本条目的保留期）还是**执行可用窗口**（lease 参数）？二者正交，不得偷换（researcher 曾把 Class III 有效离线时长偷换成 lease 参数，devops 已驳回）。

### 5.2 ⚖️-2 meta 递归终止条件未闭合

- **根因**：吸收器（补偿器/对账器）自己跑在同一条队列上，它自己的 double-execution 也需要被吸收 → 无限递归，除非终止于一个**系统之外的信任根**。
- **矛盾表现**：breaker 主张「换协议/换命名空间纯结构排除」（只答了结构性排除 b）；tester 断言「物理上不可能躲开窗口、只能靠吸收器自身 Class A 幂等自坍缩」（只答了幂等不动点 a）；reviewer 明判二者**各答一半、互相拆台**。requirement 再补一刀：「补偿=Class A」的前提（目标系统支持幂等键）是**声明期不可验证的外部事实**，故它是信仰声明而非可测终止条件。
- **统一框架（建议默认）**：**栅栏边界 = oracle 边界**。递归终止点 = 一个**在册信任根**，其幂等性/原子性由**系统之外**一方保证（DB UNIQUE 约束 / 对象存储 CAS / 第三方平台幂等键），本系统只**声明依赖**它、不**证明**它。
- **裁决口径（将军逐项确认）**：
  1. trust-root registry 的可交付/可审计形式：每条 = `{信任根 ID, 类型, 保证属性, 持有方, 失效时降级策略}`（结构见 §6）。
  2. 递归在哪个信任根终止？吸收器的副作用 class 必须 ≤ 其所依赖信任根的 class（如补偿器的补偿动作本身必须是 Class A，且其幂等键由外部信任根保证）。
  3. 跨第三方边界如何显式降级为「不支持」：目标系统不支持幂等键时，该 effect **不得声明为 Class A**，必须降级为 Class B/C 并接受对应代价。

### 5.3 ⚖️-3 E[SilentDamage] ≤ 预算是否可测

- **根因**：`E[SilentDamage] = Σ P(双活) × P(未检测) × 单次损失`。`P(双活)=double_active_probability`（devops 自认「谁报谁造假」）；`P(未检测)` 按定义是「系统没记账的损坏」——没有系统之外的全知 oracle，chaos 注入**制造得了故障、揭示不了「系统什么都没记录」这件事本身**。
- **矛盾表现**：devops 既称 P(双活)「谁报谁造假」又把它当 CI 门禁左端因子；tester 指出这等于把亲手认掉的不可测概率重新请进「唯一能真实回归」的判据。可测的只有**可数性质**：注入 ground-truth 双活交错，穷举断言「静默交错集合 = ∅、每条交错留下 absorbed ∨ audited 痕迹」。
- **裁决口径（devops 须二选一，将军裁定）**：
  1. **方案 A（推荐）**：承认 `E[SilentDamage]` 是**设计意图声明**，不是 CI 断言；CI 只签「已检测集 + 审计完整性」两类可数性质。
  2. **方案 B**：交出系统之外的 oracle（能看见静默损坏的 ground truth）并纳入验证载体；交不出即回退方案 A。
  3. 单次损失定价是否作为输入？默认 v1 不定价、只做「有痕迹/无痕迹」定性断言（❓§12 Q2）。

### 5.4 ⚖️-4（schema 欠账）Class III 双窗口未入矩阵 schema

- **根因**：requirement 的 W（A+B 双活窗口）与 Z（孤儿 A 自栅栏残漏窗口）两个窗口未同时入 schema。W 已入式（§4.6）；`Z = self_fence_interval + in-flight duration`（自栅栏发起到动作完成的残漏）尚未定义字段与测量口径。
- **裁决口径**：Z 是否入 v1 schema？**默认入**——因为 Class C 的残漏窗口是唯一能产生不可逆静默损坏的路径，Z 不入 schema 则 E[SilentDamage] 的 C 类项无定义。

## 6. 信任根（oracle）统一框架

> 三条待决点共同的根因：**信任根/裁判住在哪一侧**。本节给出统一框架，作为 §5.2 的可交付形式。

### 6.1 原则

- **栅栏边界 = oracle 边界**：任何吸收/对账动作的终止点必须落在在册信任根上，不得落在「本系统自己的 ledger」上。
- **声明依赖 ≠ 证明**：本系统对信任根只做**声明依赖**（declared dependency），不做**证明**（proof）；证明属于信任根持有方的契约。
- **class 约束**：吸收器的副作用 class 必须 ≤ 其所依赖信任根的 class。

### 6.2 trust-root registry 条目结构（可交付/可审计）

| 字段 | 说明 |
| --- | --- |
| trust_root_id | 唯一 ID |
| kind | `db-unique` / `object-cas` / `third-party-idempotency-key` / … |
| guaranteed_property | 幂等 / 原子条件写 / … |
| holder | 持有方（系统之外） |
| degradation | 信任根失效时的降级策略（如：该 effect 降级为 Class B/C，或显式「不支持」） |

### 6.3 判定规则

- 每个在册信任根必须回答：**递归在哪个信任根终止？**（回答不了 = 该信任根不在册 = 不能作为终止点。）
- 跨第三方边界：目标系统不支持幂等键 → 该 effect 不得声明为 Class A，显式降级「不支持」。

## 7. 量化基线、推导链纪律与测量方法

> 核心纪律：**量纲自检 + 推导链可追溯（lineage）**。无推导链的数字 = 断链编数，CI REJECT。

### 7.1 推导链纪律（哪些能算、哪些置空）

| 量 | 推导链 | 量纲 | 状态 |
| --- | --- | --- | --- |
| I_max（吞吐上限） | `D / (M × K)`，D=磁盘预算、M=保留窗口、K=去重键大小 | rate（1/时间） | ✅ 可给（D/M/K 钉死后） |
| lease_TTL / heartbeat / takeover_latency | `f(假死时长分布, per-class 双活代价)` | time | ⚖️ **整列置空**，输入补齐前禁报数 |
| double_active_probability | 分区时长分布 × 执行时长的函数 | 概率 | ⚖️ 置空（「谁报谁造假」） |
| P(未检测) | 系统没记账的损坏比例 | 概率 | ⚖️ 无外部 oracle 不可测（§5.3） |
| 单次损失 | 业务定价 | 货币/损失单位 | ❓ v1 默认不定价 |
| W（双活窗口） | `lease_TTL + takeover_latency + max_declared_side_effect_duration` | time | ✅ 公式定、数值随 lease 置空 |
| Z（残漏窗口） | `self_fence_interval + in-flight duration` | time | ⚖️ 未入 schema（§5.4） |

**量纲自检（lineage 门禁核心断言）**：`I_max` 产 rate，`lease` 产 time，二者正交；任何「20GB → 5s」式结论均为断链，REJECT。

### 7.2 测量方法（可机器断言，供 tester/devops 转用例）

| 指标 | 口径 | 测量/埋点 |
| --- | --- | --- |

## 10. 关键澄清结论（对矛盾点/模糊点/缺失边界的裁决与口径）

1. **「幂等投递」语义**：投递 = at-least-once + 幂等键 = effective-once，**全网禁 exactly-once**；「幂等键」只在目标系统支持时成立，是声明依赖而非本系统保证。
2. **「多节点协调」形态**：对等同步 + lease/claim/takeover，**非中心 broker**；双活防护以栅栏 + 租约实现。
3. **「任务分类」粒度**：副作用级 effects[]（class A/B/C），task_gate=max(class) 派生禁手填；任务级单字段被「混合任务」证伪。
4. **「断点续传」口径**：本地 WAL/outbox 为唯一耐久根，崩溃后精确续跑、不重做已完成副作用。
5. **SLO/lease 因果错置**：I_max 只产吞吐、产不出 lease；lease 是假死分布 × per-class 双活代价的函数，与磁盘预算正交（§5.1）。
6. **meta 递归终止**：breaker（结构排除）与 tester（Class A 自坍缩）各答一半；统一为「栅栏边界 = oracle 边界」+ trust-root registry（§5.2、§6）。
7. **E[SilentDamage] 可测性**：概率期望值不可测，可测的是「静默交错集合 = ∅、每条交错留痕迹」的可数性质（§5.3）。
8. **信任根位置**：三条待决点共同根因 = oracle 住哪一侧；答案 = 在册信任根（系统之外），本系统只声明依赖、不证明。
