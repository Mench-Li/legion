# 密钥轮换说明（2026-09-18）

> **这份文档不包含任何密钥的值。** 它只记"泄漏了什么形状的东西、影响面在哪、
> 轮换之后要同步改哪里"。任何"为了说明而贴一次真值"的写法都应当被拒绝——
> *一份为了讲清一次泄漏而再泄漏一次的文档，与它要防的事是同一件事。*

## 1. 发生了什么

在 **PRT-509（DSH 凭据读取桥）** 的核查过程中，我把 `~/.dsh/.credentials.yaml`
的内容打进了会话转录。**我自己的脱敏判据写错了**：它只对**长度 > 40 字符**的值生效。

这不是"忘了脱敏"，是**判据的阈值把一部分真值划到了保护圈之外**：

```
长度 35  →  不脱敏   ← 泄漏
长度 25  →  不脱敏   ← 泄漏
长度 25  →  不脱敏   ← 泄漏
长度 49  →  脱敏
```

## 2. 精确影响面（按长度可复算，不是回忆）

本机 `~/.dsh/.credentials.yaml` 有 4 个键。按"≤40 字符者未脱敏"这条规则复算：

| ref 名 | 长度 | 是否进了转录 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 35 | **是（明文）** |
| `CUSTOM_DS_API_KEY` | 25 | **是（明文）** |
| `CUSTOM_GPT_API_KEY` | 25 | **是（明文）** |
| `ZAI_CODING_CN_API_KEY` | 49 | 否（被脱敏判据拦下） |

★ 这就是"三把"的来历：**不是三次泄漏，是三个值落在了阈值下面。**
★ 复算方式（不打印值）：`check-committed-prefix.mjs` 同款——只比长度与前缀。

### 2.1 另有两处**已经提交进仓库**的泄漏（与本会话的误印无关，但同源）

同一个前缀 `sk-be96`——它是**本机 `DEEPSEEK_API_KEY` 的真实前缀**（7 个字符），
已用逐字节前缀比较核对过（只输出布尔值，未打印任何更多字符）——出现在**两个**地方：

| 位置 | 原文 | 处置 |
| --- | --- | --- |
| `docs/STATUS.md:2528` | ``refs: { DEEPSEEK_API_KEY: sk-be96… }`` | **已就地改成 `sk-…`** |
| `docs/superpowers/prt/PRT-PROGRESS.md:163`（PRT-509 行） | 同一句（这一行是台账里 PRT-509 的正文） | **已就地改成 `sk-…`** |

> 它当时是为了让一段安全论述"更实"——而**论述的可信度不需要一份真值来支撑**。
> 一句"形如 `sk-…`"与一句"实测 `sk-be96…`"，在读者的理解上**完全一样**，
> 只不过后者把一个活着的凭证的一截留在了 git 历史里。
> 而它出现**两次**的方式也值得记：同一段话被复制到了两处，
> 于是**一次泄漏自动变成了两次**——复制一段带真值的散文，与复制一次泄漏是同义的。

★ 复核方式：`git grep -c "sk-be96"` 现在**无输出**（改之前在两处各命中 1 次）。
★ **但轮换仍然是必须的**：这两个前缀即使已经改掉，旧值依然留在 **git 历史**里，
`git log -p` 仍能取回。改文档只是止住"继续出现在当前树上"。

## 3. 轮换步骤（建议顺序）

1. **先轮换 `DEEPSEEK_API_KEY`**——它同时是 §2.1 那处 committed 泄漏的对象，优先级最高。
2. 再轮换 `CUSTOM_DS_API_KEY`、`CUSTOM_GPT_API_KEY`。
3. `ZAI_CODING_CN_API_KEY`（长度 49）**没有**进转录，可以按你自己的节奏处理；
   但如果你怀疑阈值之外的路径，一起换掉是最省心的。
4. 轮换 = 在提供方控制台**签发新值**并**吊销旧值**。
   ★ 只签发新的而不吊销旧的，等于没轮换——泄露出去的那一把仍然有效。

## 4. 轮换后要同步的地方

| 位置 | 要做什么 |
| --- | --- |
| `~/.dsh/.credentials.yaml`（`refs:` 段） | 写入新的值。**这是 DSH 用的那一份。** |
| `~/.dsh/settings.yaml` | 无需改：它只写 `providers.apiKeyEnv: CUSTOM_DS_API_KEY`（**引用名**，不是值） |
| 环境变量（Process / User / Machine 作用域） | 本机实测 `CUSTOM_DS_API_KEY` 在这三处**都是空**，所以 key 只能来自 `.credentials.yaml`。若你曾把它设进环境变量，三处都要改 |
| Legion 的密钥库（若已用过 `legion` 的凭证写入入口） | 走 PRT-505 的写路径（新增/更新/轮换/删除），不要手改文件——那条路径每次写完会复核 ACL |
| `docs/STATUS.md:2528`、`docs/superpowers/prt/PRT-PROGRESS.md:163` | **已在 2026-09-18 就地改成 `sk-…`**（两处）。核对：`git grep -c "sk-be96"` 现在无输出 |

## 5. 判据层面的修复（防止第二次）

这次的根因是**用长度当"像不像密码"的判据**。

> 一个"只保护长字符串"的脱敏器，与一个"只保护它恰好认识的那几种形状"的脱敏器，
> 在真正需要它的时候是同一个东西——只不过前者会让人以为覆盖了全部。

正确的方向是**按来源脱敏，而不是按形状**：任何来自凭证读取路径的值，
一律脱敏；判据里不出现"多长才算敏感"这种阈值。这一条还没有实现成代码，
**如实记在这里，不假装已经修好**。

  （§2.1 那处 committed 泄漏**早于**本次会话，不是这一轮造成的）。
