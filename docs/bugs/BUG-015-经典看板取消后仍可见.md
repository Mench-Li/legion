# BUG-015｜「经典看板」早就取消了，但它的入口与**整条 v1 数据源**还留在指挥台里

> 发现于 2026-10-10，起点是将军的截图：**「军团指挥台」的任务中心右上角还挂着「打开经典看板 ↗」**，
> 快捷工具里还有「打开内部看板 / 经典看板（新窗口）」，KpiBar 右下角还能改那条 v1 数据源地址。
> 而被打开的那个 v1 看板（`scrum/serve.mjs`）**早已取消**。
> 与 BUG-014 同族：那一处是"请求发给了另一个数据源"，这一处是"**那个数据源整个都不该存在了，而它还在界面上**"。

## 0. 现象与一句话根因

指挥台上有**四条**通往那条已取消链路的入口/落点，用户全部点得到：

| # | 位置 | 用户看到 |
| --- | --- | --- |
| ① | 任务中心右上角 | `打开经典看板 ↗`（新标签页打开那条 v1 服务） |
| ② | 右侧「快捷工具」 | `打开内部看板 / 经典看板（新窗口）` |
| ③ | KpiBar 右下角 | `⚙ 127.0.0.1:4820`（点一下弹 prompt 改数据源） |
| ④ | 设置 → 连接与令牌 | `Workbench 数据源` 输入框（保存后整页重载到那个源） |

根因一句话：

```ts
// workbench/src/api.ts（修前）
const DEFAULT_API = 'http://127.0.0.1:4820'   // ← v1 看板（scrum/serve.mjs）的地址，早已取消
export function fetchConfig() { … `${apiBase()}/api/config` … }   // 连带整条 v1 取数面
export function subscribeBoard(…) { … `${apiBase()}/api/board/events` … }
export function openKanban() { window.open(apiBase(), '_blank', 'noopener') }   // ← 就是①/②的落点
```

**取消一条数据源时只删了服务端，没删客户端这一面。** 于是界面上留着一批通往死链路的入口，
更糟的是 `App.tsx` 里还留着"中枢探测不到就**回退**到 v1 只读模式"的分支 ——
中枢没起来时，用户看到的是一份**看不出是旧的**看板快照。

> 一个"取消了"的产品面，只要**入口还在**，对用户来说就没有取消。
> 而它比没取消更坏：点进去是一条死链路，报的还是一句与真因无关的话（BUG-014 同形）。

## 1. 为什么这条面必须整条删掉，而不是"把入口藏起来"

那条 v1 数据源不是"另一个视图"，它是**另一台进程、另一套接口**（`/api/config`、`/api/board`、
`/api/activity`、`/api/missions`、`/api/pause|resume`、两条 SSE）。它服务的是旧看板，
其中：

- **全局暂停**（写 `control.json`）是那条服务端的调度概念，中枢侧**没有**这个东西
  （中枢的暂停是**按目标/按任务**的，见 GoalsBoard / 任务详情）；
- **`v1 文件模式只读`** 是那条链路的阅读模式，中枢是**真 scope 分区 + 可拖拽迁移**，两者语义不同名。

所以处置是**整条删**（前端不再有任何东西认识它），而不是留一个灰按钮。留下的每一处都会
被下一个读代码的人当作"这条链路还在"的证据。

## 3. 行为变化（★ 这一条要单独说）

**中枢不可达时，指挥台不再回退到 v1 只读模式，而是明确报「中枢不可达」。**

| | 修前 | 修后 |
| --- | --- | --- |
| 中枢可达 | 中枢数据（v2） | 中枢数据（v2）—— 不变 |
| 中枢**不可达** | 静默回退：去那条 v1 数据源取一份**只读看板**，界面照常显示 | **`conn='error'`**：`✕ 无法连接中枢 /hub` + 错误原文 + 怎么把中枢指过去 |

改这个方向是有意的：回退看起来"更友好"，实际上是把**"上游没起来"显示成"有一份任务的旧快照"** ——
用户没有任何办法从屏幕上分辨这两件事，而他会照着那份快照做决定。
**没有数据要说不出来，不能拿另一条链路的数据顶上。**

错误屏给出的两条指引都在中枢这一侧（读 `hubBase()` 的实际值）：
确认 team-hub 已启动、以及中枢在别处时怎么把 `legion.workbench.hub` 指过去。

## 4. 判据

新增 `workbench/scripts/no-classic-board.test.mjs`（4 例，已登记进 `scripts/ci/run-ci.mjs`，
位置在 `model-library-panel（…）` 那条附近）：

| 用例 | 断言 |
| --- | --- |
| ① | 递归读 `workbench/src` 下全部 `.ts/.tsx`（剥掉**整行注释**后），下面 15 个字符串**0 命中**：`经典看板`/`apiBase`/`setApiBase`/`setPaused`/`openKanban`/`subscribeBoard`/`subscribeActivity`/`fetchConfig`/`fetchBoard(`/`fetchActivity(`/`fetchMissions(`/`scrum/serve`/`4820`/`v1 文件模式`/`?api=`，每条各附一句"为什么它不该出现" |
| ② | `api.ts` 里逐个点名这些导出确实不在；同时**反向锚**：`hubBase`/`probeHub`/`fetchHub*`/`subscribeHubAudit`/`dshModelsRpc`/`hubRequest` 必须还在（删 v1 不许伤 v2） |
| ③ | `SnapshotView.tsx` 用 `hubBase()`（≥4 处取数点）、不许出现 `apiBase` —— 快照属于**中枢** |
| ④ | `App.tsx` 里中枢探测失败必须显式 `setConn('error')`，错误屏必须说「无法连接中枢」并给出 `hubBase()` |

**一处刻意写明的例外**：`fetchConfig` 这一条用**词边界**（`\bfetchConfig\b`）匹配 ——
`fetchConfigBundle`（PRT-508 的配置导入导出，走中枢、有 `ModelTransferPanel` 这个生产调用方
与 `model-api.test.mjs` 守着）**保留**。裸 grep `fetchConfig` 会命中它 3 次（1 定义 + 1 导入 + 1 调用），
那是**假阳性**，不是 v1 残留；判据因此按"裸名"匹配，并在文件头写清这个例外。

**连带修好的判据**：`workbench/scripts/dsh-models-base.test.mjs` 第 ③ 条原本钉的是
"`apiBase()` 的默认值必须仍是 4820" —— 那条反向锚的对象现在整条不存在了，继续钉它会变成
`TypeError`。已改为**只守同源**（地址必须是写死的相对路径常量 `/api/dsh-models`，且 `apiBase`
不许以任何形式回来），第 ①②④⑤ 条（请求真的落在同源、`dshModelsRpc` 不许引用它、网络层具名文案、
401 文案穿透）原样保留。文件头也加了一句"v1 看板取消后，apiBase 没了，这条判据改为只守同源"。

## 5. 下次怎么发现这类问题（判断句）

> **沿着"用户点得到的东西"往回走一遍：每一个入口/按钮/输入框，今天点下去之后落到的那个服务，是不是还在跑？**
> 一条数据源被取消时，**它的入口、它的地址、它的回退分支必须在同一次改动里一起消失** ——
> 只删服务端，留下的是"点得到、打不通、还报一句与真因无关的话"的三件套。

同一族的自查方式（三条都能机械地做）：

1. **入口巡检**：界面上的每一个"打开/前往/在新窗口打开"，都要能指到一台**今天还在跑**的进程；
2. **回退审计**：每一条 `probe…()` 探测失败的分支，都要问一句"顶上来的这份数据是谁的、用户能不能分辨";
3. **字符串墓碑**：被取消的概念禁止以"只是注释/只是文案/只是个默认值"的形式留在源码里 ——
   本仓的处置是**源码级判据**（`no-classic-board.test.mjs`），不是靠下一次代码评审的眼力。

服务端强制同源、只限本机）与"另一条数据源"是否还在无关。

## 7. 生效条件与已知边界

- **要重新构建 `workbench/dist` 并刷新页面**：被托管的指挥台服务的是 `workbench/dist`，
  源码改动必须重新构建才会进浏览器（同 BUG-014 §6）。
- 本条**只动 `workbench/src`**（前端一面）。那条 v1 服务端（`scrum/serve.mjs` 及其套件）
  不在本次改动范围内 —— 它是否还要作为历史/对比工具保留，需要另行裁决。
- `workbench/README.md` 第 146 行还写着"面板右上角仍保留「打开经典看板 ↗」作调试/历史对比入口"，
  这是**与本次改动不一致的文档**；未在本条内改动（超出"删前端入口"的范围），见 §8。
- `workbench/mobile/`（手机端看板）与 `workbench/scripts/identity-gate.test.mjs` 里还有提到旧
  v1 文案的注释，同样不在 `workbench/src` 内、不属于本次判据的扫描面。
