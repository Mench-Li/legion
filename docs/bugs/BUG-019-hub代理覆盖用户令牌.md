# BUG-019（补记）｜`/hub` 代理把用户令牌换成了机器令牌 ⇒ 整个网页卡在登录门

> 这一条我**直接提交到了 main**（`3f48b02c`），违反了"只允许通过功能分支合并"的规矩。
> 抢修时图快，事后记在这里，不掩盖。

## 现象

给中枢设了 token（为了手机远程访问）之后：**web 端打不开**，页面卡在登录门。

## 根因

上一轮我为了修"非 desktop 部署的面板在 `/hub` 上静默 401"，把代理改成**始终**附上中枢机器令牌。
结果它**覆盖**了浏览器带来的用户访问令牌：

```
直连中枢  /api/identity/me（带用户令牌）→ 200
走代理    /hub/api/identity/me（带用户令牌）→ 401 IDENTITY_TOKEN_MALFORMED
```

前端启动时会调 `/api/identity/me`（bundle 里确认有）⇒ 会话判定失败 ⇒ 整页卡住。

## 改法：转发身份分三条规则

| 调用方带的 `Authorization` | 代理该做什么 |
| --- | --- |
| **没有** | 附上中枢机器令牌（未登录的本机界面要能读） |
| **workbench 自己的令牌** | **换成**中枢令牌（它是本服务的凭据，对中枢无意义） |
| **用户访问令牌** | **原样透传** |

三者长得一样（都是 `Bearer …`），第二条只能靠"值与 workbench 自己的令牌相等"来判。

> 一个"替调用方决定它该用哪个身份"的代理，
> 与一个"把用户令牌换成机器令牌"的代理，区别只在有没有人登录过——
> 而那恰好是最难复现的那种坏。

## 判据

`workbench/scripts/desktop-auth.test.mjs` 4 条，三条规则各一条 + 原有用例。
真机复验：无令牌 200 · 用户令牌 `/hub/api/identity/me` 200（与直连一致）· 首屏三端点全 200。

★ 运行时**未重启宿主**即生效：杀掉 workbench 子进程后服务插件 2 秒内自愈拉起（新代码）。
