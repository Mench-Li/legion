# BUG-021｜Agent 状态更新**从不提醒我** —— 通知只数徽标，从不弹框

> 状态：**已修**（右下角弹框 + 页面不在前台时的系统通知）
> 发现：2026-10-10，将军原话「我记得要求 Agent 状态更新时给我消息提醒的，现在没有，
> 比如 T-196 待我验收了，但是没提醒我，我不知道，浪费了等待时间」
> 影响面：`workbench/src/App.tsx`（通知 effect）、`workbench/src/notify.ts`（弹框决策）、
> `workbench/src/components/Toast.tsx`（可点弹框）、新增 `workbench/src/desktopNotify.ts`

## 0. 现场

```
09:20:58  researcher  transition  {"to":"in_review"}   ← T-196 停在待验收等将军
……
（将军一直不知道，直到自己去看）
```

审计里那条事件**是有的**，通知中心列表里**也是有的** —— 缺的只有"来叫他"这一步。

## 1. 根因：通知这条线只做了徽标，没有做打扰

`App.tsx` 的那个 effect 拉到审计行之后，**只**做了一件事：

```ts
fetchHubActivity({ scope, limit: 200 })
  .then(rows => { if (!cancelled) setNotifyUnread(countNotifyUnread(rows, scope)) })
```

数一下未读数、点亮侧栏徽标。**没有 toast、没有声音、没有系统通知。**
而"将军盯着侧栏"恰好是最不可能的情形。

> 一个"有通知中心"的系统，与一个"到点了会来叫你"的系统，
> 在有人正好盯着侧栏的时候一模一样。

顺带一个更窄的事实：那个 effect 在 `active === 'notify'` 时**整段 return**（为避免与面板重复拉取），
所以哪怕它弹框，**打开通知中心时反而不会弹**。

## 2. 改法

### 2.1 弹框决策与游标（`notify.ts`，纯函数、可判据）

- `shouldPopup(item)`：**只弹高优先级**（复用既有 `notifyPriority` 口径：拦截/转派/测试报告/
  目标关键节点/进入 `blocked`·`in_review`）。弹框是**打扰**，门槛必须比"进列表"更高 ——
  一个什么都弹的提醒，等于没有提醒。
- `popupText(item, who?)`：一句话说清"哪个任务、要你做什么"：
  `⏳ T-196 待你验收（方案研究员）`。
- `popupBatch(rows, lastSeq, limit)`：挑出这一轮该弹的。三条纪律：
  1. **首次运行（无游标）只建立基线、不弹历史** —— 否则一打开页面就被 200 条历史糊一脸，
     而"被历史通知糊脸"的用户下一步就是把这个功能关掉；
  2. 升序弹（先发生先弹），超上限只留**最新**的几条，游标仍推进到最新（丢掉的进通知中心，不补弹）；
  3. 游标按**未过滤**的全量行推进（白名单外的 `progress`/`release-stale` 也在涨 seq）。
- **弹框游标与已读游标分开存**（`legion.notify.popupseq.<scope>`）。
  拿已读态当"弹过了没有"的游标会两头都错：用户点一次「全部已读」⇒ 下一条新事件不再弹；
  用户从不点 ⇒ 每次刷新都把历史重弹一遍。写入**只前进**（并发标签页里落后的一方不许把游标推回去）。

### 2.2 接线（`App.tsx`）

同一个 effect 顺带消费那批数据弹框 —— **不新开 SSE 连接**：这个 20s 轮询**本来就是**这条链路的
取数点，弹框只是终于消费了它。并且去掉了"面板打开就整段 return"，未读数那份跳过、弹框不跳。

### 2.3 可点（`Toast.tsx`）

弹框支持 `onClick`：一条"叫你过来处理"的消息如果点不动，用户还得自己去侧栏找那个面板 ——
那正是这条提醒本想省掉的一步。点弹框 ⇒ 直接进通知中心。

### 2.4 页面不在前台时的系统通知（`desktopNotify.ts`）

右下角弹框只在**页面可见**时有意义，而"物理离开电脑"正是这条需求的起因。
三条纪律：**绝不自动请求权限**（自动弹授权框会被拒，拒一次就回不来；请求放在通知中心的按钮里）、
**只在页面不可见时才发**（可见时弹框已经说过了，再发一条是重复打扰）、点了要 `focus()` 回窗口。

## 3. 顺手修掉的一个静默缺陷

`App.tsx` 的 `labelsRef` **从未被赋值**（只有声明与读取），于是 `labels` 恒为 `{}`，
凡是按它取名字的地方都退回了英文 `role`（任务列/智能体视图/弹框都受影响）。
编队里本来就带 `role` + 中文 `name`，用它填既不新增请求也不用再猜。

## 4. 验收（判据 + 真实数据）

- `workbench/scripts/notify-popup.test.mjs`（19 例，已登记进 `scripts/ci/run-ci.mjs`）：
  只弹高优先级（`in_review`/`blocked` 弹，`claim`/`artifact`/`progress`/`chat:*` 不弹）·
  文案含任务号与"待你验收"· 首次只建基线不弹历史 · 游标推进后不重弹 · 超上限只弹最新 ·
  空列表不推进游标 · 游标只前进 · 换空间换一把游标 · 系统通知只在"不可见 + 已授权"时发。
- **真实审计流回放**（同一天，`software` 空间 200 条）：

  ```
  真实事件：seq 59771  researcher  transition  {"to":"in_review"}
  场景 A（页面一直在用）：会弹 1 条 → 「⏳ T-196 待你验收」；游标 → 59863
  场景 B（刚打开页面）：会弹 0 条（只建立基线）
  场景 C（游标已推进）：会弹 0 条（不重弹）
  ```
- 构建已更新并由运行中的服务发出：`dist/index.html` 指向的 bundle 内含
  「待你验收」「开启系统提醒」「legion.notify.popupseq.」。

## 5. 判断句

> 一个"通知中心里躺着这条消息"的系统，
> 与一个"到点了会来叫你"的系统，在没人打开通知中心的时候，是两个系统。

## 6. 遗留

- 手机 PWA 那条路**还没有**同样的弹框（`workbench/mobile/`）。本次未做。
- 系统通知的授权按钮在**通知中心**里；通知中心需要先选具体空间才渲染 ——
  也就是说"从没选过空间"的人看不到那个按钮。可接受（那种状态下也没有空间可提醒），
  但若日后要更显眼，应放到设置页。
