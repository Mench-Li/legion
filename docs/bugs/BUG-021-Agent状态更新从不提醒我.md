# BUG-021｜Agent 状态更新**从不提醒我** —— 通知只数徽标，从不弹框

> 状态：**已修**（web/桌面端右下角弹框 + 手机端底部弹框 + 页面不在前台时的系统通知）
> 发现：2026-10-10，将军原话「我记得要求 Agent 状态更新时给我消息提醒的，现在没有，
> 比如 T-196 待我验收了，但是没提醒我，我不知道，浪费了等待时间」
> 影响面：`workbench/src/App.tsx`（通知 effect）、`workbench/src/notify.ts`（弹框决策）、
> `workbench/src/components/Toast.tsx`（可点弹框）、新增 `workbench/src/desktopNotify.ts`；
> 手机端 `workbench/mobile/app.mjs`、新增 `workbench/mobile/popup.mjs`、
> `workbench/mobile/index.html`（宿主与样式）、`workbench/mobile/sw.js`（预缓存清单）

## 0. 现场

```
09:20:58  researcher  transition  {"to":"in_review"}   ← T-196 停在待验收等将军
……
（将军一直不知道，直到自己去看）
```

审计里那条事件**是有的**，通知中心列表里**也是有的** —— 缺的只有"来叫他"这一步。

## 1. 根因：通知这条线只做了徽标，没有做打扰

`App.tsx` 的那个 effect 拉到审计行之后，**只**做了一件事：

```ts
fetchHubActivity({ scope, limit: 200 })
  .then(rows => { if (!cancelled) setNotifyUnread(countNotifyUnread(rows, scope)) })
```

数一下未读数、点亮侧栏徽标。**没有 toast、没有声音、没有系统通知。**
而"将军盯着侧栏"恰好是最不可能的情形。

> 一个"有通知中心"的系统，与一个"到点了会来叫你"的系统，
> 在有人正好盯着侧栏的时候一模一样。

顺带一个更窄的事实：那个 effect 在 `active === 'notify'` 时**整段 return**（为避免与面板重复拉取），
所以哪怕它弹框，**打开通知中心时反而不会弹**。

## 2. 改法

### 2.1 弹框决策与游标（`notify.ts`，纯函数、可判据）

- `shouldPopup(item)`：**只弹高优先级**（复用既有 `notifyPriority` 口径：拦截/转派/测试报告/
  目标关键节点/进入 `blocked`·`in_review`）。弹框是**打扰**，门槛必须比"进列表"更高 ——
  一个什么都弹的提醒，等于没有提醒。
- `popupText(item, who?)`：一句话说清"哪个任务、要你做什么"：
  `⏳ T-196 待你验收（方案研究员）`。
- `popupBatch(rows, lastSeq, limit, options)`：挑出这一轮该弹的。三条纪律：
  1. **首次运行（无游标）只建立基线**，但会**补告最近 6 小时内**真正需要你动手的事
     （见 2.1.1）—— 否则"刚装上这个提醒的人"恰好什么也看不到，而他最需要知道"现在有谁在等我"；
  2. 升序弹（先发生先弹），超上限只留**最新**的几条，游标仍推进到最新（丢掉的进通知中心，不补弹）；
  3. 游标按**未过滤**的全量行推进（白名单外的 `progress`/`release-stale` 也在涨 seq）。
- **弹框游标与已读游标分开存**（`legion.notify.popupseq.<scope>`）。
  拿已读态当"弹过了没有"的游标会两头都错：用户点一次「全部已读」⇒ 下一条新事件不再弹；
  用户从不点 ⇒ 每次刷新都把历史重弹一遍。写入**只前进**（并发标签页里落后的一方不许把游标推回去）。

### 2.1.1 首次为什么是"时间窗补告"，而不是"什么都不说"或"全量补弹"

第一版我写的是"首次只建立基线、**一条都不弹**"。写完立刻发现它还留着同一个病：
**刷新的那一刻 T-196 正停在待验收，而页面什么也不说** —— "我装了提醒"与"我还是不知道"
会同时成立。两个极端都错：

| 做法 | 后果 |
| --- | --- |
| 全量补弹 | 一打开页面就被历史糊一脸；"被历史通知糊脸"的用户下一步就是关掉提醒 |
| 完全沉默 | 装上提醒的那一刻恰好不说，而那时可能正有任务在等你（**第一版的错**） |
| **最近 6 小时窗** | 只说"你刚才大概不在"那段时间里、真正需要你动手的事 |

所以 `popupBatch` 收了 `replayWindowMs`（App 传 6 小时）。**窗口只对首次生效**：
游标一旦建立，窗内的旧事件也不再补弹（只有真正新发生的才弹）。未来时间戳（时钟漂移）不入窗。

### 2.2 接线（`App.tsx`）

同一个 effect 顺带消费那批数据弹框 —— **不新开 SSE 连接**：这个 20s 轮询**本来就是**这条链路的
取数点，弹框只是终于消费了它。并且去掉了"面板打开就整段 return"，未读数那份跳过、弹框不跳。

### 2.3 可点（`Toast.tsx`）

弹框支持 `onClick`：一条"叫你过来处理"的消息如果点不动，用户还得自己去侧栏找那个面板 ——
那正是这条提醒本想省掉的一步。点弹框 ⇒ 直接进通知中心。

### 2.4 页面不在前台时的系统通知（`desktopNotify.ts`）

右下角弹框只在**页面可见**时有意义，而"物理离开电脑"正是这条需求的起因。
三条纪律：**绝不自动请求权限**（自动弹授权框会被拒，拒一次就回不来；请求放在通知中心的按钮里）、
**只在页面不可见时才发**（可见时弹框已经说过了，再发一条是重复打扰）、点了要 `focus()` 回窗口。

### 2.5 手机端也加上（`workbench/mobile/popup.mjs` + `app.mjs`）

手机端**比电脑端更需要它**：电脑端至少有侧栏徽标在视线里，手机端用户多半不在看这个页面 ——
他把手机放在兜里或桌上，而"任务停下来等你验收"只有主动点开才看得见。

> 一个"任务页签上有个小红点"的手机端，
> 与一个"到点了会在你手机上弹一条"的手机端，
> 在用户把手机放下的那段时间里，是两个东西。

- **弹框落在输入区正上方**（手机上没有"右下角"可用；那是拇指活动区兼视线落点），
  整块可点 → 直接跳到那条任务（`openTask`）。
- **骑在同一次合并刷新里**（`refreshLoop` 的 `run` 里加 `await refreshPopups()`），
  **不单开计时器**：一帧事件已经是 5 个请求了，单开一条"每帧取一次审计"的路径
  换来的只是把同一条提醒弹三遍（手机流量与电量都是真的）。
- **自己的游标、自己的键**（`legion.mobile.popupseq.<scope>`，与桌面端 `legion.notify.popupseq.*`
  **不同**）：共用一个键会让"在电脑上看过"顺手把手机上的也吞掉。
- **系统通知**：页面不在前台时发（与桌面端同三条纪律：绝不自动请求、只在不可见时发、点了回窗口）。
  授权按钮是头部那个「🔔」，只在"支持但还没授权"时出现。

#### 为什么手机端是"另写一份纯 JS"，以及怎么防它漂移

手机端**零构建**（刻意不用 React/打包器，首屏要快），所以它不能 `import` 一个 `.ts`。
于是判据重写了一遍 —— 重写就会漂移，而漂移的样子是**"电脑上会弹、手机上不弹"**：
没人会去查，因为两端各自都"看起来正常"。

所以有一条**对等判据**（`workbench/mobile/popup.test.mjs`）：同一批审计行喂给
`mobile/popup.mjs` 与 `src/notify.ts`，逐条断言**该不该弹、弹几条、文案、游标推进值**完全相同；
状态中文表也逐字对。另有源码级接线判据：提醒必须骑在合并刷新上、授权只在点击时请求
（调用点只允许一个）、宿主容器必须在 DOM 里。做过变异测试：6 个变异**全部**能让判据变红。

> 一份"两端各自实现、靠人记得同步"的规则，
> 与一份"两端实现不同、但每次改动都被一条判据顶住"的规则，
> 在没人记得同步的那天之前，是一模一样的。

#### Service Worker 的预缓存清单（漏了会静默坏）

`sw.js` 的 `SHELL` 加了 `./popup.mjs`，缓存版本提到 `v3`（版本一变 `activate` 就删旧缓存）。
这不是可选项：漏了它，"装好 SW 之后立刻离线"会打不开页面 —— 而那正是 PWA 要守的场景。
有一条判据（`sw-shell.test.mjs`）**顺着 import 图走一遍**来核对，所以不会因为人忘记而漏。

## 3. 顺手修掉的一个静默缺陷

`App.tsx` 的 `labelsRef` **从未被赋值**（只有声明与读取），于是 `labels` 恒为 `{}`，
凡是按它取名字的地方都退回了英文 `role`（任务列/智能体视图/弹框都受影响）。
编队里本来就带 `role` + 中文 `name`，用它填既不新增请求也不用再猜。

★ 手机端**没有**这个问题：它从 `state.agents` 现取（`whoFor`），编队里本来就有中文名。

## 4. 验收（判据 + 真实数据）

- `workbench/scripts/notify-popup.test.mjs`（26 例，已登记进 `scripts/ci/run-ci.mjs`）：
  只弹高优先级（`in_review`/`blocked` 弹，`claim`/`artifact`/`progress`/`chat:*` 不弹）·
  文案含任务号与"待你验收"· 首次只建基线（窗口 0）· **首次 + 6 小时窗：窗内补告、窗外丢掉、
  未来时间戳不入窗、窗内也只看高优先级** · 游标推进后不重弹（窗内旧事件也不重弹）·
  超上限只弹最新 · 空列表不推进游标 · 游标只前进 · 换空间换一把游标 ·
  系统通知只在"不可见 + 已授权"时发。
- **真实审计流回放**（同一天，`software` 空间 200 条，当时 T-196 正等待验收）：

  ```
  真实事件：seq 59771  researcher  transition  {"to":"in_review"}   （约 40 分钟前）

  首次接入（游标 0 + 6 小时窗）：弹 1 条 → 「⏳ T-196 待你验收」；基线 → seq 59880   ★ 就是这一条
  窗口为 0（第一版行为）        ：弹 0 条 —— 装了提醒却什么也不说，等待照样被浪费
  游标已推进（再刷新一次）      ：弹 0 条 —— 不重弹
  ```
- 构建已更新并由运行中的服务发出：`dist/index.html` 指向的 bundle 内含
  「待你验收」「开启系统提醒」「legion.notify.popupseq.」。
- **手机端（公网隧道 + 用户令牌实测）**：

  ```
  /mobile/popup.mjs                       HTTP 200   no-store   6.8KB
  /api/activity?scope=software&limit=200  HTTP 200   1441ms     200 条   ← 用户令牌放行
  /api/board?scope&compact=1              HTTP 200   1515ms     162 条
  真实数据跑手机端：首次打开弹 1 条 → 「⏳ T-196 待你验收（方案研究员）」；再跑一次弹 0 条
  ```

  这一条**必须实测**：手机端取数是 `.catch(() => null)` 兜底的 ——
  若 `/api/activity` 不认用户令牌，手机上会**静默什么都不弹**（正是最难查的那种坏）。

## 5. 判断句

> 一个"通知中心里躺着这条消息"的系统，
> 与一个"到点了会来叫你"的系统，在没人打开通知中心的时候，是两个系统。

## 6. 遗留（要如实知道）

1. **手机端的系统通知只在页面还活着时有效**（后台标签/后台 PWA）。
   页面被彻底关掉之后要能收到，需要 **Web Push**（订阅入库 + 服务端推送）——
   本次**没做**。所以"手机完全不打开也能收到"这句话目前**不成立**；
   成立的是"手机开着这个页面（可以在后台）时能收到"。
2. **桌面端系统通知的授权按钮在通知中心里**，而通知中心要先选具体空间才渲染 ——
   "从没选过空间"的人看不到那个按钮。可接受（那种状态下也没有空间可提醒），
   但若要更显眼，应放到设置页。
3. 手机端的「🔔」授权按钮只在 `Notification` 可用且未授权时出现；
   **iOS Safari 未安装为 PWA 时不支持** `Notification`，此时按钮不出现（不给假希望），
   页面内的提醒照常工作。
