# BUG-028｜供应商列表把**引用名**发给了客户端（档案那边已经不发）

> 状态：**仅登记**（未修）。发现：2026-10-12，拆「配置迁移」时把一条既有判据
> （`config-bundle-routes.test.mjs` 用例 ④「整条链路上任何响应体都不含密钥字面量」）
> **扩容**到 `/api/model-providers`，当场报出两条：
> 一条是**我改出来的**（档案列表的 `credential.ref`，已修）、一条是**既有的**（本文件）。
> 影响面（修的时候要动）：`team-hub/routes/model-providers.mjs`（列表红色action）、
> `team-hub/provider-store.mjs`（update 时"没给就保留"）、
> `workbench/src/components/DshProvidersPanel.tsx`（编辑态保留引用的那段逻辑）

## 0. 一句话

`GET /api/model-providers` 的每一行都带 `secretRef` 原文，而档案那一族（`/api/model-profiles`）
**刚刚**被改成只发 `credential.hasRef` —— 同一个密钥库、同一套引用名，两个端点两种口径。

## 1. 现场证据

判据 ④ 的前置自检（`hasRef: true` 证明库里这一行确实有引用名）之后：

```
AssertionError: ★ 供应商那一行本身也不该把引用名带出去：
  `secretRef` 与 `credential.hasRef` 说的是同一件事，前者多给了名字
```

同一条判据抓到的另一半（**已修**）是我上一轮 BUG-023 引入的：档案列表把
`credential.ref` / `connection.credential.ref` 一起吐了出去。

## 2. 为什么值得修（而不是"反正要登录"）

本仓的纪律写在 `team-hub/model-store.mjs` 的文件头 ②，逐字是：

> `get(id)` 返回**抹掉 `secretRef`** 的 descriptor；`internalGet(id)` 才带它。
> 引用名也是**可枚举的攻击面**。

引用名不是密钥，所以这不是"泄漏了一把钥匙"。它泄漏的是**密钥库的槽位名**
（`FJD_DS_API_KEY`、`SVEA_DS_API_KEY`…）。两个真实后果：

1. **可枚举**：任何能读这一页的人可以列出这台机器上配了哪些凭证槽位；
2. **两份口径**：同一个库里同一种东西，档案端点抹掉、供应商端点不抹掉 ——
   而"按端点分别决定"正是纪律被忘掉的方式：

   > 一条"这个端点不吐引用名"的规矩，
   > 与一条"那个端点也吐了但它不是同一个端点"的解释，
   > 在下一个新增读端点的人看来是一样的。

## 3. 修它为什么不是一行红色action

面板**依赖**它保留编辑态：

```tsx
// DshProvidersPanel.tsx
const keyRef = editing?.secretRef ?? defaultKeyRef(id)      // :250
baseURL: form.endpoint.trim(), secretRef: form.key || editing?.secretRef ? keyRef : null,   // :262
```

即：用户只改显示名、没重新填密钥时，面板靠 `editing.secretRef` 把原名回传，
**不回传就等于把这条供应商的凭证清掉**。所以正确的修法是三处一起动：

1. **读**：供应商行的 `secretRef` 抹掉，只留 `credential.hasRef`；
2. **写**：`providerStore.update` 在**没给** `secretRef` 时**保留原值**
   （"没给"与"给了 null"必须是两件事——后者才是"清掉它"）；
3. **面板**：用户没重新填密钥时**不发送** `secretRef` 字段（而不是发一个从响应里
   读回来的名字）。

## 4. 判据怎么翻转

`config-bundle-routes.test.mjs` 用例 ④ 现在**显式断言了当前行为**
（`assert.equal(mine.secretRef, PV_REF)` 并附上"修 BUG-028 时这条要翻转成
`?? null`"），并在字节断言里对 `/api/model-providers` 做了**写明的**豁免。
修完这个 bug 时，这三处必须一起改——它们就是"这件事已经做完了"的信号。

## 5. 判断句

> 一个"要登录才能看"的字段，
> 与一个"登录之后就不必再管"的字段，
> 在**谁来读这一页**这件事上是两回事；
> 而在**纪律是否还成立**这件事上是同一回事。
