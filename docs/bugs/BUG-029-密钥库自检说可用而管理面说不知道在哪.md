# BUG-029｜同一个密钥库：自检说"可用"，管理面说"不知道密钥库在哪"

> 状态：**仅登记（未修）** —— 修它要裁决"只读路径是否该因为一条**验不了**的不变量而失败"。
> 发现：2026-10-12，收尾重录既有红的基线时，`team-hub/secret-routes.test.mjs` 的 ② 报了
> `503 !== 200`。**它不是基线过期**（我一开始把它列进"重录一下"那一类）。
> 影响面：`team-hub/routes/secrets.mjs`（`GET /api/secrets`）、
> `product/paths.mjs` 的 `SECRETS_BLOCKING_DIAGNOSTICS`、
> 判据 `team-hub/secret-routes.test.mjs` ②

## 0. 现场（2026-10-12，本机，未设任何 `LEGION_*`）

同一个进程、同一个 `createHubSecretAdmin({ env: process.env })`：

```
probe.describe()          → { ok: true, code: 'SECRETS_OK',
                              message: '密钥库可用（scheme=dpapi-user，已录入 3 条）…',
                              path: 'C:\\Users\\11150\\AppData\\Local\\Legion\\secrets\\credentials.json' }

GET /api/secrets/status   → HTTP 200   { ok: true, status: {...} }
GET /api/secrets          → HTTP 503   { code: 'SECRET_ADMIN_STORE_UNAVAILABLE',
                                         error: '无法管理凭证：产品目录布局里与密钥库有关的部分没确定，
                                                 因此不知道密钥库该放在哪。（INSTALL_DIR_UNRESOLVED）' }
```

即：**它明明知道密钥库在哪（还给了绝对路径），却在另一个入口说"不知道密钥库该放在哪"。**

## 1. 根因：两条读路径问的不是同一件事

`product/paths.mjs` 的 `SECRETS_BLOCKING_DIAGNOSTICS` 里每条都有理由（那份文件写得很清楚），
其中 `INSTALL_DIR_UNRESOLVED` 的理由是：

> `assertSecretsPlacement` 要用安装目录判"密钥不在安装目录内"；拿不到它，这条不变量就**验不了**
> （不是"验过没问题"）。

于是：
- `describe()` / `/api/secrets/status` —— 只答"库能不能打开、有几条"，**不验**那条不变量 ⇒ 200；
- `GET /api/secrets`（管理面：列条目 / 写条目）—— 要验 ⇒ 拿不到安装目录 ⇒ 503。

**两条都对**（各自的口径都成立）。问题是：

- 判据 ② 假设"`describe()` 说 ok ⇒ 路由必须 200"，于是它把这种差异读成"路由没把真实结论送出来"；
- 而用户看到的是**"凭证库"页打不开**，同时**钥匙好端端躺在本机**（3 条）——
  503 的文案还说是"不知道密钥库该放在哪"，与 `describe()` 给的路径直接矛盾。

> 一句"不知道它在哪"的错误解释，
> 与一次"验不了那条不变量"的拒绝，在用户那里是两件完全不同的事：
> 前者让人去查布局，后者只要说清"有一条安全不变量这次验不了"。

## 2. 要裁决的那一个问题

| | 只读（列出条目） | 写（录入/轮换/删除） |
| --- | --- | --- |
| **今天** | 因 `INSTALL_DIR_UNRESOLVED` 被挡（503） | 同上 |
| **选项甲**：只读放行、写仍挡 | 用户看得到自己的钥匙；文案说清"那条不变量这次没验" | 保持保守：写进去可能落到只读程序区 |
| **选项乙**：维持现状 | 一致（都挡） | 一致 |

倾向**选项甲**，但这条**不**由我单方面改：它动的是"安全不变量验不了时怎么办"的口径，
而那个口径是这一族存在的理由本身。

## 3. 修的时候一起动的三处

1. `team-hub/routes/secrets.mjs` 的 `GET /api/secrets`：读/写分开判（若选甲）；
2. **503 的文案**：不许说"不知道密钥库该放在哪"——它知道（`describe()` 有 `path`）。
   应当说"这条不变量这次验不了：密钥是否落在安装目录内"，并把 `path` 一并给出；
3. 判据 `secret-routes.test.mjs` ②：把"`describe()` ok ⇒ 200"改成
   "`describe()` ok **且** 阻断集为空 ⇒ 200；否则 503 且 code 与阻断集一致"——
   两个入口问的不是同一件事，判据要按**实际的**口径写，而不是按"应该一致"的直觉写。

## 4. 判断句

> 一个"我这次验不了这条不变量"的拒绝，
> 与一个"我不知道东西在哪"的拒绝，在状态码上是同一个 503 ——
> 而在**用户下一步该做什么**上是两件事。
