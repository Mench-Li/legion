# BUG-031｜凭证库**不是**运行时钥匙的来源 —— 而界面从前不说这件事

> 状态：**面板那一半已修**（2026-10-12）；**物化那一半仍关着**（要业主裁决，见 §5）。
> 起因：将军问了一句「凭证库又是干嘛的」。查完发现它**不是**配置包那种纯冗余
> （见 `BUG-028` 之后拆掉的配置包：那份东西被备份严格覆盖），而是**真实有用、
> 但被界面说成了另一件事**。
> 影响面：`workbench/src/components/DshProvidersPanel.tsx`、`team-hub/runtime-credential.mjs`（新）、
> `team-hub/routes/secrets.mjs`、`team-hub/routes/model-providers.mjs`、`product/dsh-location.mjs`。

## 0. 一句话

**Legion 的凭证库有真实的活（"测试连接"读的就是它），但它不是让任务跑起来的那把钥匙。**
后者在 **DSH 自己的**凭证库里。而在此之前，界面上**只有前者的读数**。

## 1. 实测（2026-10-12，本机）

### ① 派工那条路**一个凭证字段都没有**

```
plugins/src/index.ts:1274   agentOptions: { provider: selection.provider, model: selection.model }
（该文件里 apiKey / secretRef / credential 出现 0 次）
```

### ② 真正让 agent 跑起来的钥匙在 DSH 那边

DSH 自己的凭证分层是**写在它源码里的四层**
（`packages/credentials/credentials-local/src/index.ts` 的模块头、`packages/util/home-paths/src/index.ts` 的 `resolveDshHome`）：

```
宿主环境（继承来的，只读，赢）
> $DSH_HOME/.credentials.yaml      （provider 管理、可写）
> <启动目录>/.env                  （只读回退）
> $DSH_HOME/.env                   （只读回退）
```

本机 `~/.dsh/.credentials.yaml` 里有 **8 个引用名**（含 `FJD_DS_API_KEY` / `SVEA_DS_API_KEY`）。

### ③ Legion → DSH 的那条写路径（物化）**门是关的**

```
services-plugin/config-schema.mjs  applyModelConfig  默认 false（真实配置里是 undefined）
services-plugin/materializer.mjs   "① 门（gate）：`enabled` 为假 ⇒ 一个字节都不写，直接返回'未接管'"
```

也就是说：**Legion 这边的值不会自动送过去。**

### ④ 于是同一把钥匙在两处各存一份，而有一份是孤儿

| Legion 库里的名字 | 指向它的供应商 | DSH 里也有吗 | 谁在用 |
| --- | --- | --- | --- |
| `FJD_DS_API_KEY` | `fjd-ds` | **有** | 全部 17 条岗位绑定 |
| `SVEA_DS_API_KEY` | `svea-ds`（没有任何绑定用它） | **有** | 没人 |
| `SVEA_DS_1_API_KEY` | **没有任何供应商指向它** | **没有** | **孤儿** |

那个孤儿是这么来的：`DELETE /api/model-providers/<id>` 从前只删那一行、**完全不碰密钥**。

### ⑤ 而 Legion 的库确实有活（不是"没用"）

点火一次真调用（就是面板那个「测试连接」按钮，它读的是 **Legion 库里的值**）：

```
POST /api/model-profiles/fjd-ds-deepseek-v4-flash-openai/probe → HTTP 200
  ok = true   code = "OK"   message = "连通且具备所需能力"
```

⇒ 它的价值是：**在派工失败之前就知道钥匙是坏的**。

## 2. 那个陷阱（本条最重要的部分）

> 往 Legion 里录一把 DSH 没有的钥匙，面板会说"已核验"、连"测试连接"都可能通过，
> **而任务跑不起来**。

表现是「界面全绿、任务认证失败」，而界面上没有任何东西指向真因。

> 一个"我这边的库里有"的读数，
> 与一个"跑起来真的能用"的读数，在界面上说的是同一句话 ——
> 而它们的修法是完全不同的两件事。

## 3. 修了什么

### ① 面板现在有两个并列的读数（而不是一个）

| 读法 | 回答的问题 |
| --- | --- |
| `credential.state`（原有） | **Legion 自己的库**里有吗 |
| `credential.runtime`（新） | **跑起来的那个进程**取得到吗 |

新那一格是**三值**：`present` / `absent` / `unknown`（读失败**绝不**降级成"没有"，
与 `credential-status.mjs` 的纪律 ① 同族）。

真机读数（重启后）：

```
deepseek-account   Legion库=none     运行侧=not-needed
deepseek-official  Legion库=missing  运行侧=present   ← 两格互补：库里没有、运行时可用
fjd-ds             Legion库=ready    运行侧=present
svea-ds            Legion库=ready    运行侧=present
```

`deepseek-official` 那一行正好说明**为什么必须两格都有**：只看前一格会让人去补一把
运行时其实已经能用的钥匙。

### ② 为什么这一格能给出**精确**答案（而不是猜）

中枢是**由宿主带着 `{...process.env}` 拉起的**（`services-plugin/config-schema.mjs` 的 notes），
所以 DSH 分层的**第一层**（宿主环境）与**第二层**（凭证文件）都能逐一复现 —— 是同一组输入。

**没查的那一层写进 detail**：第三层 `<启动目录>/.env` 是 DSH **进程的 cwd**，中枢看不到。
所以 `absent` 的措辞是"**这两处**都没有找到"，并把没查的那一层说出来。

> 本仓对这件事有先例（`credential-status.mjs` 纪律 ①「读不出来 ≠ 没有」）。
> 本条多一条同族的：**"我没查那一层"也不能说成"那一层没有"。**

### ③ 一个必须分开的决策：`~/.dsh` 要不要猜

`product/launcher/cli.mjs` 的 `dshCredentialsFileFrom` 刻意**只认 `DSH_HOME`、不猜路径**
（PRT-509 路线 A′）——那条口径服务的是**读值**：猜错的家目录会把别人留下的凭证文件
当成自己的。

但**实测这个部署的宿主环境里没有 `DSH_HOME`**（用户直接开 `DeepSeek Harness.exe`），
而 DSH 自己的优先级是 `显式 > $DSH_HOME > ~/.dsh` ⇒ 它落地在 `~/.dsh`。
只认环境变量就等于在这种部署上**永远回"不知道"**。

⇒ 拆成两个函数（`product/dsh-location.mjs`）：
`dshCredentialsFileFrom`（只认环境变量，读值用）与 `dshCredentialsFileForStatus`
（允许回落到 DSH 的默认，回答状态用），**并且回落必须说出来**：

```
…（这个位置是按 DSH 的默认 `~/.dsh` 推出来的：宿主环境里没有 `DSH_HOME`）
```

> 一条为了"别拿错钥匙"而定的规矩，
> 与一条为了"回答状态"而定的规矩，在"要不要允许回落"上必须分开 ——
> 否则你会用前者的理由，去接受后者的沉默。

### ④ 孤儿清理（两条，都不动你正在跑的 DSH）

- **删供应商时可以连钥匙一起删**（`deleteCredential: true`），三条纪律各一条判据：
  ① 默认不删；② **共享引用要拦住**并点名是谁（"顺手也删了"会让别人下次运行才失败）；
  ③ 删不掉时说清"**供应商已删、钥匙没删**"，而不是笼统报失败。
- **凭证库列表标出孤儿**：`claimedByProvider`。措辞是"**没有任何供应商指向它**"，
  **不是**"没人在用"——那把钥匙也可能正被手工脚本或 DSH 自己的配置用着。

## 4. 今天该怎么做（给用户的话）

1. 看「供应商与模型」页那一列**运行侧**；
2. 哪一条是「运行侧没有」，就到 **DSH 的模型设置页**把钥匙也配上 —— **不是**在这里再填一遍；
3. 库里那些标着「没有供应商指向它」的条目，确认没用之后可以在「凭证库」页删掉。

## 5. 还没做的那一半（要裁决）

**把物化的门打开**（`LEGION_APPLY_MODEL_CONFIG=1`）让 Legion 的库真正成为权威 ——
那才是 `docs/DECISION-legion-owns-model-config.md` 的 P3 本意。

**没有单方面打开**，因为它会**真的写你的 DSH 配置**，一旦写错影响的是你现在能跑的那套。
与 `BUG-027` 的次序一致：先把读数做成看得见的，再由业主决定什么时候动写入。

## 6. 判断句

> 一个"我存进去了"的读数，与一个"它真的会被用上"的读数，
> 在界面上往往长得一模一样 ——
> 而区分它们不需要新功能，只需要**多问一次那一侧到底有没有**。
