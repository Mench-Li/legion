# BUG-034｜"它会自己补上的默认值"被当成了差异，于是那扇门依旧开着不了

> 状态：**已修**（2026-10-12；**2026-10-13 补第二处**，见文末 §5）
> 影响面：`services-plugin/materialize-plan.mjs`（两侧模型的比较语义）
> ＋ `services-plugin/dsh-snapshot.mjs`（`declaredInSettings` 的判据）
> 判据：`services-plugin/shadow-materialize.test.mjs` ③c（三条）、
> `services-plugin/provider-import.test.mjs` ③b（三条）

## 0. 一句话

Legion 侧**没声明** `input`（归一化成 `null`）、而 DSH 侧因为引擎的默认值报了
`input: ['text']` —— 比较把这一对当成差异。**而写进去也不改变任何东西**
（物化不带 `input`，DSH 照样落 `defaultInput`）⇒ 它唯一的后果是
**每 5 分钟重写一次、永不收敛**，而门禁的放行条件恰恰是"连续几轮 diff 为空"。

## 1. 因果链（读 DSH 源码得出，不是猜）

```
svea-ds 的 patch 里模型没声明 input
  ⇒ packages/llm/llm-pi-ai/src/config.ts：modelFields.input **没有默认值**
     （注释原话："No explicit default… schemastery materializes `[]` for an absent array,
      and resolution reads that as 'no answer here' so the catalog entry below still applies."）
  ⇒ 解析回落到路线级 defaultInput = DEFAULT_INPUT = ['text']（config.ts:80/336/454）
  ⇒ adapter.ts:276-287 `listModels()` **总是**报 `inputModalities: [...model.input]`
  ⇒ dsh-snapshot 把 inputModalities 收成 `input` ⇒ 快照带上 `['text']`
  ⇒ Legion 侧没有 ⇒ `normalizeInput(undefined)` = `null`
  ⇒ null ≠ ['text'] ⇒ **永久报一处差异**
```

对照锚（为什么 `fjd-ds` 是干净的）：它的 patch **显式**声明了 `input: [text, image]`，
Legion 侧也有同一份 ⇒ 两侧表态相同 ⇒ 不算差异。
**⇒ 差异只出现在"DSH 补了默认值、而 Legion 没表态"的那一格上。**

## 2. 修法与口径

`materialize-plan.mjs` 新增 `modelDiffers()`：**Legion 侧为 `null`（未声明）的字段不参与比较**。

这与 `provider-store` 的更新语义是**同一条**：**留空即继承，不覆盖**。
用户没在 Legion 里声明 `input`，不等于"他要一个没有输入能力的模型"——
那只是"他没表态，让它继承引擎的默认"。

  > 一处"它会自己补上"的默认值，与一处"它真的不一样"的差异，
  > 在 `models` 这一格上是同一行；
  > 而前者永远消不掉 —— 于是那道门永远开不了。

⚠ **两个值必须可分辨**，否则这条规则会吞掉真实意图：

| Legion 侧 | 归一化结果 | 判定 |
| --- | --- | --- |
| 没声明 `input` | `null` | **不比较**（继承引擎默认） |
| 显式 `input: []` | `[]` | **仍然是差异**（"我要清空它"是表态） |
| `input: ['text']` vs `['image']` | 两侧非 null 且不同 | **仍然是差异** |

判据 ③c 把这三个方向都钉住了。

## 3. 顺带消掉一个**分叉隐患**（正是 BUG-033 的形态）

修之前，"未变"用指纹（`fingerprint`）判定，而"改了哪个字段"用 `changedFields`
**另算一遍** —— 同一个事实写在两处。这次的改动如果在其中一处漏掉，
就会出现"报未变、同时又报 `models` 变了"这种自相矛盾的读数。

⇒ 现在两者**共用** `sameAs()` / `modelsEqual()`。判据 ③c 里那条反向锚
（`changedFields(...)` 必须返回 `[]`）就是为了钉住"不会分叉"。

  > 一处被实现两遍的判定，与一处被判定的语义，
  > 只在有人改其中一处的那天分叉 —— 而那天的症状是**读数自相矛盾**，
  > 不是报错。

## 4. 修复后的预测与实测

用真实数据（Legion 走中枢 API、DSH 侧按 patch 声明 + 默认值规则复现）先算了一遍：

```
counts = {"create":0,"update":0,"delete":0,"unchanged":2}
clean  = true
engineInternal = ["deepseek-account","deepseek-official"]
```

```
供应商影子对账：新增 0 / 修改 0 / 删除 0 / 未变 2（clean=true）；
**不接管**（端点由引擎内置、Legion 读不到，**任何东西都不许写它们**）：deepseek-account, deepseek-official
```

## 5. 第二处（2026-10-13 → 10-14）：`declaredInSettings` 判据连改三版

给 `deepseek-official` 补上真实端点（为了让「测试连接」能用，见 BUG-032）之后，
影子对账**立刻**报了一处永久差异：`update: [{deepseek-official, [api, baseURL]}]`、`clean=false`。

根因在 `dsh-snapshot.mjs` 的 `declaredInSettings`——它想回答"这条供应商的 api/baseURL
是**用户写的**还是**引擎默认的**"。三版判据、两次踩坑：

```js
// ① 首版：引擎登记了自己 ⇒ 当作"用户声明了"
declared.some((d) => d?.provider === p.id)

// ② 第二版：那一节里有受管字段的真值 ⇒ 当作"用户声明了"
['api','baseURL','apiKeyEnv'].some((k) => typeof profile[k] === 'string' && profile[k] !== '')

// ③ 第三版（现行）：**结构**——这一节里有没有一块以它命名的条目
path[path.length - 1] === providerId   ||   typeof profile?.[providerId] === 'object'
```

**首版的坑**：`llm.listConfigurableProviders()` 会列出**每一条内置路线**
（它们都登记自己、带 `settingsNs`）⇒ `deepseek-official` 被判成"有声明"。

**第二版的坑**（先从活体现象定位、再从 DSH 源码确认）：`settings.describe()` 每个命名空间
返回**三层**（`packages/settings/settings/src/index.ts:302-331`）：

```ts
value = projectForm(form, plainConfig(entry.fiber.config))  // ← 生效值，**含引擎默认**
base  = 继承来的
user  = projectForm(form, override)                          // ← **用户真正写的那一份**
```

而快照读的是 `value`。`deepseek-official` 报的 `settingsNs` 是 `llm-deepseek`，
那一节的 `value` 里有引擎默认的 `baseURL`（非空字符串）⇒ 第二版判据命中的是**引擎默认值**。
（另有一种同样能骗过它的形状：某个**别人的**命名空间里出现了这个名字——这台机器上
`web` 节的 `searchProvider: deepseek-official` 就是。）

  > 引擎把默认值投影进 `value` 之后，
  > "用户写了这一块"与"引擎替它补了这一块"在**值**上再也分不出来 ——
  > 它们只在**结构**上还分得开。

**第三版**只问结构：① `settingsPath` 末段就是它自己，或 ② 下钻出来的那一节里有一个
**以它命名的对象**（`{ providers: { 'fjd-ds': {...} } }` 那种形状）。都不满足 ⇒ `false`
⇒ 下游按"不接管"处置（不比较、不写、也不进删除候选）。

判据：`provider-import.test.mjs` ③b **五条** —— 引擎登记了但节是空的 ⇒ false；
有自己的声明块 ⇒ true（含空块）；**真原因形状**（value 是引擎默认投影）⇒ false；
**另一种形状**（别人的节提到它）⇒ false；**端到端**（Legion 记了真端点 + 引擎默认）
⇒ `engineInternal`、`clean=true`、`update=[]`、`delete=[]`。

⚠ 与 §2 那条是**同一个家族**：都是"引擎侧的值 Legion 读不到"，
处置都是"不许把它读成差异"。区别只在读不到的位置不同 ——
前一次是**模型字段**（`input`），这一次是**整条供应商的字段**。

⚠ 这条改动要**重启宿主**才生效（插件模块在宿主进程内，配置热重载不重载 ESM）。
在重启之前，运行中的旧判据仍会为 `deepseek-official` 报一处 `update` ——
`applyModelConfig` 是关的，所以**什么都不会被写**。

⚠ **重启后要看的不是"clean 了没有"这一件事**，还要看 `engineInternal` 里
**只有 `deepseek-account`**、而 `fjd-ds` / `fjd-gpt` / `svea-ds` 仍在正常比较里
（`unchanged` 计数）——否则说明第三版把**该管的**也误判成"不接管"了，
而那会让 P3 接管整块失效。这是第三版唯一需要盯的风险点。
