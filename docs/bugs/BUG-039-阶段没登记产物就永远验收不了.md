# BUG-039：阶段没登记产物，任务就永远验收不了

## 现象

T-218（编码实现·返工第 3 轮）2026-10-23 就跑完了：隔离分支 `w/T-218` 上提交 `073ba1c6`，
19 个目标相关套件 359/359 通过、`tsc --noEmit` exit 0。任务停在 `in_review`，
下游 T-219（代码审查）`blockedBy=T-218`，两条任务一起卡了 5 天。

点「验收通过」（`POST /api/transition {to:"done"}`）返回 409：

```
阶段 implement 没有可冻结的已登记文件产物
```

## 根因

`transitionTask → done` 会调 `freezeHumanAcceptedWorkflowStage`，后者无条件调
`commitAcceptedWorkflowArtifacts`；那个函数在**产物表为空**时第一句就是
`fail('阶段 X 没有可冻结的已登记文件产物')`。

但产物表是**可选**的：worker 的实现成果提交在 `w/<任务id>` 上，而没有任何东西保证
它还会去调一次 `/api/artifact`。于是「活干完了、提交也在、只是没登记产物」这一种
完全正常的状态，在验收那一下变成一个 409 —— 而错误只出现在按下按钮的那一刻：

- 任务永远停在 `in_review`；
- 它 `blockedBy` 的下游（这里是 T-219）永远不解除阻塞；
- 看板上只表现为「不动」，没有任何可查的错误。

> 一个「工作已经提交、只是没登记产物」的阶段，
> 与一个「什么都没产出」的阶段，在验收按钮上返回了同一个 409。

## 修复

`team-hub/accepted-workflow-checkpoint.mjs`：

- 产物表非空：行为不变（只提交登记过、摘要对得上的文件）。
- 产物表为空：冻结**本任务分支的 HEAD**（`pinCleanStageHead`）。前提照旧严格：
  工作区必须是本任务的独立 worktree、分支必须是 `w/<任务id>`、且**工作区干净**。
- 工作区脏时不静默照 HEAD 冻结（未提交的改动不在 HEAD 里，冻结它们等于从交接中丢掉），
  但错误改成说清两条出路：「先提交这些改动，或登记对应产物」。

## 验证

- `node --test team-hub/accepted-workflow-checkpoint.test.mjs`：13/13 通过，新增 3 条判据
  （空产物 + 干净工作区 ⇒ 冻结 HEAD；空产物 + 脏工作区 ⇒ 拒且报出两条出路；空产物 + 非本任务分支 ⇒ 拒）。
- `node --test team-hub/accepted-workflow-checkpoint-http.test.mjs`：2/2 通过，新增一条
  端到端判据（`in_review` + 空产物 + 干净工作区 ⇒ 200，checkpoint 的 `sourceCommit` 等于 HEAD、`artifactPaths` 为空）。
- `node --test team-hub/pipeline.test.mjs`：25/25 通过（验收/交接链未回归）。

## 现场处置（T-218）

线上那一条不是等这次修复，而是先按原路径补齐：登记两份产物（带 SHA-256）→ 验收通过，
checkpoint 冻结在 `073ba1c6`。修复之后，同样的阶段即使不登记产物也能验收。
