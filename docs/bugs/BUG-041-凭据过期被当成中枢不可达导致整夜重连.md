# BUG-041：凭据过期被当成「中枢不可达」，页面重连了一整夜

## 现象

2026-10-30 09:12，指挥台（`http://127.0.0.1:5173/`）整页停在：

```
✕ 无法连接中枢 /hub
错误：401：访问令牌已过期，请刷新
自动重连已开启：第 3 次重试，间隔 5 秒。也可以立即重试。
```

而中枢本身是好的：`/api/board`、SSE、守护心跳全部正常（心跳每 30 秒一条）。

## 根因

三处叠在一起，每一处单独看都"很合理"：

1. **访问令牌会过期，而页面只等不换。** 浏览器里那把令牌（`sessionStorage['legion.identity.access']`）
   过期于 `2026-10-29T11:14Z`（约 14 小时前）；对应的刷新凭据虽然还有效，
   但刷新只在启动时尝试一次。
2. **没有刷新凭据时，死令牌不被清掉。** `recoverSession()` 开头是
   `if (getRefreshToken().length === 0) return false` —— 直接返回，
   那把已经作废的访问令牌继续留在 sessionStorage 里，之后**每一个**请求都被它带着再 401。
3. **界面把 401 当成"中枢不可达"。** 看板加载循环 `catch` 里不分类，一律
   `setHubRetryInfo` + 每 5 秒重连；重连再多次也还是同一个 401。

于是：一个开着过夜的标签页，从令牌过期那一刻起就永远在原地打转；
界面上那句"自动重连已开启：第 N 次重试"看起来像在努力，其实是死循环。

## 修复

- `workbench/src/identity.ts`：没有刷新凭据、但有访问令牌时，**清掉那把死令牌**并通知登录门
  （`expiredHandler`）。本机/桌面部署没有用户令牌 ⇒ 行为与改动前逐字相同。
- `workbench/src/api.ts`：
  - `fetchWithSessionRetry` 在 401 后**无论救没救回来都重放一次**（从前是"救不回来就把 401 交回去"）。
    清掉死令牌后这一次重放会走机器令牌；远端 Hub 则拿到一次干净的 401。
  - `hubRequest`（通用读写）补上同一套抢救——它从前**完全没有**会话抢救，
    任何走它的读写拿到 401 都直接把过期凭据的错误抛给界面。
- `workbench/src/hub-errors.ts`：新增 `isAuthFailure(e)`，只认具名码
  （401，或带 `IDENTITY_*` 码的 403），不把空间越权之类混进来。
- `workbench/src/App.tsx`：加载循环把凭据失败**挡在重连之外**——不排重连，
  文案改成"登录已过期，请重新登录"，错误面板换一块（不再给人"去检查中枢"的错误指引），
  按钮变成"重新加载页面"。

## 遗留

- 刷新凭据仍是**轮换**的：两个标签页各持一份时，后刷新的那个会把前一个的凭据作废。
  本修复让失败方落到"清干净 + 重新登录"，不再死循环；要彻底消除同源多标签争用，
  需要把刷新改成"同一浏览器内单飞"（BroadcastChannel/locks）——没有在这次做。
- 页面仍不会自动重连 SSE 之外的长时间空闲；不过令牌过期这条路径现在会明确要求重新登录。
