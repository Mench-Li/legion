# BUG-044：返工改了契约文档，下游两环就永久卡在"上游产物摘要已变化"

## 现象

目标 `G-mw34jokf-2`（账号管理）走完了需求 → 接手结算 → Codex 初审 → 两轮返工 → Codex 复审通过，随后：

```
T-306 tester  ⛔ 工作流上游版本核验失败，已停止自动派工：
   Error: 上游阶段产物摘要已变化：docs/FEATURES.md
   （期望 dae3ac40713ed0b2d6382fc7a9b350776e8ad45acff2173debece8415a78365a）
T-307 devops  ⛔ 同一个错误
```

两环都没开工，直接停在 `in_review`。

## 根因

1. 链发布时按契约把 `docs/FEATURES.md` 登记为上游产物，并**冻结摘要** `dae3ac40…`；
2. 返工（T-308 / T-310）按 docSync 要求更新了 `docs/FEATURES.md`（实现变了，手册必须同步——这正是我们要的行为）；
3. tester / devops 派工前会核验上游产物摘要（`plugins/src/index.ts` 的 `verifyAgentWorkflowInputs`）：
   ```ts
   if (fileDigest(target) !== artifact.digest && workflowArtifactDigest(target) !== artifact.digest) {
     throw new Error(`上游阶段产物摘要已变化：${artifact.path}（期望 ${artifact.digest}）`)
   }
   ```
4. 冻结摘要 vs 返工后的文件 → 必然不一致 ⇒ 下游永久拒绝派工。

> 一个"改对了反而卡死"的闸门，
> 与一个"改错了也放行"的闸门，区别只在于它拦的是谁——代价是：**合规的返工永远到不了部署**。

## 影响面

任何带 `docSync`（或契约文档被返工触及）的目标，只要发生一次返工，`tester`/`devops` 两环就永远走不过去。也就是说：**返工链条的后半段实际上不可达**。

## 修复方向（待实现，本次只记录）

- **A（推荐）**：返工结算时，把被改动的契约文档按**新摘要**重新登记（滚动版本），下游核验按"最新一次登记"比对，而不是发布时的冻结值；
- **B**：核验失败时不要静默停住，写明"哪个文件、期望/实际摘要、建议重新登记产物"，并把这条提示同时写进任务评论；
- **C**：把"上游产物完整性"与"上游产物版本"分开——返工后的下游应比对**返工提交**的摘要，而不是发布时的快照。

## 复现

```
POST /api/goal { adoptFrom: T-224, startAt: implement, workflowDefinition: v4, docSync: true }
→ settle 实现环 → codex 审查不通过 → 返工（改 docs/FEATURES.md）
→ tester 派工即失败：上游阶段产物摘要已变化
```
