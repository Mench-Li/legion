## 结论与教训

本条为陈述性/事实性结论，均以验收时逐条对照 serve.mjs 源码为依据：

- 启动与远程访问：服务以 node legion/scrum/serve.mjs --port 4820 --host 0.0.0.0 --token <t> 启动；--host 缺省 127.0.0.1；--port/--host/--token 另有环境变量等价项 DSH_KANBAN_PORT / DSH_KANBAN_HOST / DSH_KANBAN_TOKEN。
- 令牌鉴权语义：配置令牌后有三种携带方式（Bearer 头、x-dsh-token 头、?token 查询参数，见 authorized()）；未配置 --token 时写操作直接放行，/api/config 返回 {auth,host,port}——即默认不鉴权，不要按「默认拒绝」假设。
- 错误与访问控制：写操作统一经 handleWrite 映射错误——401、409（乐观锁字样）、400；GET 端点开放；CORS 为 * 并支持 OPTIONS 预检。
- 字段契约：/api/create 中 title 必填、acceptance 以 ';' 拼接；/api/transition 的请求字段 id/to/by/ifVersion/force 与 serve.mjs 命令行拼装 transition id --to --by --if-version --force 一一对应。
- 决策判断：这类「补写文档/接口行为」经验能成立的前提，是以实现源码为唯一事实源并逐条对照验收（本任务即如此核对 authorized()、handleWrite、argv 拼装）；落档时保留源码锚点，后续任务可据此直接引用，无需重读 serve.mjs。派工因 provider 名错误被打回只说明派工配置有误，不改变任务目标与验收口径——修复后继续原任务即可。

## 适用场景

- 参考：后续涉及 legion/scrum/serve.mjs 写回接口调用、远程访问与令牌配置（--host/--token/DSH_KANBAN_* 环境变量）、401/409/400 与 CORS 行为判断或排障、README「写回接口与远程访问」一节修订复用，或需快速确认真实语义而不想重读源码时，应先取本条作为锚点。
