# Web 与桌面共享后台

Web 和桌面是同一产品的两个入口，使用同一个 DataDir、同一份数据库和同一组后台进程。后打开的入口验证并连接现有后台，不另外启动一套服务，也不通过改端口创建第二套数据。

## 使用

- Web：使用 `scripts/legion-up.ps1` 或 `product/launcher/cli.mjs` 启动，打开输出的 Workbench 地址。启动脚本会在端口选择、体检和运行时安装之前尝试连接现有后台。
- 桌面：正常打开。已有后台时优先连接；没有后台时按现有首次设置和运行时准备流程启动。
- Windows 默认产品目录为 `%LOCALAPPDATA%\Legion`，默认 DataDir 为其中的 `data`。安装版桌面不再另外指定 Electron userData 下的产品目录。显式设置 `LEGION_HOME`、`LEGION_DATA_DIR` 时，两端必须使用相同值。
- 不显式指定工作区的连接入口可使用已运行后台的工作区；显式指定不同工作区时拒绝连接。不能用同一个 DataDir 同时运行两个工作区。
- `node product/launcher/cli.mjs --connect-existing` 只连接，不启动。没有后台时退出码为 11，后台验证或连接失败为 5；成功为 0。普通参数、布局和配置错误沿用原退出码。支持 `--json` 查看当前服务地址。

## 退出与停止

关闭网页不会停止后台。关闭桌面窗口仍保留托盘；“退出桌面端（后台继续运行）”断开界面连接，桌面启动的后台由独立进程继续监督。

托盘中的“停止共享后台（Web 和桌面均停止服务）”明确停止共享服务。“重新启动服务”由当前后台持有者执行，并重新发布连接信息。Web 前台启动器的 Ctrl+C 仍表示主动停止后台。

## 发现与认证

启动器先取得现有 DataDir 单实例锁，所有服务完成就绪检查后原子发布 `legion-backend.json`。发现端点使用随机回环端口，独立于业务服务端口。连接入口同时验证活着的锁持有者、启动时间、规范化数据目录、工作区、产品和运行时版本，以及受令牌保护的后台身份响应。

端点只绑定 `127.0.0.1`，状态、停止和重启均要求令牌、正确 Host 和同源 Origin。记录文件按私有文件权限创建；HTTP 状态和桌面协议不返回发现令牌。停止成功后才清除发现记录并释放锁，停止失败保留监督和所有权以便重试。陈旧记录不会授权连接到任意占用端口的服务。

桌面启动的后台保留服务认证。直接本机导航到工作台时可建立 HttpOnly、SameSite=Strict 浏览器会话；跨站导航和 API 请求不能创建会话。会话过期、后台凭据变化、伪造 Cookie 或错误 Host/Origin 都不能通过认证。

## 从现有版本切换

本次开发不自动搬迁或覆盖数据库，不改变当前已运行服务。旧安装版可能使用 Electron userData 下的 `product` 目录，手工启动的 Web 也可能使用仓库内的 `team-hub/team.db`；它们不是上述统一入口管理的共享实例。

切换时先备份并确定要保留的产品数据，停止旧启动入口，再用更新后的统一启动入口运行。已有产品目录可通过相同的 `LEGION_HOME` 指定给两端。仓库内的旧数据库应使用已有的产品旧数据接管流程迁入 DataDir，不能直接复制运行中的 SQLite 数据库，也不能只把端口占用当作身份验证。

已有的旧版启动器没有发现端点，需要先重启到新版本，才能被另一入口自动连接。本次没有生成安装器或执行当前用户数据迁移。
