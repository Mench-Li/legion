# PRT-401：Context Source 与 RunContextSnapshot

> `runtime/contracts/canonical.mjs`（**共享基础库**）+ `runtime/contracts/context.mjs`
> + `runtime/contracts/context.test.mjs`（**33 例**）。
>
> spec §6.5 的第一句就是本模块的全部设计约束：
> **「任一员工运行都能还原其实际输入、来源版本、过滤和裁剪原因。」**

---

## 1. 「还原」要求的是能**区分**，不是"记了一些日志"

一份只有 `sources` 的快照无法回答最关键的那个问题：某个东西**为什么不在里面**。
三种完全不同的情况会长得一模一样：

| 情况 | 用户看到的 |
| --- | --- |
| 这个来源不存在 | 不在 `sources` 里 |
| 有这个来源，但员工无权读 | 不在 `sources` 里 |
| 有这个来源，被 token 预算裁掉了 | 不在 `sources` 里 |

所以 `excluded[]` 与 `sources[]` **同等重要**，并且由一条**计数守恒**断言守着：

```js
sources.length + excluded.length === candidateCount
```

不守恒就抛错。这条断言的价值在于：一个"忘记记录被裁掉来源"的实现会产出一个
**看起来完整**的快照，而那些实现正是 spec §6.5 要防的。有了它，那种实现直接红。

另外，同一来源**不能既入选又被排除**——那说明两次判定不一致，而其中一次必然是错的。

---

## 2. 不可信是**默认值**，不是选项

spec §6.5 点名仓库文件、网页、附件、上游产物、用户输入一律不可信。但"点名一个清单"
有个漏洞：**新增一种来源类型就静默获得了权限**（因为它不在清单里）。

所以判据不是清单，而是：**没写 `trust` 就是 `untrusted`**。而且是字面量比较，
`'Trusted'`（首字母大写）不会被当成 `trusted` ——一个笔误就是一次提权。

### 而被用例逼出来的一处改正

第一版只在 `trust === 'untrusted'` 时检查权威字段（`grants` / `approvalPolicy` /
`manifestPatch` / `toolScope` / `permissions` …），并配了一条用例断言
"**可信**来源可以带权限字段"。

那条用例红了——因为实现里那些字段**根本没被复制进去**，于是它暴露了一个真实问题：
把 `grants` 放在不可信检查之外，等于说 **一次提权只需要把来源标成 `trusted`**。

改正后的规则更强也更简单：**任何**来源都不许带权威字段。
权限的来处是 EmployeeManifest（它作为**内容**进入快照），不是快照上的一个活字段。
一个 ContextSource 是**内容 + 出处**，不是策略对象。

顺带把"其余字段静默忽略"也改掉了：未知字段**拒绝**。理由与 ModelProfile 同一条
——**忽略会让不该出现的字段搭便车**，而一个被静默丢掉的 `grants` 比一个被拒绝的更坏：
调用方会以为"我已经把权限声明出去了"。

---

## 3. token 计量必须带出处，并且出处**进哈希**

spec §6.5：拿不到精确 tokenizer 时，使用**明确标记的**保守估算器。

一个裸数字是没有出处的断言：界面上 `5000` 与 `约 5000（保守估算）`看起来一样，
而只有后者可复核。所以：

* `kind` 是必填枚举（`exact` / `conservative-estimate`）；
* 保守估算**必须**带 `note` 且注明是估算，否则拒绝——不注明时它和精确值无法区分；
* `kind` **参与快照哈希**。

最后一条是关键，也是有一条例用专门守的：**token 数相同、计量种类不同 → 哈希必须不同**。
理由：两次运行的 token 数一样，但一次精确、一次估算，它们关于"上下文放不放得下"
的结论**可信度不同**。哈希相同会让回放误以为两者同等可信。

## 4. 共享基础库：spec 要求"共享"，而在此之前是**两份实现**

spec §6.5 末段：快照哈希的规则与审批哈希**共享基础库**，但使用**不同的 Schema 和
domain separator**，防止跨对象复用哈希。

我查了一下现状：`runtime/dsh-composition/enforcement.mjs` 里有一份**自己的**
`canonicalJson`（审批用）。两份实现今天行为一致——而**没有任何东西在维持它**。
只要有人改了其中一份的键排序或 `-0` 处理，两个子系统就会对"同样的内容"给出不同哈希，
而**两边各自的用例都还是绿的**。

所以本轮做的是**提取**而非重写：新建 `runtime/contracts/canonical.mjs`，
把原实现搬过来，审批侧改为从它 import（并重导出以保持既有 import 面不变）。

### 证明这次重构没有改变任何哈希值

改哈希实现是危険的：任何一位不同都会让**已经存下来的批准**全部失效。
所以我写了一个等价性检查，把旧实现的内联副本与新共享实现逐一比对：

```
比对 25 个值，不一致 0 个
undefined 抛错一致: true (true/true)
审批哈希逐位相同: true
   sha256:743aaf9044c0a7446b766c3f3a0390af8948d728c2be014aba221e19324b7659
```

覆盖：键排序、数组保序、`-0`、`undefined` 键省略、NFC（`e\u0301` vs `\u00e9`）、
西里尔/中文字符串、嵌套结构，以及 `undefined` 的抛错行为。

### domain separator 为什么是哈希的一部分

审批哈希与快照哈希可能对**结构相同**的对象取值。只算 `sha256(canonicalJson(value))`
的话，一个"工具调用参数"与一个"上下文来源"只要字段恰好相同就会得到**同一个哈希**，
于是"这个哈希我批准过"可以跨用途复用。

拼进去的是 `domain \u0000 schemaVersion \u0000 json`。用 **NUL** 分隔是因为
NUL 不可能出现在这三部分各自的正常取值里，于是 `("a\u0000b", json)`
与 `("a", "b\u0000json")` 这类拼接歧义不可能存在——所以 `domain` 含 NUL 时**直接拒绝**，
那是这个"不可能"的前提。用空格或冒号就会留下歧义。

有用例直接验证：**结构完全相同的对象，在两个 domain 下哈希不同**。

## 5. 确定性

spec 要求快照"确定性、可回放"。两处：

* canonical JSON 键**排序**（`{a,b}` 与 `{b,a}` 是同一个对象）；
* `orderSources()` 按 `(type, id, version)` 排序。顺序会进入最终文本，因此它必须是
  确定的函数，而不是"谁先被检索到"。用例验证：**传入顺序反转 → 排序结果相同**。

快照深度冻结；`verifySnapshotHash()` 能发现"存进库里之后被改过"的快照
（用例用展开对象绕过冻结来模拟）。

## 6. 变红验证（12 条全红）

```
基线 fail = 0
✔ 变红  fail=1  被裁掉的来源不记录（丢失"裁剪原因"）
✔ 变红  fail=1  默认可信（新增来源类型静默获得权限）
✔ 变红  fail=1  只在 untrusted 时检查权限字段（提权只需标 trusted）
✔ 变红  fail=1  token 计量种类不进哈希（精确与估算同等可信）
✔ 变红  fail=1  canonical JSON 不排序键（哈希取决于恰好怎么写出来的）
✔ 变红  fail=1  canonical JSON 数组排序（顺序信息丢失）
✔ 变红  fail=3  domain 不参与哈希（审批哈希可冒充快照哈希）
✔ 变红  fail=1  domain 允许含 NUL（拼接边界歧义）
✔ 变红  fail=1  verifySnapshotHash 恒为真（改过的快照发现不了）
✔ 变红  fail=1  保守估算不必注明是估算（与精确值无法区分）
✔ 变红  fail=1  contracts/index.mjs 不再导出 freezeContextSnapshot
✔ 变红  fail=1  审批侧长回一份自己的 canonicalJson（两份实现无人维持一致）
```

### 第 ⑪ 条第一次是**绿的**，而它又是一条**子串检查**

接线那条用例第一版写的是 `idx.includes('freezeContextSnapshot')`。
把导出改成 `freezeContextSnapshotUnused: freezeContextSnapshot` 之后，
**子串仍在、用例仍绿，而那个入口已经不可用了**。

这与本项目反复记过的那条是同一个家族：
*「一个测字符串的断言，和一个正确的实现，在输出上完全一样。」*

改成**真的 `import` 并调用**（导出存在但一调用就炸同样是"没有入口"）之后才真的红。
