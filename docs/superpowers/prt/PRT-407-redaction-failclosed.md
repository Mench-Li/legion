# PRT-407 收尾：脱敏失败 → 整条不发（`EXCLUSION_REASONS.REDACTED` 终于有了产出路径）

> 装配器里那句注释写着：`EXCLUSION_REASONS.REDACTED` 目前**没有产出路径**，
> 它是留给脱敏（PRT-408）的**预留值**。
>
> 也就是说：契约里定义了一个排除理由，而**没有任何代码能产出它**。
> 调用方以为可以传它，它永远不会出现。

本批给它补上真实产出路径，并把判据从"可达 + 预留"收紧成"**每一条都必须可达**"。

---

## 1. ★ 这个枚举值到底该是什么意思

先把语义掰清，否则补出来的产出路径一定是错的。

`redacted` 作为一条**排除理由**，字面上是自相矛盾的：脱敏是**内容变换**，
被脱敏的来源**仍然在** `sources[]` 里（这一点装配器自己的注释论证过，是对的）。
一个"已经被脱敏"的来源根本不会出现在 `excluded[]` 里。

所以 `redacted` 唯一自洽的含义是：**脱敏那道工序没做成，所以这条不能发。**

**★ 而前端早就是这个意思了。** `workbench/src/snapshotView.ts`：

```ts
redacted: '整条不发：内容整体不可外发',
```

与之相对，后端 `describeAssembly` 写的是：

```js
const label = { …, redacted: '已脱敏', … }   // ← 反的
```

**同一个快照，后端摘要说"已脱敏"、前端说"整条不发"，读起来是两件相反的事。**

> 一个"排除原因写已脱敏"的摘要，
> 与一个"排除原因写整条不发"的摘要，在没有任何来源被排除时是同一个东西——
> 只不过前者会让用户以为那份文档**进去了**（只是变了样），
> 而它其实压根没发出去。

现在两处说的是同一件事（后端改成「整条不发（脱敏失败）」），并由用例钉住
（断言摘要里出现"整条不发"、且**不**出现"已脱敏"）。

## 2. ★ 脱敏失败 → fail closed，不放行原文

```js
try {
  r = redactSource(p.source)
} catch (e) {
  excluded.push(createExclusion({
    id: p.source.id,
    reason: EXCLUSION_REASONS.REDACTED,
    detail: '脱敏失败，无法确认它不含密钥，按不发送处理：' + …,
  }))
  continue
}
```

放行是绝对不能做的——那会把**没脱敏的原文**送进模型，而那正是脱敏要防的唯一一件事：

> 一个"脱敏失败就放行原文"的实现，
> 与一个"脱敏失败就整条排除"的实现，在脱敏从不失败的时候是同一个东西——
> 只不过前者会在它失败的那一次，把密钥原样送给模型，
> 而快照上两次看起来都"来源已完整清点"。

### 2.1 为什么不是"整个装配抛错"

那其实更安全，但代价不对等：一个来源的问题会杀掉**整次运行**，而且
**没有任何地方记录是哪个来源出的问题**。排除方案把"哪一条、为什么"写进
`excluded[]`——那正是账本的用途。用例同时钉住"别的来源不受影响"。

## 3. ★ 判据收紧：从"可达 + 预留"到"每一条都必须可达"

旧判据是：

```js
const reserved = [EXCLUSION_REASONS.REDACTED]
assert.deepEqual(all.filter((r) => !reachable.has(r) && !reserved.includes(r)), [])
```

它有一个**安静的缺口**：预留值可以**永远**预留。

> 一个"允许把枚举值标成预留"的判据，
> 与一个"每个枚举值都必须可达"的判据，在该值恰好后来被实现时是同一个东西——
> 只不过前者会**一直**允许它不被实现，而没有任何用例会红。

`REDACTED` 从引入到本批之间一直挂在预留名单上，正是这条判据放行的。
现在预留名单**删除**，判据是 `all.filter((r) => !reachable.has(r)) === []`，
并新增 `assert.equal(reachable.size, all.length)`。

★ 用例**名字**也改了：「要么能产出、要么被明确标为预留」→
「**每个排除理由都必须能产出**（不允许"预留"）」。名字不改的后果不是难看：

> 一个名字里写着"允许预留"的用例，
> 与一个真的允许预留的用例，在没有任何预留值的时候是同一个东西——
> 只不过前者会在有人照着名字做的时候放行一个死枚举。

## 4. 新增用例

`★★★ 脱敏失败 → **整条不发**，且原文一个字都不进快照（PRT-407）`

触发方式：让来源的 `content` **取值抛错**（`redactText` 本身对任何字符串都不抛，
所以那是脱敏唯一真正做不成的形态）。六条断言：

1. 那条被排除，理由是 `REDACTED`，detail 里写着"脱敏失败"；
2. 它**不在** `sources[]` 里；
3. 密钥**一个字都不进** `finalText`，也不进 `JSON.stringify(snapshot)`（全字段扫）；
4. 别的来源**不受影响**（排除一条 ≠ 整次装配失败）；
5. 被排除的那条**不产生 `redactions` 记录**（"脱敏"与"排除"不混）；
6. 人读摘要说的是"整条不发"，且**不**包含"已脱敏"。

### 5.1 ★★ 探针工具自身有两个**真缺陷**（一次真实事故逼出来的）

这次不是发现产品缺陷，是**发现我自己的验证工具在骗我**。事故过程：

1. 我新加了一个探针，它改的文件（`assembler.mjs`）**没有注册进 `ORIG`**；
2. 探针改完文件、测试跑完，下一个探针因为锚点已被改掉而抛错；
3. `finally { restore() }` 遍历的是 `ORIG`——**那个文件不在里面**，于是它被永久留在改坏的状态；
4. 我再跑一次，`ORIG` 是从**磁盘上那份脏文件**读的。

**缺陷 ⑴：`restore()` 只还原注册过的文件。**

> 一个"能改任意文件、但只能还原一部分"的探针工具，
> 与一个"只能改它能还原的文件"的探针工具，在探针恰好只改注册文件时是同一个东西——
> 只不过前者会在有人新加一个目标文件时，把源码留在改坏的状态，
> 同时报告"还原通过"。

修法：`mutate()` **拒绝**改未注册进 `ORIG` 的文件（在写盘**之前**就抛），
于是"改坏了没人能还原"这一类事不可能发生。

**缺陷 ⑵：`ORIG` 是从磁盘现状读的。** 这是第 4 步，也是最危险的一步——
从此每一次"逐字节还原校验"都是拿脏文件跟脏文件比，**恒等成立**。

> 一个"从磁盘现状取基线"的还原校验，
> 与一个"每次都能通过"的还原校验，在磁盘本来就是干净的时候是同一个东西——
> 只不过前者会在上一次崩掉之后，把**"残骸"当成"原文"**，并且从此永远绿灯。

修法：基线哈希记在**仓库之外**（`_prt-handoff/.breakverify-baseline.json`），
启动时比对；不一致就**拒绝运行（exit 2）**，列出是哪些文件，
并说明两种成因（我真的改了源码 / 上次留了残骸）**需要人来看一眼**——
不自动选边，因为"把残骸当成原文"正是要防的那件事。
`--accept-baseline` 是确认源码改动后的显式动作。

**已实测**：往 `assembler.mjs` 尾巴上追加一行注释后重跑，退出码 **2**，
输出点名 `runtime/context/assembler.mjs`；还原后 37/37 恢复绿。

## 7. ⚠️ 诚实边界

1. **脱敏失败的那条来源只留一条排除记录，不留"它本来是什么"**。
   原文一个字都不留是**有意的**（否则排除记录本身成了第二个泄漏点），
   但这也意味着事后无法判断失败的是哪一类内容。
2. **`REDACTED` 的真实触发面很窄。** `redactText` 对任何字符串输入都不抛，
   所以这条产出路径只在"内容取值本身抛错"这类情形上被触发——
   它是**安全网**，不是日常路径。真正的密钥命中走的是
   `redactions[]` + 留在 `sources[]` 里的脱敏后正文（那是 PRT-408 的常规路径）。
3. **跨层枚举对齐那条用例是手工镜像**。
   `workbench/scripts/snapshot-view.test.mjs` 把后端枚举**硬编码成字面量数组**
   （`['unauthorized', 'stale', 'over-budget', 'redacted', 'missing', 'out-of-scope']`），
   并不读 `runtime/contracts/context.mjs`。所以**后端新增一个排除理由时它不会红**——
   它宣称"逐一对齐"，实际是一份需要人同步的副本。
   本批没有改枚举值，所以没有触发；但这是一处**已知的弱门禁**。
4. **判据只保证"可达"，不保证"可达得合理"**。
   一个理由可以由一条几乎不可能走到的路径产出（`REDACTED` 现在正是这样），
   而用例照样绿。要更严需要"每条路径的最小触发条件"这类断言，本批没做。
5. **脱敏失败时不重试、不降级**。没有"用更保守的方式再脱一次"的路径。
6. 结论一致性与 PRT-408 的其余部分（来源清单）仍未做——见 PRT-408 行。
