## 1. 起点：PRT-504 是一整块**没有任何入口**的功能

动手前先查了一遍调用方：

```
$ git grep -ln createModelProbe
runtime/probe/http.mjs          ← 实现
runtime/probe/index.mjs         ← 实现
docs/...                        ← 文档
```

**非测试命中只有它自己的实现文件。** 也就是说 PRT-504 交付了实现、两个套件、
一份设计文档、一条 `docs/STATUS.md` 记录——而**没有任何东西能触发它**。

> **一个没有任何入口的功能，和一个不存在的功能，从用户角度看完全一样。**

这与上一轮 PRT-509 的形态同源：那次空的是"线中间那一截"（ACL runner 永远
`undefined`），这次空的是**整条线的外部端口**。两次都是**用例全绿**。

所以本轮的顺序是：**先接线，再做页面**——否则页面只是给一块死代码加了个按钮。

## 2. 后端：`team-hub/probe-service.mjs`

### 最重要的一条判断：「没探测过」不是「探测失败」

探测需要凭证。密钥库打不开（DPAPI 不可用 / 文件坏 / 布局不合法 / 没填 endpoint）时，
我们**根本没问过供应商**。此时返回任何 `ok:false` 的探测判定都是**撒谎**：

| 说成 | 用户会去查 | 真实原因在哪 |
| --- | --- | --- |
| "模型连不上" | 网络、供应商状态、模型名 | ❌ **完全错误的方向** |
| "这次没探测过" | 密钥库 | ✅ |

两种错法的代价**不对称**，所以这里返回一个**结构上不同**的东西：

```js
{ ok: false, unavailable: true, code: 'PROBE_SECRETS_UNAVAILABLE', message, detail }
```

它**没有 `class`**（没有失败分类可言）、**没有 `latencyMs`**（没发过请求）。
调用方必须显式分支，不能顺手把它读成判定。HTTP 上是 **503**——
不是 4xx（用户没做错），也不是 200（那会被前端当成一个判定）。

### 一个反例：凭证解析失败**不**归我拦

凭证引用存在但拿不到值时，执行器已经把它建模成一条带独立分类的判定
（`class: 'fail-closed'`），文案明确写着"不是供应商的问题…不要去供应商控制台换钥匙"。

**执行器那层处理得比我拦下来更好**——它有专门的分类和更准的话。
在服务层再拦一次只会让同一个判定存在**两个产生点**，而两份必然漂移。所以放行。

### 端到端实测（真起 hub、真发请求）

```
① 建档案: 200
② 档案不存在: 404 {"code":"PROFILE_NOT_FOUND"}          ← 「没这个档案」
③ 真探测:     503 {"code":"PROBE_LAYOUT_BLOCKED", ...}  ← 「没探测过」
④ 多段 id:    400 {"code":"BAD_ID_ENCODING"}
```

② 与 ③ 是**两件不同的事**：前者要人去建档案，后者要人去修密钥库。混成一个码会让
其中一半的人找错方向。

## 3. 前端：`workbench/src/modelSettings.ts`

这一层单独存在，是因为它守的是一条本仓库反复证明的纪律：

> **后端加了码、前端还是笼统提示 —— 那条码就等于没加。**

把 503 渲染成红色的"连接失败"，用户会去查网络，而且他会开始怀疑一个
**其实从未被验证过**的东西。所以 `unavailable` 走一个**灰色"未测试"**徽标，
并且**绝不**显示失败分类。

### 分类决定"该做什么"

| 分类 | 用户的下一步 |
| --- | --- |
| `config` | 去改配置，**重试不会变好** |
| `transient` | 稍后重试 |
| `fail-closed` | **本机凭证库**的问题，不要去供应商那边 |
| `unknown` | **不能当作暂时问题重试**——请看原始信息 |

把 `unknown` 猜成 `transient` 会让用户反复重试一个永远不会好的配置错误。
分类缺失时按 `unknown` 处理：**保守的方向是"别乱重试"**。

### 其余几处"不猜"

- **空能力表 ≠ "什么都不支持"**。供应商大多根本不报能力，此时唯一诚实的答案是
  "没有证据"。猜错两个方向都更糟，所以文案直接说出来。
- **凭证状态未知 ≠ "没有凭证"**。猜"没有"会制造一条**永远不对**的提示
  （同「一条永远不对的告警和没有告警是同一件事」）。
- **候选建议不带用户已填的值**。混进去看起来像"系统认可了你输入的那个"，而它并不存在。
- **未列出的码承认自己不认识**（走 `unknown` 分支），不假装给一句"一切正常"。
- **被跳过的 fallback 候选也要显示**，并带原因——只显示能用的会让用户以为链条更短，
  而运行失败之后他没有任何线索知道"其实还有一个候选，只是被跳过了"。
- **导入被拒绝时不再列变更项**（拒绝优先）——列了会让人以为反正能导。

## 4. 本轮最重的发现：PRT-007 基线**看不见**一类路由

加完路由后跑闸门：

```
$ node scripts/prt/baseline-snapshot.mjs --record
  路由  125          ← 与**改动前一模一样**
$ node scripts/prt/baseline-snapshot.mjs --check
baseline-snapshot: 平台契约与基线一致（无漂移）
```

而那条路由是真的、端到端能跑的。原因：抽取器只认**字符串字面量**：

```js
/req\.method\s*===\s*'([A-Z]+)'\s*&&\s*path\.startsWith\(\s*'([^']+)'/g
```

我把路由写成了 `path.startsWith(MODEL_PREFIX)`（常量），于是：
- `--check` 绿；
- `--record` 写入一份**少了一条真实端点**的"权威契约"。

而同级的四条路由（GET/PATCH/PUT/DELETE）恰好用的是字面量，所以它们在基线里——
**这个盲区一直存在，只是直到这次才有一条路由掉进去。**

> **一道看不见某类改动的闸门，比没有闸门更危险**——它会让人相信已经守住了。

本仓库已经记过这条（上一轮在 PRT-252 的源码断言上又犯过一次）。这次不再只写进文档，
而是**让抽取器主动拒绝**：新增 `findOpaqueRouteGuards()`，发现
`req.method` 守卫下的路径用的是**常量**（形如 `*PREFIX`/`*PATH`/`*ROUTE`/`*URL`）就抛错，
并说明"请改用字面量，或扩展抽取规则支持常量解析"。

修法不是"记得用字面量"（那是靠人记），而是**让忘记变成一次失败**。

修好之后：**125 → 126**。

## 5. 变红验证

后端 5 条、前端 9 条，全部变红：

```
基线 fail = 0
✔ 变红  「没探测过」塌成「鉴权失败」（把用户引向供应商控制台）
✔ 变红  给"没探测过"加上失败分类（调用方可以顺手当判定用）
✔ 变红  布局不合法时仍然继续（假装知道密钥库在哪）
✔ 变红  诊断快照带上缓存键（泄漏 secretRef 引用名）
✔ 变红  路由不再调用探测（退回一个假判定）
✔ 变红  「没探测过」渲染成红色失败（用户会去查网络）
✔ 变红  unknown 塌成 transient（反复重试永远不好的东西）
✔ 变红  空能力表被说成"支持全部"（无据的猜测）
✔ 变红  凭证状态未知说成"没有凭证"（永远不对的提示）
✔ 变红  候选建议混入用户已填的值（看起来像系统认可了不存在的选项）
✔ 变红  被跳过的候选不再显示（链条看起来比实际短）
✔ 变红  被拒绝的导入仍然列出变更项（让人以为能导）
✔ 变红  未列出的码被假装认识（不承认自己不认识）
```

### 又一条"变红验证自身出错"

前端第 ① 条我原本写的是"文案里不许出现'连不上'"的正则。它**失败了**——
因为正确的文案恰恰要**引用**这句错误说法来否定它（"这不是"模型连不上""）。

> **一个会被正确实现绊倒的断言，比没有断言更坏。**

改成结构判据（`class === undefined`、`latencyMs === undefined`）——
那才是"没探测过"与"探测失败"真正不同的地方，而不依赖于措辞。

## 6. 一处自己造的缺陷（顺手修掉）

`inspect()` 第一版返回 `cache: probe.inspect().entries.length`，而
`entries[].key` 是 `profileId\u0000fingerprint`，**fingerprint 含 `secretRef` 的引用名**。

引用名进了诊断快照，就能画出"这台机器配了哪些供应商"——正是 PRT-254 明确禁止的
（`product/secrets.test.mjs` 有用例守着）。而我的用例只断言了"不含 `sk-`"，
所以**它是绿的**。

> **能算出指纹 ≠ 该把指纹写进日志。**

改为只暴露 `cacheSize` 与 `cacheCodes`（判定码不含引用名），并把断言改成
`!text.includes('"K"')`——引用名一旦出现就会红。
