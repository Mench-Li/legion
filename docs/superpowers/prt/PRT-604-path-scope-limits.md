## 1 唯一真正要紧的事：包含关系不能用字符串比

最容易写出来的版本是 `target.startsWith(root)`。它在每一条只用了普通文件名的用例里
都是绿的，因为那些名字确实在 root 里面。它错在三个地方，**每一个的方向都是放行**。

### 1.1 边界不是前缀

> 一个「用 `startsWith(root)` 判包含」的范围检查，
> 与一个「`C:\work-evil` 也在 `C:\work` 之内」的范围检查，是同一个东西——
> 而它的方向是放行。

`assertBoundaryNotPrefix` 不只断言正确答案，还把 `startsWith` 会在**哪几行**给出错误
答案一起留证（`prefixWouldBeWrongOn`）——因为"为什么必须有边界"这件事，
只有在看到那几行与正确答案分歧时才成立。

### 1.2 字符串相等 ≠ 同一个文件

> 一个「只比路径字符串、不解析链接」的范围检查，
> 与一个「在允许目录里放一个指向 `/etc` 的链接就得到了 `/etc`」的范围检查，
> 是同一个东西——而它的方向是放行。

`assertSymlinkEscapeCaught` 同时给出 `textualWouldAllow: true` 与 `allowed: false`：
前者说明纯字符串判定为什么看起来是对的。

### 1.3 写操作恰好都是**新文件**

`realpath` 对不存在的路径会失败。于是"先 realpath 再比较"的写法在**新建文件**时
要么抛、要么被 catch 掉当成"解析不了，跳过解析"。而写操作正是新建文件：

> 一个「只对已存在的文件做真实路径解析」的范围检查，
> 与一个「新建文件时静默跳过解析」的范围检查，是同一个东西——
> 而写操作恰好都是新建文件。

所以解析是 `splitAtDeepestExisting`（最深存在前缀）+ 剩余段拼接。
**没有解析器时抛**，不提供"解析不了就跳过"的降级。

## 2 本批抓到的四个真缺陷

### 2.1 ★★ `..` 被当成"尾点"剥掉 → 每个 `..` 都变成 `.`

Windows 会把路径段末尾的点与空格剥掉（`a.txt.` → `a.txt`）。第一版把这个规则无条件
施加到每一段上，于是 `..` 被剥成空串、再被兜底成 `.`——**每一个 `..` 都变成了 `.`**，
路径只会往深处走：

> 一个「把 `..` 也当成'尾点'剥掉」的规范化，
> 与一个「`..` 静默变成 `.`、于是路径永远往深处走」的规范化，是同一个东西——
> 而它的方向是放行。

最坏的形态是**一次完整的越界**。`/work/sub/../../../etc/passwd` 折叠成
`/work/sub/etc/passwd`，**在范围之内**。

这个缺陷是被**装载自检**抓到的（`hazardsRejected` 里那条样本对不上），不是被人看出
来的——它在任何只往前走（不用 `..`）的用例里都是绿的。

修法：`collapseSegments` 先认 `.` 与 `..`，再对别的段剥尾点。同时补一条**方向最坏**
的用例：那个路径必须不在范围之内，且报的是更具体的 `OUT_OF_SCOPE`
（"这个路径自己就往上逃出了根"）而不是笼统的"不在范围内"：

> 一个「把'路径自己就无效'报成'不在范围内'」的拒绝，
> 与一个「值班的人去改范围表、而其实该改的是调用方」的拒绝，是同一个东西。

### 2.2 ★★ 接回来的那一段自己还会走链接 → 解析必须**迭代**

`exists()` **看不穿链接**。目标 `/work/link1/link2/f`（`link1 → /base`、
`/base/link2 → /deep`）：`exists('/work/link1/link2/f')` 是 false（真实 fs 上也一样），
`exists('/work/link1')` 是 true。于是最深存在前缀是 `/work/link1`，解析成 `/base`，
接回 `link2/f` 得到 `/base/link2/f`——**而真实路径是 `/deep/f`**。

> 一个「只解析最深存在前缀、剩下那段直接拼接」的解析，
> 与一个「在链接目录下面再套一层链接就逃出去了」的解析，是同一个东西——
> 而它的方向是放行。

修法：迭代到路径稳定，轮数有上限（12）。上限不是凑数——`/loop/a → /loop/a/a`
这类**自我加长**的链接表每轮变长，永远不稳定：

> 一个「递归解析但有轮数上限」的实现，
> 与一个「链接表能自我加长时把进程转死」的实现，是同一个东西。

注意区分两种"环"：`/loop/a → /loop` 会**收敛**（每轮吃掉一段），
`/loop/a → /loop/a/a` 才发散。用例把两种都钉住了。

这条是**破坏性验证**抓出来的：我原本以为"逐段替换链接"的循环是多余的（因为
`splitAtDeepestExisting` 已经停在链接上），把探针删到只认整段链接——结果用例没红，
顺着查下去才发现真正的缺口在**拼接之后**，不在拼接之前。

### 2.3 ★★ 写一行 `version` 跳过范围表的全部校验

与 PRT-603 完全同一个形状：`checkPathScope` / `narrowScopeToWorkspace` 写的是

```js
const s = scope?.version === PATH_SCOPE_VERSION ? scope : normalizeScope(scope)
```

于是手工构造一个带 `version` 的范围表就跳过了**全部**校验——包括
"写范围必须是读范围的子集"：

> 一个「看到 version 字段就认为它已经校验过」的校验，
> 与一个「在范围表里写一行 version 就能跳过所有检查」的校验，是同一个东西。

修法：总是归一化。代价是每次判定都归一化一遍（纯函数，很便宜）。

### 2.4 ★ 归一化接受不了自己的输出

修了 2.3 之后立刻撞上：`normalizeScope` 的输出带 `version`，而字段闭合名单里没有
`version` → `normalizeScope(normalizeScope(x))` 抛"不认识的字段"。

> 一个「接受不了自己的输出」的归一化，
> 与一个「第二次经过就抛」的归一化，是同一个东西。

修法：`version` 进字段名单，并且**值也要校验**（否则它就从后门变成了另一个后门）。

## 3 范围表：只能收窄（与 PRT-603 同一条纪律）

> 一个「写范围可以大于读范围」的范围表，
> 与一个「写不了的东西先读出来、再写到别处」的范围表，是同一个东西。

字段同样必须**闭合**。PRT-603 的 `workspaceRoot` 在这里落地为**进一步收窄**。

### 3.1 收窄是**取交集**，不是筛选

第一版写的是"只保留落在 `workspaceRoot` 之内的写根"。于是
`write: ['/work/sub']` + `workspaceRoot: '/work/sub/deep'` 被判成"没有交集"——
而正确答案是 `/work/sub/deep`（工作目录比写根更深，它把写根收到了自己这里）：

> 一个「把'工作目录比写根更深'当成'没有交集'」的收窄，
> 与一个「岗位配了一个更深的目录就什么都写不了」的收窄，是同一个东西。

读范围**不**被工作目录动到——否则会误伤"读仓库、写工作区"这类正常配置。

### 3.2 收窄里那条"write ⊆ read"检查是**死分支**，已删除

交集只会比写根更深，所以收窄之后 `write ⊆ read` 自动成立。原来放在那里的一道检查
**没有任何输入能到达**：

> 一段从未被执行的分支，与一段不存在的分支，在"它到底对不对"上是同一个东西。

校验收在入口（`normalizeScope`），那里是可达的；不变量本身由用例直接断言。

这一点是**破坏性验证**抓出来的：探针 ㊴㉙ 把那个分支改成 `if (false)`，用例全绿。

## 4 Windows 的那些坑

| 形态 | 为什么危险 | 处置 |
| --- | --- | --- |
| `C:foo` | **盘符相对**：相对该盘的当前目录，不是绝对路径 | 抛 `NOT_ABSOLUTE` |
| `\foo` | "当前盘"的根，随进程而变 | 抛 `NOT_ABSOLUTE` |
| `\\?\C:\…` | 设备命名空间：`..` 与尾点规则都不同 | 抛 `DEVICE_PATH` |
| `NUL` / `CON` / `COM1` | 设备名，**有没有扩展名都生效** | 抛 `DEVICE_PATH` |
| `a.txt.` / `a.txt ` | Win32 会剥尾点尾空格 | 比较前剥掉 |
| `\\server\share\…` | 根是 share，不是盘符 | 自己的根 |
| 大小写 | win32/darwin 折叠，linux 敏感 | **跟着平台走** |

大小写规则那条有一个刻意的选择：**平台不认识时抛**，不给默认值——
> 一个「平台不认识就按 Linux 处理」的范围检查，
> 与一个「在 Windows 上 `C:\WORK` 与 `C:\work` 是两个不同目录」的范围检查，
> 是同一个东西——而它的方向取决于哪一边被当成根。

（探索时还撞到一个自己的 bug：POSIX 的根是 `/`，朴素的 `${root}/${body}` 会拼出
`//work`。同一个目录有两种规范形式，包含判定就会随机成立。已经修掉并留了探针。）

## 5 与强制面的接线

spec §6.6 line 449 要求越界路径**两处**都拦：pre-execute 提前拒绝 + guard 最终复核。
所以 `pathScope` 端口在桥里被用在两个地方：

> 一个「只在 pre-execute 查路径范围」的组合，
> 与一个「guard 那一层已经换成了另一份范围表」的组合，是同一个东西——
> 而 guard 正是"不可撤销"的那一道。

顺序：**路径范围 → 岗位白名单 → 策略端口**。越界是 hard floor 的一部分，
而岗位清单是"这个岗位能干哪些事"，两者拒绝的理由不同、修复动作也不同。

范围检查本身抛错 → **拒绝**（与 `projectionFor` 同理），理由带码。

另外给桥加了 `enforcementSurfaces()`：把"装上了什么"读出来。
`pathScope` / `whitelist` 都是**可选端口**，一个没接上的端口在运行时与"从不拒绝"
无法区分：

> 一个「端口是可选的、但没有任何地方能看出它没接」的桥，
> 与一个「以为范围限制在生效、其实那道检查根本没挂」的桥，是同一个东西。

## 6 沙箱：配置名不算证据

spec §6.6 line 454 明说"仅有配置名不算生效"。`describeBackendEvidence` 的结论不是
布尔，它说清楚"是靠什么判定的"：

> 一个「看到 `sandbox: workspace-write` 就认为范围限制在生效」的判定，
> 与一个「沙箱后端根本没启动、而所有人都以为它在」的判定，是同一个东西。

`effective` 只在**同时**有配置名与后端探测结果时才为真。

## 7 诚实边界

1. **真实路径解析的 seam 是真的，但生产实现还没接上**。本模块提供
   `createResolver` 这个**纯内存**参考实现；生产要接
   `fs.realpathSync.native` + `fs.existsSync`。函数不能跨 JSON，所以这一层永远留在
   进程内。**这意味着目前没有任何一次真实的符号链接被解析过**——本批证明的是
   "解析之后判定是对的"，不是"解析器已经接上了"。
2. **迭代轮数上限（12）是一个工程选择**，不是证明。真实文件系统上正常的链接层级远
   小于 12；超过就拒绝，方向是安全。
3. **`ADS`（备用数据流，`file.txt:stream`）只被识别、没有被拒绝**。
   `normalizeForCompare` 会算出 `hasStream: true`，但判定路径上还没有用它的规则。
   数据流写在文件**之内**，所以"在范围内"这个结论本身不算错，但它是一个独立的
   审计话题。留给 PRT-605/606 的权限细分。
4. **工作目录比较不是权限边界**。`workspaceRoot` 只用来收窄写范围；真正的边界是
   `ctx.sandbox` + 本模块的解析判定。spec line 454 说"仅有配置名不算生效"——
   本模块能提供的是判定，不能提供的是**后端是否真的在拦**。
5. **Windows 的 8.3 短名（`PROGRA~1`）没有处理**。它需要 `GetLongPathName`，
   属于解析器那一侧的职责（与符号链接同一类），而不是字符串规范化。当前行为是
   尽力而为：短名与长名会被当成两个不同路径，方向是**多问一次**而不是放行。
6. 大小写规则对 `darwin` 默认折叠——APFS 可以配置成大小写敏感，所以那里也是
   "默认更严格"的近似，不是精确判定。

### 8.1 探针与用例的改瞄记录

两处首次不红，各自指向一个**不同的**真问题：

| 探针 | 首次结果 | 处置 |
| --- | --- | --- |
| ㊴⑧ "逐段替换链接"的能力被删 | 不红 | **探针指错了地方**：`splitAtDeepestExisting` 已经停在链接上，所以 realpath 拿到的正好是链接本身，逐段能力用不上。删掉探针后顺查发现真缺口在**拼接之后**——接回来的段自己还会走链接。改成"只解析一轮"的探针后变红；同时补 ㊴⑧b（轮数无上限）。*这条是本批最有价值的一次"探针没红"——它指向的不是覆盖缺口，而是实现缺口。* |
| ㊴㉙ "收窄之后不再校验 write ⊆ read" | 不红 | **探针不可能红**：交集语义下该分支数学上不可达。*一个「恒定走同一个分支」的探针，与一个不存在的探针，在「它到底测没测到」上是同一个东西。* 代码里把死分支删掉，探针改瞄到它在别处揭示的真问题——`version` 字段成为跳过全部校验的后门（㊴㉙、㊴㉙b、㊴㉙c、㊴㉙d 四条） |

用例自身修正（不是探针问题，是我的夹具写错）：
- "一层链接指向仍在范围内的位置"——第一版夹具的链接指向 `/base`，那**确实**在
  `/work` 之外，拒绝是对的。改成链接指向 `/work/real`，并补一条"同一链接指向外则拒绝"
  的对照，避免用例退化成"见到链接就拒绝"。
- "逃出根本身"——我原本期望 `['a','..','..','b']` 折成 `['b']`，那等于把"逃出根"
  当成"根的别名"。改成断言抛错，并补"正好回到根"的对照。
- "不传工作目录 → 原样返回"——总是归一化之后返回的是新对象，改成结构比较。
- 自我展开的链接表——我挑的 `/loop/a → /loop` 其实**会收敛**；真正发散的是
  `/loop/a → /loop/a/a`。两种都写进用例。
