# PRT-613 审批、UI、审计与执行看到同一份不可变工具参数

> spec §6.5 line 468：「审批绑定不可变 `ToolExecution` 参数的 canonical operation
> 哈希；DSH `tools/pre-execute` **不允许改写工具参数**，因为审计、UI 和实际执行
> 必须看到相同输入。Legion 如需改变参数，只能**拒绝当前调用**并要求模型或工具
> 定义产生一个新的 Tool Call，**不能在审批后静默改写**。」
> spec line 935：「保证审批、UI、审计与执行看到同一不可变工具参数，禁止 pre-execute 改写。」

状态：**已交付**（`runtime/dsh-composition/tool-args.mjs`；
判据 `runtime/dsh-composition/tool-args.test.mjs` 30 例）

---

## 1 为什么"四个面都同意"这句话自己证明不了自己

最容易写出来的实现是这样：冻结时算一个哈希，四个观察面各自**按自己的副本重算**
一遍哈希，相等就通过。它在参数被改写时**照样通过**——因为那个"自己的副本"已经
是被改写过的样子了，重算出来的哈希当然与它自己一致。

> 一个「每个观察面各自按自己的副本重算哈希、再比哈希」的校验，
> 与一个「从不校验」的校验，在「pre-execute 到底能不能改写参数」上是同一个东西——
> 只不过前者会打印一行"四个面一致"。

所以身份必须**随体携带**：冻结的那一刻算一次，之后所有观察面读到的都是
**携带的那个值**，没有任何一个面有机会"按自己的副本重新证明自己"。
重算只发生在**一处**（`assertNotRewritten` / `assertObservationFaithful`），
方向固定：重算 → 比冻结体。

## 2 本批抓出来的真缺陷：`toolName` 不在身份里

第一版 `hashToolArguments(args)` **只哈希了 `args`**。于是
`file_write` 与 `file_delete` 在参数相同时得到**同一个身份**——
一次"写文件"的批准会覆盖一次"删文件"。

> 一个「只把参数算进身份、没把工具名算进去」的哈希，
> 与一个「同一个参数在任意工具下都算同一次操作」的哈希，是同一个东西——
> 而它的方向是**放行**。

这是本模块的用例 `⑤ 不同 toolName 是不同身份` 在第一次运行时抓出来的（红了）。
F-02 侧的主体里本来就有 `toolName`（`CANONICAL_OP_KEYS`），是我在这里漏了它。

**这一条值得单独写下来**：方向是放行，而放行方向的缺陷不会有人来报 bug。

## 3 深冻结，不是浅冻结

`Object.freeze({arguments:{path:'a'}})` 冻不住 `path`。而"哪个文件被写"恰恰在第二层。

> 一个只冻结了最外层的"不可变"参数，
> 与一个「内层随时可以被悄悄改掉」的参数，是同一个东西——
> 只不过前者会通过 `Object.isFrozen()` 的检查。

`deepFreeze` 递归冻结；`assertDeepFrozen` **逐层**确认，并留下
**算出来的冻结路径列表**作为证据（`['path','mode','nested.deep.value']`），
而不是一个布尔 `ok`——`ok` 可以被"删掉整个检查"的那一处补丁伪造。

另外，冻结体**不持有调用方的对象**：`structuredClone` 一份再冻。
否则调用方在冻结之后改一下自己手里的对象，被批准的参数就变了。

## 4 "携带"这件事只在序列化边界上可观测

这是本批**实测**得到的一条，值得单独记下来。

破坏性验证的第一个版本把 `observe` 改成"按 `body.arguments` 重算哈希"——
**一处都没红**，而且它不可能红：冻结体的 `arguments` 是深冻结的，
任何一面按它重算都必然得到同一个哈希。重算与携带在进程内**恒等**。

> 一个「在进程内比较携带值与重算值」的校验，
> 与一个恒真的校验，在「跨进程之后还对不对得上」上是同一个东西——
> 因为进程内根本没有第二种可能。

真正的风险在边界上：观察面拿到的是**它自己那份副本**（反序列化之后的）。
若它"按自己的副本重算"，重算值当然与它自己一致——复核永远通过。

所以本批补了 `serializeObservation` / `assertObservationFaithful`，
把边界显式做出来。后者抓三种形状：

| 形状 | 后果 |
| --- | --- |
| 携带的哈希 ≠ 冻结体 | 有人报了一个别处的身份 |
| 携带的 canonical 文本 ≠ 冻结体 | 规范化过程本身不稳定 |
| 携带的哈希**等于**冻结体、但参数重算得别的 | **最坏的一种**：所有哈希比对都通过，执行的却是另一份参数 |

最后一种的正确读法是：

> 一个「用被检查对象自己的数据去证明被检查对象」的复核，
> 与一个恒真的复核，是同一个东西。

## 5 pre-execute 不允许改写

`resolvePreExecuteResult` 只有两条路：**同身份放行**，或抛。
"用新参数自动重走审批"不在其中——它与静默改写在"用户批的是不是被执行的那次"
上是同一个东西，而 spec 明说只能**拒绝当前调用**并要求产生一个新的 Tool Call。

判等**不**用对象引用：一次 JSON 往返就会换掉引用，靠引用判等会把合法的
"同值重放"误判成改写。判等用 canonical 哈希。

---

## 6 UI 摘要不参与身份

UI 需要一句给人看的摘要。若审批绑定的是摘要，那么摘要相同的两次**不同**调用
会共用一次批准。

> 一个「绑定到 UI 文案」的审批，与一个「绑定到参数摘要」的审批，
> 是同一个东西——只不过前者让参数在文案相同的所有位置自由变化。

`assertNotBoundToSummary` 查三种误用：绑定值不是参数哈希、绑定文本恰好是摘要、
绑定值等于摘要的哈希。

⚠️ **顺带修的一处顺序缺陷**：第一版把通用的"绑定值不是参数身份"检查放在
**前面**，于是"绑定到摘要哈希"这条**更具体**的诊断被它挡住、**永远不可达**——
报出来的是通用的那一句。

> 一个被前一道更宽的判断挡住的、更具体的诊断，
> 与一个不存在的诊断，在「值班的人能不能看出是哪一种错」上是同一个东西。

## 7 诚实边界

1. **本模块是原语，还没有接到真实的 DSH `tools/pre-execute` 钩子上**。今天的调用者
   是用例。接线属 PRT-602（Enforcement Bridge）。
2. **`toolName` 的规范化只做 NFC + trim**。不做大小写折叠、不做别名解析——
   "`File_Write` 与 `file_write` 是不是同一个工具"是工具目录的事（PRT-603），
   在这里猜会在工具改名时静默失效。
3. **深冻结对 `Map`/`Set`/`Date`/类实例无效**。工具参数按 JSON 形状约定
   （`canonicalJson` 也只支持 JSON 形状）；非 JSON 形状的参数会在
   `canonicalJson` 那里抛或产出无意义结果。本模块不额外拦。
4. **`structuredClone` 不能克隆函数**。参数里有函数会在冻结时抛——这是想要的
   （工具参数必须是数据），但错误信息来自 `structuredClone` 本身，不够指向性。
5. **摘要的生成不在本模块**。`summary` 是调用方传进来的字符串；本模块只保证
   它**不参与身份**。至于摘要会不会误导人（比如截断得太狠），不在这里解决。
