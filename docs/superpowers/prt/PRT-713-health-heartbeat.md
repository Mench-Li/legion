# PRT-713 默认关闭、显式选择加入的脱敏健康心跳

> spec §6.6：「商业 Alpha 默认仅本地展示；远程心跳必须**显式选择加入**、
> 只发送**脱敏聚合状态**，并允许用户**随时关闭**。」
>
> `product/heartbeat.mjs`。本地展示那一半（九个指标）是 PRT-712。

## 1. 唯一真正要紧的那条纪律

这类代码最常见的失败**不是忘了加密**，而是「关掉之后还在发」：

- 定时器到点了，而 `stop()` 只是把 `enabled` 置了 false ——
  已经在路上的那一次照发；
- `stop()` 清了定时器，但发送是异步的，清完之后 resolve 的那一次照发；
- 用户在界面上点了关闭，产品重启后配置读回来又变成默认开；
- 出错的路径上偷偷重试。

对一个已经点过「关闭」的用户来说，上面每一种都与「根本没关」没有区别。

> 一个「关了之后还会再发一次」的心跳，与一个根本没关的心跳，
> 在「用户点了关闭之后数据还会不会出去」上是同一个东西。

## 2. 三道独立的闸，任何一道不通过就不发

| 闸 | 拦的是什么 |
| --- | --- |
| ① **策略** `enabled !== true` | 默认就没开。默认是 `false` |
| ② **代际** `generation` | `stop()` 让代际 +1；发送在真正落到 `transport` **之前**再核对一次。**这是唯一能拦住"已经在路上的那一次"的东西** |
| ③ **已停掉** `stopped` | `stop()` 之后**任何**后续发送都拒绝，包括 `sendNow()` |

② 与 ③ 是**两道不同的闸，缺一不可**：

- `generation` 拦的是**已经开始的**那一次发送；
- `stopped` 拦的是**之后才发起的**发送。

只做 ② 会出现这种情况（**这是本轮量出来的真缺陷**）：用户点了关闭、定时器
停了，但任何一条仍然持有这个实例的代码路径调用 `sendNow()` 就会照发——
而 `sendNow()` 读到的代际是**已经加过的**那一个，所以那道闸根本不响。

> 一个「关掉之后只要有人再调一次就还会发」的心跳，
> 与一个关不掉的心跳，在「用户点了关闭之后数据还会不会出去」上是同一个东西。

### 两次核对之间不是空的

`shouldSend()` 在**构造载荷之前**与**调用 transport 之前**各查一次。
这两次之间的代码（脱敏 + 序列化）要花时间，而用户的「关闭」完全可能正好
落在这个窗口里。只查一次的实现，漏掉的恰好是「已经走到这一步的那一次」——
也就是用户唯一会注意到的那一次。

有一条用例专门构造这个窗口：把 `metrics` 做成带 getter 的对象，
第一次被读到（也就是载荷正在构造、`transport` 还没被调）时触发 `stop()`。

## 3. 显式选择加入：同意是一件**可查**的事

开启心跳需要三样东西同时成立，缺一不发：

- `enabled === true`
- 一个合法的 `endpoint`
- 一条 `consent` 记录（**谁在什么时候同意了**）

没有 `consent` 时，`validateHeartbeatPolicy` 判定不合法；
而 `shouldSend` **自己也**再查一遍。这不是冗余——`shouldSend` 是唯一紧贴
`transport` 的那道闸，**一道依赖"前面某个校验已经跑过"的闸，
在有人把那行校验挪走的那个下午就失效了**。

这条「双重检查」本身也需要被观测：如果只断言「没发」，那么把 `shouldSend`
里那道检查删掉用例照样绿。所以用例断言的是**具体的理由码** `HEARTBEAT_NOT_OPTED_IN`。

> 一道「删掉也不会让任何用例变红」的闸，与一道不存在的闸，
> 在「它到底拦不拦得住」上是同一个东西。

## 4. 端点必须 https

心跳是产品**主动**把数据送出去的唯一通道。允许 `http://` 意味着用户的运行
状态在链路上是明文——而这条链路上有队列深度、错误率、可用率，
合起来足以推断一台机器在干什么。

> 一个「默认明文、想加密可以自己配」的上报通道，
> 与一个明文的上报通道，在「数据出去的时候有没有被保护」上是同一个东西。

## 5. 载荷：**允许名单**，不是拒绝名单

一个「把所有已知敏感的字段删掉」的实现，在有人往上游加了一个新字段时会
**静默外流**它。允许名单相反：新字段默认不外流，想外流得**显式加进去**。

> 一个靠「记得把新的敏感字段排除掉」来保密的载荷，
> 与一个会把新字段发出去的载荷，在「下一次谁忘了」上是同一个东西。

允许名单只认**叶子值**：

| 类型 | 处理 |
| --- | --- |
| 有限数 | 收 |
| 布尔 | 收 |
| 字符串（**受控值**：`schema` / `platform` 精确匹配枚举） | 收 |
| 其余字符串（短、无空白、无 `/` `\`） | 收 |
| `NaN` / `Infinity` / 对象 / 数组 / 函数 / `null` | **丢** |
| 不在名单上的键 | **丢** |

`schema` 的值 `legion/heartbeat@1` 里带 `/`，会被「无路径分隔符」那条规则
当成疑似路径丢掉。失败方向是安全的，但服务端就拿不到「该怎么解读这份心跳」了。
所以给这几个键改用一条**更窄也更明确**的规则：只认列出来的那几个值。

> 一个「看起来像就可以」的检查，与一个「必须正好是它」的检查，
> 在「用户的数据会不会跟着自由文本一起出去」上是两回事。

还有一段守「允许名单本身别被人加宽」：一条用例断言名单里只允许
`productVersion` 与 `runtimeState` 这两个自由字符串键——**加键之前得先想清楚
它会不会带出路径或任务名**。

`payloadFromRuntime` 是生产路径上唯一该用的入口：它自己只取
「状态 + 指标摘要 + 版本」，调用方无法往里塞别的东西。

## 6. 未知指标不进载荷

PRT-712 的 `metricsSummary` 已经把读不出来的指标排除掉了；
心跳这边继续保证这一点——远端收到一个 `0` 会把它当成真实读数，
而这正是 PRT-712 通篇要防的那件事。载荷带 `observedMetrics` / `totalMetrics`，
远端因此知道这份摘要有多完整。

## 7. 定时器必须 `unref`

一个让进程无法退出的心跳，会让「用户关闭了产品但进程还在」变成一件只有
任务管理器能解决的事。

## 8. 变红验证：22 处，22 处红

重点：★ 默认开着 / 默认策略下照样排定时器 / `stop()` 之后仍能发送 /
★★ **去掉 transport 之前的第二次代际核对** / `stop()` 不加代际 /
没有同意记录也发 / 允许非 https / **载荷改成拒绝名单** /
字符串不再查空白与路径分隔符 / 受控值改成「短就行」/ 对象数组也能外流 /
未知指标填 0 进载荷 / 没配 transport 时当成成功 / 出错时偷偷重试 /
定时器不 `unref`。

### 两处"没咬"——同一类原因：**另有别的地方也拦着**

| 探针 | 为什么没红 | 处置 |
| --- | --- | --- |
| ㉔⑥ 删掉 `shouldSend` 的同意记录检查 | `validateHeartbeatPolicy` 也要求同意记录，于是"没发"依然成立——**用例只断言了"没发"** | 改成断言**具体的理由码**；这才让紧贴 `transport` 的那道闸可观测 |
| ㉔⑮ 删掉 transport 类型检查 | `await null(...)` 抛的错被 catch 接住，理由码同样是 `SEND_FAILED` | 改成断言诊断**文案**能区分「没配通道」与「发送失败」 |

两处都不是「探针写错了」，而是**用例的断言太宽**：
「没发」与「没发，且理由是那一件事」是两个不同强度的断言，
只有后者能发现「另一条路上的检查被删掉」。

## 9. 本批**没有**解决的事

- **没有真实的 transport**：`createHeartbeat` 接受注入的
  `async (payload) => any`，而一个真的 HTTPS 上报通道**没有实现**——
  也就是说这个产品目前**发不出去任何心跳**。
- **没有同意流程**：`consent` 是一个由调用方传入的对象，
  产品里还没有一个界面或 CLI 去采集它（PRT-707 的首次运行向导是它的位置）。
- **配置里没有 `heartbeat.*` 键**：`product/config.mjs` 还没有把这几个路径
  接进 `KNOWN_CONFIG_KEYS`，所以用户目前无法通过配置文件开启。
- **没有接进 Launcher**：`launcher.mjs` 还没有在启动时创建心跳实例。
- **`HEARTBEAT_INVALID_ENDPOINT` 与 `HEARTBEAT_PAYLOAD_REJECTED` 目前
  没有调用方会产生**：端点非法现在归在 `BAD_POLICY` 下报，
  载荷被丢弃的键只出现在 `dropped` 里。这两个码是为将来留的，
  不要读成「已经支持了」。
- **`timeoutMs` 没有生效**：策略里有这个字段，但 `transport` 是注入的，
  超时该由注入方负责。**产品自己并没有实现超时**。
