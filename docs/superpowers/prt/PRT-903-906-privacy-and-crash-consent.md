## 2 PRT-903：为什么说明不能是手写的

隐私说明最常见的失效方式不是写错，而是**写完就旧了**：代码里多加一条出境通道、
多收一个字段，说明里一个字都不变——而它读起来依然完整。

> 一个「手写的隐私说明」，
> 与一个「代码里新增了一条出境通道、而说明里一个字都没变」的说明，
> 是同一个东西——只不过前者读起来是完整的。

所以 `product/release/privacy.mjs` 把说明**挂在代码自己的允许名单上**：

| 说明里的部分 | 来源（不是抄写） |
| --- | --- |
| 心跳发什么 | `heartbeat.mjs` 的 `ALLOWED_PAYLOAD_KEYS`（**同一份数组**） |
| 本地存什么 | `data-classes.mjs` 的台账 |
| 需要哪些同意 | `crash-report.mjs` 的 `CONSENT_PURPOSE_IDS` |
| 允许名单变了 | `assertNoUndisclosedEgress` 式检查 → `FIELD_LIST_DRIFT` |

### 2.1 ★ "心跳关着"≠"没有数据出境"

`DEFAULT_HEARTBEAT_POLICY.enabled` 是 `false`，很容易得出"数据不出门"。
但**模型调用是必然出境的**——它由 DSH 发出。

> 一个「心跳关闭，因此没有数据出境」的隐私说明，
> 与一个「用户的目标与代码正在被送给模型供应商」的说明，是同一个东西——
> 只不过前者在"我们自己的通道"这个范围内是完全正确的。

所以出境通道分三类，且 `delegated-dsh` 那一类**必须非空**：

| 类别 | 通道 | 默认 |
| --- | --- | --- |
| `product-owned` | 心跳上报、崩溃报告 | **关闭** |
| `delegated-dsh` | 模型调用 | **开启**（且本仓库关不掉） |
| `loopback` | team-hub 内部调用 | 开启（不出机器） |

`defaultsSummary.egressStillHappensWithAllDefaults === true` 就是这一条的机器读数，
渲染出的说明里也**主动**写了一句"心跳关着不等于没有数据出境"。

### 2.2 反方向也要查：过期的披露同样是误导

`observedEgress` 缺席（"没观测"）与空数组（"看了，一条都没有"）**行为不同**：
缺席时不报未披露/过期，空数组时每一条通道都报 `STALE_CHANNEL`。
这与 PRT-614 的 `legacyHighRiskTools`、PRT-904 的 `installedPrefixes` 是同一条纪律。

### 2.3 ★ 自检抓出来的真缺口

`model-call` 通道声明了 `user-consent`，但它的 `consentPurpose` 是 `null`——
**一条要求同意、却没有对应同意事项的通道**，它的"同意"在配置里无处可表达。

装载期自检因此红了（`privacy-no-consent-purpose`）。修复是在 `crash-report.mjs` 里
补一个同名的 `model-call` 同意事项：

> 把这一项并进别的同意事项，等于把"我关不掉它"藏进一个用户以为能关的开关里。

**这是本模块存在的理由的一次自我演示**：一个手工维护的说明不会发现这件事。

## 3 PRT-906：授权不能集中在一个布尔上

崩溃报告与诊断包的区别恰好在于"谁在什么时候决定"：

- 诊断包：用户**主动**生成（spec line 747）。生成的那一刻就是授权。
- 崩溃报告：**进程崩了**。没有人在场可以问。

所以崩溃报告拆成两个动作，而它们**各自需要同意**：本地落盘 / 对外发送。

### 3.1 ★ 三个会安静出错的坑

**① "本地生成不用问，先存下来以后再问"**

> 一个「本地先生成、等用户同意再上传」的崩溃报告，
> 与一个「在用户从没同意过的磁盘上，已经躺着一份未脱敏的内存转储」的实现，
> 是同一个东西——只不过前者的授权检查发生在**另一个模块**里。

所以本地落盘也**必须在事先同意的范围内**，且脱敏是**无条件**的
（探针 54⑤ 把脱敏改成"不落盘就不脱敏" → 红）。

**② "没同意"与"没说"合并**

同意状态是**三分**的：`granted` / `denied` / `unknown`。

> 一个「把读不出来的同意当成默认同意」的崩溃报告，
> 与一个「用户明确拒绝过、报告照样发出去」的实现，是同一个东西——
> 只不过前者的默认值是在一个没人会去看的地方写的。

`normalizeConsent`：缺字段 → `unknown`；非法值 → `unknown` + `CONSENT_INVALID`。
**出厂默认是全部 `unknown`，不是全部 `granted`。** 探针 54①② 专打这两条。

**③ 撤销只影响将来**

> 一个「撤销只影响将来生成的报告」的同意模型，
> 与一个「用户点了拒绝、而之前那份报告还在磁盘上等着某天被上传」的模型，
> 是同一个东西——只不过前者在同意状态上看起来是完全正确的。

`revokeConsent` 产出**待处理清单**（`stale`），且 `unknown` 也算待处理——
"没说"不是"可以留着"。探针 54⑨⑩。

### 3.2 ★ 只勾"上传"不能变成"直接发走"

`transmit: uploadOk && captureLocal`——没有本地已同意的副本，就不存在可发送的东西。

这条挡的是"只勾了上传、于是实现临时生成一个未脱敏的副本直接发走"。
探针 54④ 把 `&& captureLocal` 去掉 → 红。

### 3.3 ★ 带脱敏映射表的报告**不算**已脱敏

> 如果脱敏映射（原文→占位符）和被脱敏的内容一起被存进包里，
> 那这份包里的敏感信息一个都没少。

`assertRedacted` 因此拒绝 `includeMap: true`，也拒绝"脱敏后仍有残留"。
探针 54⑪⑫。

### 5.1 ★ 探针打不动的那三条，是我的实现有缺陷

第一版跑 `break-903.mjs` 的结果是 **4/7**：55④⑤⑥ **补丁明明应用了
（`applied=1`），却没有任何用例变红**。

原因不是探针写错，而是**那三条判据在真实输入上永远不可能触发**：

| 判据 | 第一版为什么恒不触发 |
| --- | --- |
| 无控制手段 | `controls` 在模块级常量里写得好好的 |
| 要求同意却没挂事项 | 同上（而且这一条自检刚修过一次） |
| `fields: null` 却没说从哪来 | 同上 |

`privacyReport` 当时直接读 `EGRESS_CHANNELS` 这个常量，所以这三条**没有输入能让它们红**
——它们从来没有被验证过。

> 一个「永远不会触发」的复核，与没有复核，
> 在「它到底拦不拦得住」上是同一个东西。

修复：`privacyReport({ channels })` 的表**可注入**（与 PRT-607 的 preset 表、
PRT-612 的 `assertMappingConsistent` 同一条教训），并在装载期自检里补了这三条的
**反向控制**（喂坏通道 → 必须报；喂好通道 → 必须零 finding，否则是无差别报警）。
修复后 7/7 全红。新增的 7 条用例见 `privacy.test.mjs` 测试组 ⑧。

**记这一笔是因为它正好是本模块的主题**：一份"看起来在检查"的东西，
与一份"真的会红"的东西，区别只在**有没有一个能喂坏值的入口**。

## 7 ⚠️ 诚实边界

1. **说明是生成的，不是发布的。** `renderPrivacyNotice()` 返回一个字符串，
   但**没有任何东西把它写进安装包或发布页面**。文档面（README、官网）仍然是
   手工维护的，与这份说明之间**没有**联动。漂移判据只保证"这份生成物与代码一致"。

2. **`privacyReport` 的 `observedEgress` 由调用方给。** 与 PRT-614 的
   `legacyHighRiskTools`、PRT-904 的 `stores` 同一条边界：一份**不完整**的
   `observedEgress` 会让未披露通道检查通过，而本模块**没有机制发现它漏了**。
   **那是信任边界，不是检查。**

3. **崩溃报告不落地也不上传。** `planCrashReport` 只返回一个计划——
   本仓库**没有**崩溃处理器调用它，没有写文件的代码，没有 HTTP 客户端。
   所以"崩溃时会脱敏"这句话目前**不成立**。

4. **`payload.fields` 由调用方给。** 一个不完整的字段列表意味着
   结构排除扫不到那个密钥文件——而本模块不会知道少给了什么。

5. **同意没有持久化层。** `normalizeConsent` 读一个普通对象；
   谁把它写进配置文件、从哪读回来，**本批未接**。撤销后的"待处理清单"
   同样没有执行者去删文件。

6. **模型调用的目的地不可知。** 说明里如实写了"由 DSH 决定、本仓库看不到"——
   这是准确描述，不是免责声明。要真正披露目的地需要从 DSH 的模型配置读取。

7. **团队/企业场景未覆盖。** 说明是"给单个用户看"的。若一个组织部署 Legion，
   管理员与最终用户的同意关系（谁能同意、谁的数据）本批**未处理**。

8. **`model-call` 同意事项目前无处可勾。** 我补的是"它可以被表达"，
   不是"UI 上有一个开关"。同意事项与实际配置项之间**没有**一致性检查。
