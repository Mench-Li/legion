## 三、★ 用例与自检抓出来的真缺陷（本次最有价值的部分）

### 3.1 PRT-903：一条"要求同意却没有同意事项"的通道

自检抓到 `model-call` 通道声明 `user-consent` 而 `consentPurpose` 是 `null`——
一条要求同意、却在配置里**无处表达那个同意**的通道。补了同名同意事项。

### 3.2 PRT-903：三条**永远不会触发**的复核

破坏性验证第一版只有 **4/7**：三个补丁 `applied=1` 却**没有任何用例变红**，
因为那三条判据读的是模块级常量，在真实输入上**不可达**。

> 一个「永远不会触发」的复核，与没有复核，在「它到底拦不拦得住」上是同一个东西。

已把 `channels` 改成可注入并补反向控制，修复后 7/7。

### 3.3 PRT-905：导出体积把"不复制"的字节也算进去

`counts.bytes` 把 `reference-only`（产物）的字节也加了进去，
于是**100 字节 + 10 GB 产物**的一次导出报告 `1000000100`。

> 一个「把不复制的东西也算进体积」的读数，
> 与一个「告诉用户这次导出有 10 GB」的读数，是同一个东西——只不过前者在加法上是完全正确的。

已拆成 `bytes` 与 `referencedBytes`。

### 3.4 PRT-905：一个"靠崩溃变红"的假探针

探针 57⑥ 第一版 `if (false)`，**确实红了但 `thrown=1`**——红的原因是抛
`TypeError` 而不是断言。按纪律**崩溃式变红不算证据**，已改成人类真会写的 bug
（给认不出的类别一个兜底默认），变成断言级变红。

### 3.5 PRT-907：三处"检查本身是错的"

1. **只认文档里那种写法**：正则只认带尖括号的 `--port.<进程>=<n>`，
   于是手册里 `--port.team-hub=9000` 被切成 `--port` 并报"不存在"。
2. **对真实存在的开关喊狼来了**：手册写「**不要**直接加 `--allow-port-in-use`」
   是提名字，却被报成"不存在"——*一个让支持人员学会忽略其输出的检查。*
3. **靠形容词判断"够不够具体"**：`observable` 原是自由文本，用正则去猜，
   在 `lease 过期但 attempt 没有推进` 这句**真实且合格**的读数上误报。
   已改成 `kind`（闭集）+ `ref`（必须含标识符）的结构化形式。

另外，`AUTH_FAILED` / `SECRET_UNAVAILABLE` 在 `product/**` 里搜不到生产者，
一度以为手册编了假码（实际在 `runtime/contracts/errors.mjs`）——
**这件事直接催生了第三条交叉核对**（手册 ↔ `ERROR_CODES` 逐个核对）。

### 3.6 阶段 8：回滚裁决漏掉失败的那份迁移（最危险）

`up()` 里"第一句成功、第二句抛错"的迁移**不留 applied 记录**，
于是只看 `appliedMigrations` 的裁决判成"仅回滚程序安全"→
**把程序退回到读不懂当前库的版本**。已引入三态 `partialWrites`
（`false`=确实没写 / `null`=**不知道** / 未知按**已写**算）。

同批还修了：`patchPair: 'unverified'` 从黑名单缝里过去（改成白名单）；
`restoreSnapshot` 不删 `-wal`/`-shm`（**合并后的库能正常打开**，所以不会以"打不开"暴露）；
`forward-fix-required` 被判成"已知兼容"；切换前磁盘复查被传错大小因而永不失败。
