# Legion 协作台界面设计

日期：2026-10-02。状态：设计提案，尚未实施。

本文依据用户提供的任务看板、Agent 聊天两张截图，以及当前 Workbench 源码，定义产品命名、导航信息架构和 Agent 聊天体验。截图中的名称、数字和消息仅作为布局示例。本文只交付设计，不改变现有界面或服务。

修订说明：用户已认可整体视觉，要求具体内容严格按代码仓库排布。配套 HTML 已按当前组件和只读数据库快照校准；本说明优先于下文首版中尚未校准的交互示例。任务沿用六泳道和“全部 / 工作中 / 待我决定 / 待办 / 已完成”视角，不再使用截图的三列、“我负责的”或假设的项目筛选。日程仍是独立日程子页；任务卡打开任务详情，通过详情中的“联系 Agent”进入聊天。概览保留多目标、共享上下文与团队场景入口；设置保留空间、持续执行、Agent 工作流、模型与凭证、连接与令牌及浏览器助手。模型与凭证保留快速分配、模型档案、岗位绑定、配置搬家、凭证库五页。Agent 工作状态按任务投影，答问可用性不得从工作状态推断。按 Agent 直接聊天是用户要求的新设计，现有空间会话单独保留。详细映射见 `docs/prototypes/README.md`。

## 1. 命名与设计方向

推荐中文名称：**Legion 协作台**，侧栏空间不足时显示 **Legion**，首页标题显示 **协作台**。

“协作台”能覆盖与 Agent 对话、任务派发、产物查看和空间管理，不依赖军事角色隐喻；保留 Legion 便于延续品牌识别。

| 候选 | 特点 | 结论 |
| --- | --- | --- |
| Legion 协作台 | 简洁，兼容个人和团队使用，覆盖完整工作流程 | 推荐 |
| Legion 智能工作台 | 容易理解，但名称偏长且较通用 | 备选 |
| Legion 协作空间 | 更强调空间，容易与产品内的“空间”混淆 | 不优先 |

同步调整用户可见用语：将“将军 / 指挥员”改为真实用户名和“空间管理员 / 成员”；“编队”改为“Agent 团队”；“派活”改为“分配任务”；“待命”改为“空闲”。权限行为不随文案改变。若“general”等为内部身份键，则保留内部值，只更改展示文案。

整体采用截图的轻量工作台风格：窄图标栏承担模块切换，二级侧栏承担列表和筛选，主内容区承担工作。Agent 聊天成为人员入口的默认主页面。

## 2. 现状与主要问题

当前 `Sidebar.tsx` 将首页、任务、智能体、文件、技能、规范、浏览器、对话、日历、通知、快照共 11 项平级排列，并在下方继续展开空间列表。低频管理功能与日常入口竞争位置。

`App.tsx` 在不同模块外仍固定展示右侧任务、动态和快捷工具，也保留全局 KPI 与底部命令区域。聊天因此无法充分使用主工作区。

现有 `ChatView.tsx` 已包含空间会话、消息分页、附件、回复和重试逻辑；当前 Agent 页面主要展示团队与任务。空间聊天能力不等于已经具备可信的单个 Agent 对话绑定。先前 Agent 对话提案可作为服务契约参考，但实现前必须重新核对实际代码，不能将文档视为已上线能力。

## 3. 导航分组与合并

一级导航从 11 个平级模块收敛为 **5 个工作入口 + 底部设置**。使用统一线性图标，不再用不同风格的 emoji 表示模块。

| 一级入口 | 图标语义 | 二级内容 | 承接现有模块 |
| --- | --- | --- | --- |
| 概览 | 四格 | 空间概览、目标与进展、团队场景 | 首页；保留现有场景能力 |
| Agent | 人员 | 按空间分组的 Agent、空间讨论 | 智能体、对话中心 |
| 任务 | 列表 | 全部任务、我负责的、未分配、待验收；列表 / 看板 / 日历视图 | 任务中心、日程日历 |
| 资源 | 文件夹 | 文件与产物、技能、规范 | 文件中心、技能中心、规范 |
| 动态 | 铃铛 | 通知、执行动态、上下文快照 | 通知中心、实时动态、快照 |
| 设置（底部） | 齿轮 | 空间管理、Agent 配置、模型与连接、浏览器助手入口 | 空间设置及低频配置；浏览器助手保留独立页面 |

合并指导航归组，原有功能页面可以作为子页保留，不要求将三个资源面板改写成一个长页面。日历保留已有独立日程能力，在任务入口内以“日历”视图或子页访问，不把独立日程强制转换成任务。

浏览器助手的实际操作页面继续可用：从设置中的工具入口进入，并可通过快捷搜索打开。若后续使用数据表明它属于高频工作，可增加固定快捷入口，不挤占首版一级导航。

通知未读数显示在“动态”图标上。Agent 消息未读数显示在“Agent”图标和具体 Agent 行上；两个计数按各自来源计算，不重复累计同一通知。

### 3.1 空间选择

- 概览、任务、资源、动态：二级侧栏顶部放“全部空间 / 当前空间”选择器，不再在全局侧栏底部重复展开所有空间。
- Agent：默认显示全部有权限空间的分组列表，支持按空间筛选；每个分组可独立折叠。
- 进入 Agent 聊天时，会话绑定的空间是消息目标；其他模块原来的空间筛选独立记忆。去查看该 Agent 的任务时，再明确切换到其所属空间。
- “全部空间”仅是列表聚合视角，不是可发送消息的目标空间。
- 新建、重命名、仓库绑定及执行设置集中在空间管理，也可由空间分组的更多菜单访问。

## 4. 页面骨架

桌面布局采用三栏：一级图标栏 64px、二级侧栏默认 272px（可在 240–320px 调整）、主内容区占据剩余宽度。这里的尺寸是原型起点，须在实际字体和窗口上验证。

```text
┌──────┬────────────────────┬─────────────────────────────────────┐
│品牌  │ Agent       搜索 ＋ │ 产品助理      产品空间 · 可对话      ⋯│
│      │                    ├─────────────────────────────────────┤
│概览  │ ▾ 产品空间    3     │                                     │
│人员● │   ● 产品助理    2   │          消息、进展与任务卡           │
│任务  │   ● 开发 Agent     │                                     │
│资源  │   ○ 测试 Agent     │                                     │
│动态  │                    │                                     │
│      │ ▾ 市场空间    2     │                                     │
│      │   ● 内容助理       ├─────────────────────────────────────┤
│设置  │   ○ 运营助理       │ 发消息给产品助理…           附件 发送 │
└──────┴────────────────────┴─────────────────────────────────────┘
```

一级图标有悬浮文字提示、键盘焦点与明确选中态。Agent 入口使用人员图标，符合参考截图；不另设平级“对话中心”。

聊天页面收起全局 KPI、底部命令条和常驻右侧任务 / 动态栏。任务上下文由顶部入口打开右侧抽屉，关闭后恢复聊天宽度。概览页面可继续显示摘要与团队场景，任务页只展示与任务有关的统计和操作。

任务页面延续截图的看板结构：顶部标题、列表 / 看板 / 日历切换、负责人 / 优先级 / 项目筛选及新建按钮；二级侧栏放任务视图和 Agent 筛选。状态列使用当前业务状态，包括待验收、受阻等，不机械缩减成截图的三列。空间与项目是两个概念，仅在有真实项目数据时显示项目筛选。

## 5. 人员入口与 Agent 列表

### 5.1 按空间分组

列表顶部显示“Agent”、搜索按钮和新增按钮。新增按钮根据权限提供“添加 Agent”和“新建空间”，无权限时解释原因。搜索匹配 Agent 名称、岗位与空间名，结果仍按空间分组。

分组标题显示“空间名称 · Agent 数量”，不使用含义不明的“2/3”。折叠时仍显示该空间未读消息数。有待处理问题的分组给出明确提示。

每行包括头像、Agent 名称、简短副标题和未读数：副标题优先显示“待你回答”或最近有效进展，没有进展时显示最近消息摘要，再没有则显示岗位。名称过长省略，悬浮可查看全名。选中行用浅青灰底突出，避免仅通过颜色表达选中状态。

答问可用性与工作状态分别表达：头像旁的点表示答问可用性（可对话 / 不可用 / 未知），副标题可显示执行中、空闲、受阻等。不能由“任务执行中”推断在线。状态过期显示未知及更新时间；离线 Agent 仍可点击查看历史。

空间讨论作为各分组中的次级条目保留，使用对话图标，与人员条目的头像区分，承接原空间会话。多个既有空间会话可在“空间讨论”子列表查看，不强制迁移成某个 Agent 的消息。

### 5.2 点击与恢复

1. 点击人员图标，打开 Agent 列表，恢复最近查看的有权限会话；首次进入未选择 Agent 时显示“选择一个 Agent 开始对话”。
2. 点击任意 Agent 行，主区直接打开该 Agent 的主对话，无需先进入详情或点击第二个聊天按钮。
3. 切换 Agent 保留各自草稿、历史滚动位置与任务上下文。刷新后恢复选择；已删除或权限撤销的 Agent 回到安全的空态。
4. 从任务负责人、概览团队成员或通知中的“联系 Agent”进入，也打开同一主对话；任务入口同时带入可见的任务上下文。
5. Agent 配置与成员管理放在更多菜单，不占用聊天主入口。

## 6. Agent 聊天主区

### 6.1 顶部

左侧显示头像、Agent 名称、空间与可对话状态；右侧提供“关联任务”按钮和更多菜单。菜单包括查看资料、规则与技能、运行记录、Agent 设置（按权限展示）。

当前模型只有在服务端能确认时才展示；执行使用的模型和答问使用的模型必须区分。详细运行信息放在抽屉，顶部不堆叠技术字段。

### 6.2 消息

- 普通聊天采用截图的左右气泡，用户在右、Agent 在左；正文支持既有 Markdown、附件和引用。
- 日期与时间分隔保持低对比；合并连续消息的重复头像和时间，减少噪声。
- 任务进展显示紧凑卡片，包含任务名、事实摘要和查看任务 / 产物入口。
- 待用户回答的问题提供选项或回复按钮，在列表同步显示“待你回答”。
- 新消息仅在用户处于底部时自动滚动；阅读历史时显示“有新消息”，加载更早记录保持阅读位置。
- 区分“发送中”“已保存”“回复中”“失败”。只有确有送达确认才能显示“已送达”；已有持久化成功不应伪装为 Agent 已收到或已读。

### 6.3 输入与执行语义

输入框占据主区底部，默认文案“发消息给 {Agent 名称}…”。首版提供附件、发送和必要的任务上下文，不展示尚未接入的语音按钮。默认 Enter 发送、Shift+Enter 换行，并支持用户改为 Enter 换行。

普通聊天默认是答问。输入框提供简洁的“关联任务”入口：用户选择任务后，明确显示目标与“询问进度 / 追加要求”；创建任务通过“新建任务”进入现有任务流程，不能将每句聊天自动视为执行指令。

追加要求提交后必须显示实际回执，如“已保存，将在下一次执行时纳入”。多活动任务时用户必须明确选择目标；停止执行等操作放在任务抽屉，展示请求与执行结果，不能用一句模型回复代替实际控制结果。

### 6.4 右侧任务抽屉

默认关闭，宽屏打开约 360px，窄屏覆盖主区。包括关联任务、最近进展、产物和运行记录；点击任务再进入详情。聊天的“全部任务”视角只影响阅读过滤，不是批量执行目标。

## 7. 视觉规范与适配

以浅灰背景、白色主面板、青色主操作和浅青选中态建立层次；文字采用近黑正文与灰色辅助信息。参考色建议：背景 `#F5F6F8`、侧栏 `#F8F9FB`、边框 `#E5E8ED`、主色 `#008595`、正文 `#1B2430`。实际实施检查文本对比度，禁用状态也必须可读。

正文 14px，页面标题 20px，列表主标题 14px，辅助文字 12px；列表行约 56–64px，图标点击区域至少 40px，采用 8px 间距体系。头像使用图片或名称首字，不要求生成新品牌图标。

| 可用宽度 | 布局 |
| --- | --- |
| ≥1200px | 三栏常驻，可打开任务抽屉 |
| 900–1199px | 图标栏 + 较窄列表 + 主区，任务抽屉覆盖主区 |
| <900px | 二级侧栏通过按钮打开；选中 Agent 后进入完整聊天，顶部提供返回列表 |

不同宽度均保留当前会话及草稿。长列表内部滚动，不让设置入口或输入框被挤出屏幕。折叠分组使用可键盘操作的按钮，提供展开状态；状态同时提供文字，所有图标按钮有可访问名称。

## 8. 空态与异常

| 场景 | 界面行为 |
| --- | --- |
| 没有空间 | 提示创建空间，有权限才显示创建按钮 |
| 空间没有 Agent | 展示分组空态及添加 Agent 入口，不制造默认在线成员 |
| Agent 没有聊天记录 | 显示岗位介绍和“了解当前任务 / 询问能力”建议，不生成虚构历史 |
| Agent 不可对话 | 仍可查看历史；若有持久化投递队列则明确等待，否则禁用发送并说明原因 |
| 消息发送失败 | 保留原文本及附件，支持对该条消息重试，避免重复落库 |
| 切换会话后旧请求返回 | 丢弃旧页面写回，不将 A 的消息显示到 B |
| 空间失去访问权限 | 服务端拒绝读写，清除可见缓存与选中态，不保留不可访问内容 |
| 历史会话无法映射到 Agent | 保留在空间讨论或历史会话中，不按同名或岗位猜测绑定 |

## 9. 实施边界与建议拆分

### 9.1 第一阶段：界面骨架与导航

更换展示名称；拆出一级图标栏和模块二级导航；完成上述模块映射；将右栏、KPI 和底部命令区改为按页面显示。保留旧模块的进入能力与现有权限规则。

建议组件：`AppRail`、`ModuleSidebar`、`SpacePicker`、`ResourceNav`、`ActivityNav`。这些是拟议组件名，不是现有文件。

### 9.2 第二阶段：Agent 聊天闭环

实现按空间分组列表、稳定会话选择和主区聊天；提取 `ChatView` 的消息列表及输入逻辑，复用分页、附件和失败处理。新增组件可包括 `AgentDirectory`、`AgentChatView`、`AgentContextDrawer`。

Agent 主对话需服务端权威绑定空间与稳定 Agent 身份，并确保同一身份重复进入不会创建重复会话。现有 `scope + role` 可用于兼容身份查询，但不能仅依赖展示名、列表索引或临时进程编号。若稳定身份与绑定接口尚未实现，需在此阶段补齐，不能只换头像后仍发送给通用空间助手。

导航状态区分模块、列表空间筛选、选中的 Agent、会话和可选任务；异步写回校验空间与会话身份；服务端独立校验访问权限。草稿按真实会话身份存储。实时消息优先复用既有事件流；已读只在消息实际可见时更新。

### 9.3 第三阶段：任务上下文与进展

接入可信进展卡、任务抽屉、未读与待回答标识，完善追加要求和控制回执。查询、追加要求和控制任务分别使用对应服务契约，避免外观完成而执行含义不清。

## 10. 验收标准

1. 产品主名称显示“Legion 协作台”，主要用户入口使用协作语义。
2. 左侧常驻一级导航为 5 个工作入口和底部设置；11 个原模块均能通过归组后的路径到达。
3. 人员图标打开按空间分组的 Agent 列表；点击 Agent 一次即进入对应聊天。
4. 同空间同岗位及不同空间同名 Agent 的会话可正确区分；从任务与概览进入时复用同一 Agent 主对话。
5. 聊天默认不显示常驻右侧任务动态栏、全局 KPI 和底部命令条；输入区与列表在目标窗口尺寸可正常使用。
6. 切换会话不串消息、不丢草稿，旧异步响应不会覆盖当前会话；刷新可恢复有权限的选中对象。
7. 离线、未知、执行中和受阻状态语义明确；无真实送达 / 已读确认时不显示相应标记。
8. 追加要求显示具体目标与真实生效回执；不能把普通聊天默认当成执行指令。
9. 空间讨论及旧会话可继续访问，无法确定归属的历史不会被擅自绑定到 Agent。
10. 导航与分组可键盘操作，窄屏可返回列表，长列表和长消息不遮挡发送区。

推荐据此先制作两个页面原型：**Agent 聊天页**验证人员入口与空间分组，**任务看板页**验证导航合并和主工作区布局，再进入完整界面实现。
