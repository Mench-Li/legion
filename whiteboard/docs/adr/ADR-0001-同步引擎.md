# ADR-0001 同步引擎

- 状态：草案（待将军签发）

## 决策

采用 CRDT 操作式同步：文档 = 「LWW 元素集 + 每字段 LWW 寄存器」，op 携带
Lamport 时间戳 (v, clientId)，合并为逐寄存器取最大时间戳，天然满足交换律/
幂等律/结合律，收敛不依赖服务端顺序。服务端为薄 relay（广播 + 持久化 + 快照）。

> 实现说明（禁网约束下的等价实现）：环境禁止联网下载依赖，yjs/y-protocols/
y-websocket 缺失，故以零依赖自研 RFC6455 relay + LWW 操作式 CRDT 落地，其语义
与 Yjs 基线对齐（收敛、墓碑、字段级局部更新、presence 隔离、每用户 undo）。
StorageProvider / 同步层留有接口边界，依赖可用时可替换为 Yjs 而不改上层。

## 理由

- 局部撤销语义天然对齐 Y.UndoManager（origin 过滤）。
- 离线/重连近乎免费：重连即快照 + 增量回放，乱序/重复注入仍收敛。
- 单机自托管最简：单进程即承载 relay + 状态 + 持久化。

## 被否方案

- OT（ShareDB）：需中心化变换、撤销语义与 Y.UndoManager 不对齐，实现重。

## 代价

- 自研 CRDT 仅覆盖 v1 元素语义（无嵌套/编组），扩展到富文档需引入 Yjs。
