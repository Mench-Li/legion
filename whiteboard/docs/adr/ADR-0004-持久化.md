# ADR-0004 持久化

- 状态：草案（待将军签发）

## 决策

SQLite(WAL) 单文件嵌入式 + StorageProvider 抽象接口
（apps/server/src/storage.mjs）。v1 实现用 node:sqlite（Node ≥22.5 内置，零原生
依赖、零联网下载），另有 MemoryProvider 供测试与互换。

接口：load() -> { snapshot, ops }；append(ops)；snapshot(state)；close()。
定期快照 + 增量 op 日志（append 即 WAL 提交，RPO≈0），启动回放。

## 理由

- 7/8 主张：单文件可查询、崩溃安全（WAL）、容器挂卷即可持久化。
- StorageProvider 抽象使内存 ↔ SQLite 互换，上层（Room）不感知。
- node:sqlite 规避 better-sqlite3 原生二进制在容器/Alpine 的编译问题。

## 被否方案

- y-leveldb（coder 原主张）：目录文件、不可查询，与「单文件可查询」验收不符。

## 代价

- node:sqlite 仍标 experimental（Node 22 有警告），需固定 Node ≥22.5。
