# ADR-0008 房间治理与实例形态（P3-1）

- 状态：草案（待将军签发）
- 关联：ADR-0004（持久化）、ADR-0005（部署形态）、P3-1 切片

## 决策

1. **实例形态：继续单实例、单进程**，不承诺横向扩展。本 ADR 显式记录被否方案与触发条件（见下），
   取代 ADR-0005 中「单房间」的前提——ADR-0005 的部署结论（单容器 + 单进程 + /healthz）继续有效。
2. **多房间**：房间 ID（`^[a-z0-9][a-z0-9_-]{0,63}$`）作为一等公民；每房间**独立 SQLite 文件**
   `data/rooms/<roomId>.db`，惰性打开、空闲关闭（默认 5 分钟无在线用户）。房间数上限默认 50。
3. **房间级权限**：`WHITEBOARD_ROOMS="roomId:token:role,..."` 声明；角色 `rw`/`ro`（只读只拒写入，
   仍可同步与 presence）。未声明的房间沿用全局 `WHITEBOARD_TOKEN` 语义（回环开发可完全不配 token）。
4. **连接治理（分级）**：连接数超限在**升级阶段**返回 503（全局/单房间/单 IP 三档，默认 200/50/50）；
   消息过大或 op 条数过多或畸形 → 1009/1008 立即断开；频率超限 → 先丢弃并告警，窗口内累计达阈值才断开。
5. **可观测性**：`/healthz`（浅，保持既有契约）、`/readyz`（深，逐房间存储 + 心跳新鲜度）、
   `/metrics`（计数/仪表盘/限流配置）、`/api/rooms*`（房间与审计，控制面默认仅回环）。

## 理由

- 单实例交付成本最低：零外部依赖、单文件库、无服务发现与一致性协议，符合本仓库「禁网/禁下载」约束。
- 房间治理解决的是**同一实例内的多团队隔离与滥用防护**，不需要分布式能力即可获得主要收益。
- 分级限流避免「一刀切断开」误伤：网络抖动只丢消息，持续冲击才断开；超限原因是可区分的（503 体带 reason）。
- 每房间独立文件让「删房间 = 删文件」、单房间损坏不波及他人，代价是跨房间聚合需逐库读取（已接受）。

## 被否方案（显式记录，附触发条件）

### A. 多实例横向扩展 + 外部共享数据库
- 否的理由：需要外部 DB/Redis、房间→实例路由、跨实例广播与在线态同步；
  且与「零第三方依赖、零联网下载」的现状冲突，收益在当前规模（单团队、单机自托管）不成立。
- **转 v2 触发条件**（满足任一即重新评估，不提前做）：
  1. 单实例连接数持续超过**全局上限 200** 或单房间持续超过 **50**（ADR-0005 的 soak 界）；
  2. 需要跨机房/多进程共享同一房间的实时协作（当前单进程语义无法满足）；
  3. 可用性要求高于单点（进程崩溃期间不允许停止服务）。
- 若触发，优先顺序：① 先把 StorageProvider 换成共享存储（接口已留，见 storage.mjs）；
  ② 再引入房间→实例路由与跨实例广播（本 ADR 需相应改写）。

### B. 单一数据库 + `room` 列（而非每房间独立文件）
- 否的理由：房间隔离降级为查询条件（一次 WHERE 漏写即跨房间串数据），删房间需清理多表；
  单文件争用面更大。若后续要做**跨房间聚合分析**，可再评估（当前指标只按房间逐个读概况，成本可接受）。

### C. 房间级成员表 + 邀请/踢人管理面
- 否的理由：需要成员持久化、邀请流程与管理 API/UI，属产品功能扩张而非治理必需；
  当前用「每房间 token + 角色」即可覆盖「私有房间 / 只读房间」两类真实需求。
- 触发条件：出现「同一房间内需要区分多个不同权限的人」的需求时再评估。

### D. 一律立即断开 / 一律只丢弃
- 否的理由：一律断开会在网络抖动时误伤正常用户；一律丢弃对恶意客户端无刚置。
  故取分级（见决策 4）。

## 代价与已知边界

- 指标与审计是**进程内**的（重启归零）；审计文件按大小轮转保留 3 份，不做压缩与长期归档。
  **P4-5 起补充**：运行计数器仍是进程内（刻意设计），但**审计归档已可读、可跨重启回溯**——
  `GET /api/rooms/<id>/audit?source=archive|all` 直接查 JSONL，响应附 `retention` 如实报告
  「能回溯多久」与 `historyTruncated`（本进程是否已轮转掉更早的历史）。**仍无长期归档**：
  保留 3 份即滚出，轮转按单文件字节而非时间/天数——这是决策 1「不承诺横向扩展、不引入外部存储」的直接后果。
- 角色只有 rw/ro 两档；无「按元素/按区域」的细粒度权限，**无操作级审计回放**（P4-5 补记了 op 的
  条数与类型分布摘要，但仍不记录元素内容，故无法据审计重建画布）。
- 房间空闲关闭依赖 tick 心跳；进程被强杀时房间文件由 SQLite(WAL) 自行恢复，未落快照的增量在 op 日志中。
- 单 IP 上限是**粗粒度**防滥用（默认与单房间一致 50），不适用于把所有用户都藏在同一出口后面的大规模部署；
  此类部署需在反向代理层做真实客户端识别（本服务不信任 `X-Forwarded-For`，避免伪造绕过）。
